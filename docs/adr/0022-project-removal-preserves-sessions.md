# 删除项目保留会话

## 上下文

用户于 2026-11-02 补充双栏工作台的删除项目确认弹窗，要求采用参考图一的圆角白色弹窗样式和参考图二的文案。文案明确：项目从列表移除，正在运行的对话停止，对话记录保留并移到「对话」下，源文件夹中的文件不删除。这修订了 [ADR 0020](0020-projects-organize-workspaces.md) 第二轮确认中的级联删除项目会话、运行中拒绝删除的条款。会话记录不可恢复的删除与保留存在实质差异，需保留修订依据。

## 决定

- 删除项目必须先显示模态确认，标题为“删除项目？”，说明为“项目会从列表中移除，正在运行的对话会被停止。对话记录会保留，移到「对话」下；项目文件夹里的文件不会被删除。”。取消、关闭与 Escape 不改变数据。
- 明确确认后，先停止项目中正在运行的对话，再移除项目及其组织关系。保留 Session 身份、内容及子智能体记录，清空项目归属，成为独立对话；子智能体会话仍归属于原父会话。
- 源文件夹、用户文件、会话已固定的工作目录、worktree 绑定，以及按 Workspace 保存的批准与记忆均保留。保留会话不触发直接删除 Session 时的关联资源清理。
- 停止失败时不能继续移除项目；移除失败时不能删除会话或提前显示成功。已停止的运行不自动恢复，界面如实反馈失败并允许重试；提交期间防止重复操作。
- 当前打开的对话保留，归属更新为“对话”。新对话草稿已选择该项目时，清空失效的项目选择。
- 本决定仅替代 ADR 0020 的删除项目条款，其他项目、Workspace 与固定工作目录规则继续有效。直接删除单条对话仍是另一种操作，不受本次修订影响。

## 理由与备选方案

此前方案在删除项目时级联删除对话，并因运行中工作拒绝删除。用户本次选择保留记录、停止执行并解除组织关系，使“删除项目”的影响符合其确认文案。代价是这些独立对话仍在原工作目录中运行；这与已有的归属和工作目录分离原则一致。

## 后果与验证

已由 [项目删除服务](../../apps/server/src/application/sessions.ts)、[确认弹窗](../../apps/desktop/src/renderer/features/projects/project-delete-dialog.tsx) 和列表状态同步实现，当前契约见[项目与会话列表](../subsystems/projects.md#删除项目并保留会话)。删除期间阻止新 Run、子会话及归属变更，等待根会话和后台子代理的实际结束，再执行原子项目删除；停止超时或结束处理失败保留项目并允许重试，不重启已停止的执行。

[Sidecar 协议用例](../../tests/integration/sidecar-delete-project.test.ts) 验证记录、父子关系、未改动的隔离 worktree 跨重启保留、取消超时的失败与重试、真实后台 Job 在删除后继续写入、定时任务继续触发、Workspace 记忆和批准保留。[浏览器用例](../../apps/desktop/src/renderer/features/sidebar/project-delete.browser.test.tsx) 验证确认几何与指定文案、取消/关闭/Escape 的无副作用及焦点、提交锁定和目标稳定、失败重试、当前记录及草稿附件保留。[真实 Electron 用例](../../apps/desktop/e2e/project-delete.e2e.test.ts) 验证删除项目后原会话在“对话”下保留，并跨应用重启继续发送。直接删除会话的独立约束继续由其[生命周期用例](../../apps/server/src/application/session-delete.test.ts)验证。
