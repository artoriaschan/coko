# 02: 工具摘要行与通用详情

**What to build:** 将现有工具调用展示为参考项目的紧凑摘要行和行内详情，先完成真实输入/输出、未知工具与 MCP、状态以及 Inspect 的完整路径。用户可以在现有时间线中展开一条工具、观察其输出并进入 Coko 追踪视图。

**Spec:** [对话详情与工作步骤复刻规格](../spec.md)

**Spec scenarios:** AC-01（工具行）、AC-11、AC-12、AC-18、AC-23（工具开合）、AC-24、AC-25

**User stories:** 11、15—18、23、25、27、29—31

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 复刻图标、标题、摘要分隔、状态提示、hover/focus、开合箭头及通用输入/输出正文容器，工具正文由用户手动展开；取消仅因命令、编辑类型或失败状态而默认打开正文的旧规则。
- [ ] 未知工具与 MCP 调用仍显示真实工具名称及完整可查看的参数、结果；不能识别专用类型时保持通用详情有效，不新增可执行工具或旧数据兼容层。
- [ ] 用真实调用身份配对参数、partialResult 与已提交结果；同一调用只出现一次，参数相同的不同调用互不合并，结算时保留展开状态、选区与阅读位置。
- [ ] 区分运行、完成、失败、待审批和缺失结果等 Coko 实际状态，保留原有审批决定、沙箱与 Hook 元信息；不能凭缺失字段补造成功、退出码或耗时。
- [ ] Inspect 进入 Coko 现有追踪入口，仅使用它真实支持的定位能力；没有可用入口时不呈现死按钮，展开与检查不触发工具再次执行。
- [ ] 既有专用工具正文和子代理入口在共用外壳调整后仍可用；为 04—07 提供同一详情容器约定，业务订阅和宿主回调仍由应用层拥有。
- [ ] 真实 App 测试覆盖流式到提交、重复/不同调用身份、未知/MCP、输入输出、错误、键盘与 Inspect；记录工具行及通用详情的双主题视觉证据，并检查共享消费者。

- 采用规格的真实 App 装配入口及本票要求的现有 Sidecar/Electron 入口；纯函数测试只补充边界，不代替用户可见路径。
- 按当前实际改动选择相关测试，运行类型和文档检查；保留精确命令、实际数量、退出码、参考/当前对象版本、主题/语言/尺寸及可访问证据。只更新失效证据，不用盲目重试、固定 sleep 或放宽断言制造通过。
