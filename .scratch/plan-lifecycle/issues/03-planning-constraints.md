# 03: 规划约束由计划阶段施加，并变为硬性

**What to build:** 规划期间“不改 Workspace”改由计划阶段保证，而且不再依赖用户每次都不点批准。Session 在规划中时，文件写入被直接拒绝，命令在只读沙箱里运行且不能提权，向可写终端的输入与带 Worktree 隔离的派发被拒；规划期间派发的 Subagent 受同样的约束。本票之后进入规划仍会把 Permission Mode 设为 `plan`，其余调用的询问与否暂时不变（04 处理）。见 [规格](../spec.md) 的“阶段一：判定、沙箱与注入”与设计稿。

**User stories:** 7、8、9、10、11、12、13、14、31、33、34

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 判定表测试改为“Permission Mode × 是否规划中 × 工具类型”：规划中文件写入工具为拒绝，位置紧随拒绝规则之后，先于询问规则、受保护路径、越出可写根、模式放行与允许规则；不在规划中的各格与改动前相同
- [ ] 外部 Hook 的 allow 不能放行规划中的写入；Hook 的 deny 仍然优先并保留它自己的结果文本
- [ ] 写入拒绝的文本按设计稿，说明 Session 在规划中、内容应写进计划；不产生审批请求
- [ ] 沙箱档位：规划中一律 read-only、可写根为空；不在规划中沿用现有映射
- [ ] 规划中带提权参数的命令直接返回错误结果，不询问；不在规划中的提权行为不变
- [ ] 规划中向更宽档位启动的 PTY Job 输入被拒；read-only 模式下的拒绝不变，其余模式仍按提权询问
- [ ] 规划中带 Worktree 隔离的 Subagent 派发在判定与派发两处都被拒；read-only 模式下的拒绝不变
- [ ] 规划期间派发的 Subagent：子 Session 的“是否规划中”取根 Session；写入被拒，命令在只读沙箱；子 Session 的系统消息中有“正在规划、不可改动”的说明，没有提交计划的指引
- [ ] Memory 写入、Todo List 与 Goal 工具、读取与搜索在规划中照常放行
- [ ] `<plan_mode>` 中关于写入与命令的表述与新行为一致（写入会被拒绝）
- [ ] Sidecar 集成测试：规划中的写入结果为拒绝、没有审批请求、目标文件不存在或逐字节不变；有匹配的允许规则与 Hook allow 时仍被拒；被放行的写文件命令因只读沙箱失败（darwin，其他平台按现有约定）；带提权参数的调用出错且不询问
- [ ] 现有断言“规划中写入询问”的用例改为断言拒绝，并在评论中说明原因
- [ ] 文档：权限判定与审批、Plan Mode、子代理、命令执行（PTY 与 stdin）、外部 Hook 的组合说明；`pnpm run check:docs` 通过
