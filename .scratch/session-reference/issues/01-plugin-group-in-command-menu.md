# 01: `/` 菜单的插件分组

**What to build:** 用户在草稿开头输入 `/` 时，已启用插件贡献的命令与 Skill 出现在单独的“插件”组里，位于 Skill 组之后、MCP 组之前；其余各组只剩不来自插件的条目。条目的名字、参数提示、描述、调用方式与同名取舍都不变。

**User stories:** 1–8。

**规格：** [spec.md](../spec.md) 的“`/` 菜单的插件分组”。

**Blocked by:** None（可立即开始）

**Status:** ready-for-agent

- [ ] 命令目录的每一项带可选的插件名：插件贡献的命令与 Skill 有，其余条目没有
- [ ] 来源取值不变：插件命令仍为用户来源，插件 Skill 仍为 Skill 来源；`command` 条目的来源字段不变
- [ ] 菜单把带插件名的条目归入“插件”组，位于 Skill 组之后、MCP 组之前；“用户”组与“Skill”组不再含插件条目
- [ ] “插件”组内按名字排序；组内仍是前缀匹配在前、包含匹配在后
- [ ] 没有带插件名的可用条目时不出现“插件”组；停用的插件命令照旧不出现
- [ ] 同名优先级、遮蔽诊断、启停与提交时的展开不变；设置页“Skills & Commands”分区不变
- [ ] “插件”组名中英文文案齐全
- [ ] 集成测试（真实 Sidecar）：装有一个带命令与 Skill 的插件时，命令目录中这两项带插件名，其余不带；同名取舍与现状一致
- [ ] renderer 的 Browser Mode 测试：分组的顺序与归属、没有插件条目时没有该组
- [ ] 以五个来源分组为全集的现有菜单断言按新增分组更新，不删除其覆盖的场景
- [ ] 当前行为文档同步：命令（命令目录字段、菜单分组）与插件（菜单中的分组）
- [ ] 记录实际运行的检查与未验证项
