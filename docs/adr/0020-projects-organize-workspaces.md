# 项目是组织容器，执行边界仍是 Workspace

## 上下文

2026-11-02 的桌面双栏设计引入“项目”作为侧栏的组织单位：项目有名称和多个源文件夹，其中一个标为“主要”；会话可以在项目内创建、在项目之间移动，也可以是不属于任何项目的独立对话。

此前的 Workspace 是用户登记的单个目录。Session 的工作目录缺省就是它；指令文件、项目设置、项目 Hook、MCP、Skills 与子代理定义都从这个目录读取；worktree、按 Workspace 作用域保存的批准规则与记忆条目都挂在 Workspace 上。[ADR 0016](0016-session-cwd-fixed-worktrees.md) 规定工作目录在 Session 创建时固定。参考实现程小帮的项目以单个路径为键，会话可以没有项目，删除项目时级联删除其会话。

用户于 2026-11-02 在双栏对话列表的需求澄清中逐条确认：采纳下述映射与独立对话目录的推荐方案；项目名称可以重复，主要文件夹不能重复；创建项目时主要文件夹已属于其他项目，就打开已有项目。

## 决定

- **项目。** 项目是用户命名的一组源文件夹，其中恰好一个主要文件夹，对应一个 Workspace。主要文件夹在所有项目中唯一，名称可以重复。新建项目的主要文件夹已是其他项目的主要文件夹时，不创建新项目，改用已有项目：从创建入口进入时打开它，从“移到项目”的“选择文件夹…”进入时把对话移入它。
- **归属与工作目录分离。** 一个 Session 最多属于一个项目；它的 Workspace 与工作目录在创建时固定（ADR 0016）。移入、移出项目或在项目间移动，只改变归属，不改变工作目录、worktree 绑定以及按 Workspace 作用域保存的批准与记忆。要在另一个目录中工作，就新建会话或交接。
- **项目内的新会话**在主要文件夹的 Workspace 中运行。修改项目的文件夹列表，不改变已有会话的工作目录。
- **新建的独立对话**（Standalone Session）在 Coko 于首次发送时创建的专属目录中工作。目录位于 Coko 管理、用户可见的根目录下（例如 `~/Coko/chats/<日期>-<短 id>`），不放在应用数据目录中；这个目录就是该会话的 Workspace。
- **迁移。** 升级时，每个现有 Workspace 迁移为只含一个文件夹的项目，原有会话归入该项目。

以下四点由用户于 2026-11-02 第二轮确认：

- **附加文件夹。** 项目的源文件夹中不是会话工作目录的那些，对项目内的会话来说都在 Workspace 内（在项目内新建的会话是主要文件夹之外的文件夹；从别处移入的会话还包括主要文件夹）：读取不需要审批，写入按权限模式处理，命令沙箱的可写根也包含它们；拒绝规则与受保护路径照常生效。指令文件、项目设置、Hook、MCP 与 Skills 仍只从工作目录读取。文件夹列表在每个 Run 开始时读取，修改从下一个 Run 生效。同一个文件夹可以同时是多个项目的附加文件夹，或另一个项目的主要文件夹。
- **主要文件夹。** 第一个添加的缺省为主要，用户可以更改；移除主要文件夹时由列表中的下一个接替，接替者已是其他项目的主要文件夹时保存失败。更换只影响之后新建的会话。
- **删除项目（此条已被替代）。** 第二轮曾确认级联删除会话及子智能体会话、进行中工作阻止删除。用户随后于同日通过删除项目弹窗的文案修订此条：[ADR 0022](0022-project-removal-preserves-sessions.md) 规定停止运行中的对话，移除项目但保留会话并转为独立对话；本页其余决定仍有效。
- **专属目录。** 独立对话被删除后，它的专属目录保留，因为其中是用户的工作文件。

## 理由与备选方案

- **把 Workspace 改称项目并扩展为多目录。** 这样移到项目就要更换 Session 的 Workspace，与 ADR 0016 冲突：Checkpoint 路径、相对路径的权限规则、指令来源都会在会话中途改变，按 Workspace 保存的批准与记忆也会跟着会话换到另一个项目。最终只能禁止移动或把移动改成交接。
- **项目就是单目录的 Workspace。** 最简单，但放弃了用户明确要求的多个源文件夹。
- **独立对话共用一个固定目录。** 不同对话的文件和“总是允许”规则会互相影响。
- **独立对话使用用户主目录。** Agent 默认就能读写整个主目录。
- **专属目录放在应用数据目录。** 用户在编辑器里找不到这些文件，清理应用数据时产物也会一起被删；ADR 0016 不把 worktree 放进应用数据目录也是这个原因。
- **允许主要文件夹在项目间重复。** 两个项目会共用一个 Workspace 及其批准与记忆，所以用户要求主要文件夹唯一。
- **附加文件夹只作引用、读写都要审批。** 更保守，但与界面“添加可读取和编辑的文件夹”的承诺不符。附加文件夹是用户在应用中授予的，不是仓库里的项目文件授予的，所以与 [ADR 0008](0008-project-files-only-tighten.md)“项目文件只能收紧”不冲突。
- **删除项目时把会话改为独立对话。** 第二轮曾因归属与工作目录不一致而未采用；用户在后续弹窗确认中明确要求保留记录，现由 [ADR 0022](0022-project-removal-preserves-sessions.md) 采用此方案。归属变化继续遵守固定工作目录的决定。

## 当前实施范围

已实现项目与会话组织字段、SQLite v10 的 Workspace 迁移、主要 Workspace 唯一约束、列表协议、分类交互与会话置顶。根会话在项目主要 Workspace 中创建时默认归入项目，子会话的协议归属从根会话派生，分叉与交接继承来源归属，置顶保持归属与执行目录不变。当前行为与验证入口见 [项目与会话列表](../subsystems/projects.md)。独立对话首次发送目录与项目草稿的主要 Workspace 首次发送已实现，入口与验证见[工作台归属栏](../subsystems/workbench.md#新对话归属栏)。多文件夹创建、真实路径唯一检查与已有项目复用也已实现，SQLite v11 保存主要目录在完整列表中的位置。附加文件夹的权限范围与项目其余管理仍待实施，因此 implementation 为 partial。

## 后果与验证

- 会话移动后，它的工作目录可能不在当前项目的文件夹列表中。侧栏表达的是归属，不是工作目录，这是预期结果。
- 专属目录会随独立对话增多而积累，Coko 不自动清理。
- 附加文件夹扩大了 [ADR 0005](0005-permission-mode-and-sandbox.md) 中“Workspace 内”的范围与可写根；判定顺序、受保护路径与拒绝规则不变。
- Workspace 的含义扩展到 Coko 为独立对话创建的目录，术语表已同步。
- implementation 变为 implemented 前需要验证：项目内新建会话的工作目录是主要文件夹；以重复的主要文件夹创建项目时打开已有项目、不新增项目；独立对话的专属目录在首次发送时才创建，之后不变；会话在项目之间移动后，工作目录与 worktree 绑定不变；修改项目的文件夹列表不改变已有会话的工作目录；升级后每个 Workspace 成为一个单文件夹项目，原有会话都在其中；附加文件夹的读取不询问、写入按模式询问，Seatbelt 允许写入它们，修改列表从下一个 Run 生效；移除主要文件夹时由下一个接替，冲突时保存失败；删除项目的停止、保留和移出验收按 [ADR 0022](0022-project-removal-preserves-sessions.md)；独立对话删除后专属目录仍在。
