# 05: 检索的近似匹配

**What to build:** Agent 换一种说法检索时仍能找到相近的记忆。`memory_list` 带 `query` 时先做现有的严格匹配（每个词都出现），有结果时行为不变；严格匹配为空时，用查询文本查找相近的条目，至多 20 条，结果第一行注明没有完全匹配、以下是相近的条目；仍然没有时返回现有的“没有匹配”文字。`scope` 参数对近似匹配同样生效。记忆接口的 `query` 不变，仍只做严格匹配，设置页的搜索框因此保持精确。运行时没有 FTS5 时不放宽。

**规格场景:** [spec](../spec.md) 的 AC-22 至 AC-26；实现决定“检索的近似匹配”；用户故事 18、19、20、25。

**文档影响:** [Memory](../../../docs/subsystems/memory.md) 的检索、工具与权限（`memory_list` 的 `query` 说明）与验证各节。

**Blocked by:** 04 新建时返回相近条目

**Status:** ready-for-agent

- [ ] AC-22：库中有一条条目，模型用措辞不同、严格匹配为空的 `query` 检索时，结果第一行注明没有完全匹配，随后是该条目的条目块。
- [ ] AC-23：`query` 的严格匹配有结果时，结果与现状相同，没有近似匹配的说明。
- [ ] AC-24：既没有严格匹配也没有相近条目时，返回现有的“没有匹配”文字。
- [ ] AC-25：AC-22 的同一个查询经 `/api/memories?query=` 请求返回空列表。
- [ ] AC-26：运行时没有 FTS5 时，AC-22 的检索返回现有的“没有匹配”文字。
- [ ] 近似匹配至多 20 条，按相近程度排序；给出 `scope` 时只在该作用域内查找；可见范围与严格匹配相同，其他项目的条目不出现。
- [ ] 工具描述说明没有完全匹配时会返回相近的条目；查询中的 FTS 语法字符仍按字面处理（沿用现有对手用例）。
- [ ] 真实 Sidecar 用例在 FTS5 与强制降级下各跑一次，沿用现有记忆检索用例的写法。
- [ ] 按[测试约定](../../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关集与类型检查；实际执行的检查和文档影响记入 Comments。
