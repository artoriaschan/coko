# 04: `@` 菜单的会话组与草稿 chip

**What to build:** 用户在输入区输入 `@`，文件候选下方出现“会话”组，列出同一 Project 里最近的其他会话，继续打字按标题过滤。选中后输入区出现一个显示 `@会话标题` 的 chip，它整体选中与删除，随草稿保存；提交出去的文本是 `@session:<id>`。本票不依赖 Sidecar 的展开：没有 02 时提交的只是一段文本。

**User stories:** 9–24、26、27。

**规格：** [spec.md](../spec.md) 的“`@` 菜单”“草稿中的 Session Reference 节点”。

**Blocked by:** None（可立即开始；端到端效果需要 02）

**Status:** ready-for-agent

开始前按 [界面约定](../../../docs/tech-stack/ui.md) 检查输入区、`@` 文件菜单与 File Reference 节点的现有实现与样式。

- [ ] `@` 菜单为一个列表两组：文件组在前、会话组在后，同一段查询同时过滤两组；文件组的候选、排序与目录 Tab 下钻不变
- [ ] 会话候选来自界面已持有的会话列表，不新增接口
- [ ] 候选范围：项目内的会话只列同一 Project 的会话（含 Worktree Session）；独立对话只列其他独立对话；新对话草稿按草稿所选的 Project
- [ ] 当前会话、已归档的会话不出现
- [ ] 按最近更新时间从新到旧；空查询显示 5 个；有查询时按标题匹配（不区分大小写，前缀在前、包含在后），最多 20 个
- [ ] 条目显示标题与最近活动时间
- [ ] 两组都没有匹配时菜单不出现；只有一组有匹配时只显示那一组；没有任何可引用的会话时菜单与现状相同
- [ ] 键盘、Esc、输入法、定位与指针选择沿用现有 typeahead，现有 typeahead 测试继续通过
- [ ] 选中会话后插入 Session Reference 节点并跟一个空格：chip 显示 `@会话标题`，样式与 File Reference chip 一致，整体选中与删除，不能在其中输入，不可点击
- [ ] 节点的序列化文本为 `@session:<id>`：提交的文本、读出的纯文本与复制出的文本都是这个形式
- [ ] 标题是选中时的快照，随草稿保存
- [ ] 带会话节点的草稿在切换会话与重启后恢复；节点缺少 id 或标题时按现有“未知节点”规则丢弃草稿
- [ ] 一条消息里可同时有文件节点与多个会话节点
- [ ] “会话”组名与相关无障碍文案中英文齐全
- [ ] renderer 的 Browser Mode 测试：两组的顺序、空查询的 5 个、标题过滤、范围过滤（另一个 Project、归档、当前会话都不出现）、只有一组有匹配时的显示；节点的显示、读出文本、整体删除与草稿往返
- [ ] 当前行为文档同步：上下文管理的界面与草稿部分
- [ ] 记录实际运行的检查，并按 UI 调试约定说明哪些交互在静默 CDP 或 Browser Mode 中验证、哪些未验证
