# 09: 重启、重试、压缩与断连后的已加载工具

**What to build:** 已加载的工具在重启、continue、retry，以及手动、自动、溢出三种压缩之后仍然可用，模型不必再搜索，恢复过程不重跑业务工具。工具所在 Server 断开时，断开期间的 Run 不提供该工具；重连后的 Run 自动提供，不需要重新搜索。工具的说明或 schema 在两个 Run 之间改变时，请求中使用新定义。

**规格场景:** [spec](../spec.md) 的 AC-09、AC-11；对应 TS-14、16。

**设计依据:** [design.md](../design.md) 第 6 节的生命周期表。

**文档影响:** [MCP](../../../docs/subsystems/mcp.md) 补充已加载工具在恢复、压缩与断连下的行为。

**Blocked by:** 03 按需加载最小闭环：目录、按确切名称加载与加载记录

**Status:** ready-for-agent

- [ ] AC-09：会话已加载两个工具。重启 Sidecar 后 continue、对失败的请求 retry，以及分别触发手动、自动与溢出压缩之后，下一次请求都包含这两个工具的定义；重启后的请求仍以基础提示开头；恢复过程不重跑业务工具。
- [ ] 已加载集合从有效条目重新派生，不经过压缩切点过滤。
- [ ] AC-11：已加载工具 A 所在 Server 断开期间的 Run 不提供 A；下一个 Run 重连后自动提供 A，无需搜索；A 的说明与 schema 在两个 Run 之间改变后，请求中是新定义。
- [ ] 场景经真实 Sidecar（faux 脚本）验证，先例为压缩与 MCP 的现有 Sidecar 测试。
- [ ] 按[测试约定](../../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关集与类型检查；实际执行的检查和文档影响记入 Comments。
