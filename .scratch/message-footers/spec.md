# 消息底栏与本轮用量规格

Status: ready-for-agent

## 来源、确认与实施状态

本规格按 `to-spec` 汇总 2026-11-04 本会话已确认的需求。用户先确认 Q1“交互布局参照，视觉沿用 Coko”，随后对 Q2—Q6 采用推荐并明确“Q5 移除费用展示”；对 Q7、Q8、Q10、Q11 采用推荐，要求先调查 Q9 的实际统计链路；在获知当前统计缺陷、参考实现及其限制后，对修订的 Q9 回复“全部采用建议”。产品需求因此为 `approved`。当前实施状态为 **未开始**；源码调查与最小校验不表示产品已修复或验收通过。

本功能使用独立 tracker 目录，是已交付的[对话详情规格](../conversation-detail/spec.md)之后的新修订。本文只接管消息底栏、助手回复分支和本轮用量统计的要求；旧规格保留为当次交付基线。本文明确修订范围内，以本次确认优先；消息正文、工作步骤、工具详情和阅读位置等仍沿用原有规则。

既有约束见[术语表](../../GLOSSARY.md)、[界面约定](../../docs/tech-stack/ui.md)、[设计系统规格](../../docs/tech-stack/ui-design-system.md)、[测试约定](../../docs/tech-stack/testing.md)、[tracker 协议](../../docs/agents/issue-tracker.md)、[开发流程](../../docs/DEVELOPMENT_WORKFLOW.md)和 [ADR 0006](../../docs/adr/0006-file-checkpoints-and-rewind.md)。任务材料不加入正式文档导航。

## Problem Statement

用户在助手消息下看到独立的 `0 tokens · $0.00` 行，既缺少便捷的回复分支入口，也无法查看本轮输入、输出及缓存消耗。用户消息底部缺少发送时间，而且分叉入口的位置和用户希望的操作不符。

这不只是底栏样式问题。当前界面可能因为用量对象包含合法的额外字段而跳过真实统计，显示零；重试和失败压缩中已经报告的消耗也可能漏计。用户需要底栏显示真实、可解释、可回看且不重复计算的本轮消耗，不能用默认零掩盖未取得的计数。

## Solution

### 底栏与消息操作

| 编号 | 已确认行为 |
| --- | --- |
| FOOT-01 | 移除原独立 `tokens · 费用` 行，以每个已结束 Run 的一个助手底栏承载操作、用量和时间。交互布局参考 DeepSeek Harness，视觉使用 Coko 的字体、语义 token、图标和共享浮层组件。 |
| FOOT-02 | 助手底栏依次提供复制、在新对话中分支、本轮 token 入口、结束时间。参考实现的其他扩展操作不因本规格自动纳入。新底栏及其用量详情卡均不展示费用。 |
| FOOT-03 | 生成中不展示本轮结束底栏，阶段回复不各自附加重复底栏；正常结束后放在本轮最终助手回复下。 |
| FOOT-04 | 停止或失败的 Run 也展示已取得的用量和可信结束时间；没有最终回复时，底栏位于本轮已产出内容或结束状态之后。没有助手正文时不提供复制；停止、失败和仍在生成的回复均不提供分支。 |
| FOOT-05 | 用户消息底部提供发送时间、复制 icon 和“回退到此处”icon，不展示“从这里分叉”按钮。用户消息不显示本轮用量。 |
| FOOT-06 | 用户发送时间和助手 Run 结束时间始终显示。默认使用本地时区的 24 小时 `HH:mm`，悬停可读完整日期及秒；键盘路径也能读取完整时间。使用实际提交/结束记录，重新加载不把时间改为查看时刻。缺少可信时间的历史记录不伪造时间。 |
| FOOT-07 | 最新助手回复的操作及用量常显，历史助手回复在悬停或键盘焦点进入时显示；用户复制、回退同样在悬停或聚焦时显示。无悬停能力时操作保持可见。时间不随操作隐藏。 |
| FOOT-08 | 助手复制该条回复的原始 Markdown 正文，不含思考、工具过程、用量、时间或底栏标签；用户复制发送的原始文本。复制不隐式下载附件或复制图片二进制。成功后图标短暂变为勾号并提示“已复制”；失败不显示成功状态，沿用应用反馈机制。 |
| FOOT-09 | 操作遵守键盘可达、可访问名称、仅图标 Tooltip 和焦点规则；底栏出现、流式更新和显隐不无故改变消息身份、阅读位置或正文选区。支持明暗主题、zh/en 和主内容宽度至少 390 CSS px。 |

### 在新对话中分支与回退

| 编号 | 已确认行为 |
| --- | --- |
| FORK-01 | 所有成功完成且有最终助手正文的回复，包括非最新的历史回复，均可作为新对话分支的内容边界；不采用参考实现“只能对最新一轮分支”的限制。 |
| FORK-02 | 新 Session 保留截至所选助手回复的完整有效上下文，包括该轮先前的用户输入、思考及工具调用和结果，排除边界之后的上下文。已压缩历史按现有摘要与保留区间表达，不凭空恢复不存在的原文。 |
| FORK-03 | 分支自动打开新 Session，输入框为空，不把旧的目标用户消息或助手回答回填为草稿。原 Session、原草稿和现有文件不因分支改变。 |
| FORK-04 | 分支沿用源 Session 的项目归属、模型及现有必要配置，使用同一工作目录和当前文件，不复制、还原或新建历史文件快照，也不自动创建 Worktree。沿用现有授权及只读限制；分支不能绕过运行中、待审批、待结果确认等禁止条件。 |
| FORK-05 | 来源可追溯，复制的历史用量仍属于源 Session，不计入新 Session 的新增消耗。新 Session 后续请求可以使用保留下来的完整对话。分支失败保留源对话并给出错误，不报告虚假的成功。 |
| REWIND-01 | 用户回退沿用现有确认框，支持“仅对话／仅代码／对话和代码”，默认“对话和代码”。涉及对话回退时，从有效上下文撤回目标用户消息及之后内容，保留原始记录，并将目标用户文本返回输入区，沿用已有草稿合并规则。 |
| REWIND-02 | 文件回退沿用现有 Checkpoint 预览、文件清单、偏离提示、路径边界与执行限制；仅覆盖文件工具追踪范围，不承诺撤销 bash 或外部副作用。取消确认不改变上下文或文件。 |

### 本轮用量与详情卡

| 编号 | 已确认行为 |
| --- | --- |
| USAGE-01 | “本轮”使用 Coko Run 的真实归属，汇总当前 Session 中该 Run 实际启动的模型请求，包括工具循环、已报告用量的失败尝试与重试、上下文压缩。排除标题生成和子 Session 的子代理消耗，不跨 Run 混算。 |
| USAGE-02 | 每次真实请求尝试只计一次；不同时把同一次请求的助手消息、追踪记录和压缩结果重复相加。只计划但未发出的重试不算请求，重试后也不能丢失前次已报告的消耗。 |
| USAGE-03 | 优先修复真实 usage 获取、归一化、持久化与汇总链路。当前依赖返回的合法额外字段不能导致整条用量被丢弃；不通过放宽所有协议校验或把所有异常归零来掩盖问题。 |
| USAGE-04 | 四个互斥分桶为未缓存输入、缓存读取、缓存写入、输出；总 tokens 为四者之和。服务商返回的输入总量若包含缓存，归一化时必须正确拆分，不能重复加缓存。reasoning 属于输出子集，不再次计入总量。 |
| USAGE-05 | 正常完成且服务已报告完整 usage 时，必须展示准确的本轮总量。真实、明确报告的零可以显示为 `0 tokens`；“没有取得”与“实测零”必须可区分。只在协议明确规定省略即零时按零解释，不用本地 tokenizer 估算冒充服务端计量。 |
| USAGE-06 | 对取消、断流、失败或缺少必要计数的请求，保留已经取得的有效计数；整轮展示明确的“不完整”标记，详情说明存在未完整报告的请求。完全没有有效计数时仍保留可识别的用量状态入口，表达未取得完整统计，不显示伪造的 `0 tokens`。失败尝试和失败压缩中已经报告的消耗同样保留。 |
| USAGE-07 | 底栏 token 使用紧凑格式，点击打开详情卡；卡内展示精确总数、可可靠归属的 Provider/模型、缓存命中率、未缓存输入、缓存读取、缓存写入、输出，以及确有数据的 reasoning 子集。多请求或多模型不能错误标为单个模型；不支持或未报告的可选字段不伪造为零，部分统计不可伪装为精确的整轮指标。 |
| USAGE-08 | 详情卡可再次点击触发器、外部点击或 Escape 关闭，关闭后焦点按共享组件规则返回。浮层优先出现在触发器上方，适配视口边缘、窄窗口和长模型名，不被消息容器裁剪，不在打开后因父行失去 hover 而消失。 |
| USAGE-09 | 重连、重新打开 Session、应用重启和历史回放后的统计与持久化事实一致；相同事件重放不翻倍。兼容旧记录中已存在的合法用量形状，不能因额外字段整体拒绝；旧记录无法证明完整性时明确限制，不补写虚构历史计数。 |
| USAGE-10 | 移除费用仅作用于本规格的新底栏及详情卡，不删除请求计量、费用预算和审计数据，不改变现有会话累计费用入口或定价能力。 |

## User Stories

1. 作为用户，我希望助手底部不再出现旧的 token 与费用独立行，以便直接阅读回答。
2. 作为用户，我希望每轮只出现一个助手底栏，以便知道用量对应整轮执行。
3. 作为用户，我希望在底栏复制当前助手正文，以便保存原始 Markdown。
4. 作为用户，我希望复制不混入思考和工具过程，以便得到所选回复本身。
5. 作为用户，我希望复制成功有短暂反馈，以便确认操作结果。
6. 作为用户，我希望复制失败得到明确提示，以便重新尝试。
7. 作为用户，我希望从助手回复创建新对话分支，以便探索另一条思路。
8. 作为用户，我希望历史成功回复也能分支，以便从早期结论继续。
9. 作为用户，我希望新分支保留截至该回复的工具和对话上下文，以便模型理解已有工作。
10. 作为用户，我希望新分支自动打开且输入框为空，以便立即提出新问题。
11. 作为用户，我希望原对话和草稿不受分支影响，以便保留原来的工作。
12. 作为用户，我希望分支继续使用当前工作目录的文件，以便理解它不会恢复历史代码。
13. 作为用户，我希望停止或失败的回复不提供完成回复分支入口，以便避免误认它已经成功结束。
14. 作为用户，我希望用户气泡下显示发送时间，以便回看何时提交了指令。
15. 作为用户，我希望助手底栏显示整轮结束时间，以便了解本轮何时结束。
16. 作为用户，我希望悬停或键盘操作可查看完整日期和秒，以便区分跨日历史。
17. 作为用户，我希望复制用户原始文本，以便再次使用相同指令。
18. 作为用户，我希望用户气泡只提供复制和回退，以便在明确的位置执行相应操作。
19. 作为用户，我希望回退前能选择对话、代码或两者，以便控制实际恢复范围。
20. 作为用户，我希望对话回退将目标指令送回输入框，以便修改后重新发送。
21. 作为用户，我希望回退继续说明文件工具边界和偏离情况，以便了解哪些文件会改变。
22. 作为用户，我希望看到本轮全部模型请求的 token 合计，以便理解完整消耗。
23. 作为用户，我希望已经报告的失败尝试、重试和压缩消耗不被漏掉，以便统计反映真实请求。
24. 作为用户，我希望标题和子代理消耗不混入这个本轮入口，以便保持约定的统计范围。
25. 作为用户，我希望同一请求不会因为有多种记录而重复计数，以便信任总量。
26. 作为用户，我希望服务已经返回的 usage 不因额外字段被丢掉，以便避免正常回答显示假零。
27. 作为用户，我希望点击 token 打开精确明细，以便检查输入、输出和缓存使用。
28. 作为用户，我希望能查看确实报告的 reasoning 子集，以便了解输出构成而不重复计算。
29. 作为用户，我希望看到有数据依据的模型归属和缓存指标，以便解释本轮表现。
30. 作为用户，我希望未完整取得的统计有明确标记，以便不把部分数值当成总量。
31. 作为用户，我希望新底栏及详情卡不展示费用，以便聚焦 token 和消息操作。
32. 作为用户，我希望重启和重新打开对话后的统计一致，以便可靠回看历史。
33. 作为用户，我希望分支复制的历史消耗不计为新对话新增消耗，以便避免重复归账。
34. 作为键盘用户，我希望能聚焦、操作和关闭底栏浮层，以便无需鼠标完成操作。
35. 作为用户，我希望最新操作容易找到、历史操作按需显示，以便兼顾可达性与阅读清晰度。
36. 作为用户，我希望底栏在明暗主题和窄窗口下可读且不扰乱阅读位置，以便持续查看长对话。

## Implementation Decisions

- **以 Run 聚合展示。** 消息时间线、底栏与用量详情使用真实 Run 和 Session Entry 归属，不把参考项目的 Turn 直接当作 Coko 的领域对象；运行时状态、持久化事实和纯展示状态分别负责。
- **复用界面基础设施。** 消费现有按钮、Tooltip、浮层、Toast、字典和设计 token；布局与操作顺序参考 DeepSeek Harness，不复制其品牌、主题或非本范围的扩展操作。
- **扩展 Fork 边界。** 当前用户 Checkpoint 之前分叉并回填用户草稿的语义，不能直接搬到助手底部。新增以成功助手回复为包含边界的分支能力，保留当前公开调用方的既有语义，避免旧调用方静默改变行为。具体请求字段、来源记录版本和迁移方式在功能设计中确定。
- **遵守既有记录约束。** 不通过删除或更新旧 Session Entry 来实现回退、分支或修复历史统计。Fork 来源、压缩摘要、有效区间和新 Session 的用量归属必须一致。
- **使用当前工作目录。** 分支继承既定工作目录语义；源 Session 已绑定 Worktree 时不能无意改为项目默认目录。不把“共享当前文件”实现为创建新 Worktree 或恢复历史代码。
- **记录每次请求尝试的计量事实。** 模型调用、重试、压缩、持久化、追踪及界面汇总需共享可去重的请求归属；已有接口足够时优先扩展，避免另建平行计量系统。数据结构与是否复用现有请求记录由功能设计说明。
- **在适配边界归一化。** 从实际 Provider usage 获得四个互斥 token 分桶、可选 reasoning 和完整性信息，兼容当前依赖的合法扩展字段。保留必要协议校验；不能简单把严格校验改成无条件接受任意对象。
- **完整性属于事实。** 必须能区分实际报告的零、协议规定的零、未知和部分报告；不能仅从已初始化为零的对象推断“已取得”。适配器若丢失字段存在性，需要在足以保留原始报告事实的边界解决，不能让 UI 猜测。
- **单次请求单一计数。** 同一请求的最终消息、尝试记录、追踪和压缩结果不能各计一次；失败、中止与重试仍保留已报告消耗。汇总使用确定的来源与去重规则，不能按“数值相同”去重。
- **向后读取。** 已持久化的旧 usage 需要兼容读取；对其有效字段进行归一化，不改写为猜测值。重连及加载后的结果与同一批事实在线更新的结果一致。
- **不扩展移除费用的范围。** UI 隐去新底栏和详情卡的费用，不删计量或预算字段；会话累计费用消费者需要进行相关回归，但本规格不重新设计该入口。
- **设计与正式记录的衔接。** 助手 Fork 扩展了现有领域定义和 ADR 0006 的用户锚点分叉边界。实施前的功能设计需要说明兼容契约；按领域文档流程同步术语，并为改变已实施长期决定记录明确后继关系。当前 ADR、术语和实现说明不会仅因本规格已批准就被宣称已变更或已实现。

## Testing Decisions

### 入口与原则

优先复用两处现有高层入口：**真实 Sidecar 协议集成测试**验证运行、请求、持久化和分支上下文，**实际 App 的 Browser Mode 测试**验证底栏和详情卡。另以静默真实 Electron 完成代表性桌面验收；只有模型服务、外部网络和时钟等不确定边界使用可控替身，不逐层 mock 内部汇总与存储。

用户于 2026-11-04 对 `to-spec` 第 2 步的测试边界核对回复“采用建议的测试边界”，因此以上 Sidecar 协议集成、实际 App 的 Browser Mode 与静默 Electron 验收方案均已确认。只在模型服务、外部网络和时钟等不确定边界使用可控替身，不逐层 mock。

1. **外部行为优先。** 断言真实请求上下文、持久化记录、重载后的值、渲染结果、剪贴板内容和文件逐字节状态；不以 class 名、函数调用次数或助手声称完成替代结果。
2. **请求链路回归。** 通过真实适配入口输入代表性的 Chat Completions、Responses、Anthropic 流式响应，包含实际依赖的扩展字段，验证服务已返回的用量不会变成零。不能只用人工裁剪后的规范 usage 夹具绕过已复现问题；必要时在已有适配边界增加聚焦协议用例，不增加公开产品 API。
3. **整轮、重试与压缩。** 覆盖多模型请求、失败后重试、已报告用量后中止、失败压缩及正常压缩、标题和子 Session 排除、消息与追踪重复载体、真正零和不完整数据。计数与完整性经持久化后读回验证。
4. **分支与回退。** 通过协议从较早成功助手回复分支，再发请求检查模型实际收到的上下文；确认原 Session、文件和草稿不变，目标无旧消息草稿、历史用量不重复归属，并覆盖压缩及既有禁止条件。用户回退继续验证三模式与取消后的文件事实。
5. **界面行为。** 通过真实 App 装配验证每 Run 一个底栏、完成和停止/失败、空正文、最新与历史显隐、复制内容及反馈、时间格式、详情字段及不完整标记、费用缺席、浮层关闭与焦点返回。
6. **重放与兼容。** 使用无需密钥的录制或可控会话输入覆盖额外 usage 字段、旧记录、不完整报告和重连/重启；新增或更新相关可见输出预期，逐项审查差异，不直接用实际结果覆盖独立期望。
7. **桌面与视觉验收。** 静默 Electron 检查本规格交互及原生剪贴板边界，记录明暗主题、zh/en、窄窗口、历史/最新、键盘和浮层边缘结果。真实鼠标或原生层需要前台窗口时先告知，浏览器证据不能替代该类验证。
8. **执行范围。** 实施后运行最小相关测试集及类型检查，涉及数据和协议时扩大到真实消费者；无理由不运行全仓测试。真实 Provider 验证与无密钥协议回放分别报告，不能把可控流测试称为真实服务验证。本次仅产出规格，不运行产品测试或宣称功能通过。

已有测试先例包括 [Sidecar 回退和分叉集成测试](../../tests/integration/sidecar-rewind.test.ts)、[Sidecar 压缩集成测试](../../tests/integration/sidecar-compaction.test.ts)、[消息区浏览器测试](../../apps/desktop/src/renderer/features/conversation/messages.browser.test.tsx)、[用量与费用浏览器测试](../../apps/desktop/src/renderer/features/conversation/session-cost.browser.test.tsx)、[对话联合浏览器测试](../../apps/desktop/src/renderer/features/conversation/integrated-detail.browser.test.tsx)和 [Electron 回退与分叉测试](../../apps/desktop/e2e/rewind.e2e.test.ts)。其中用户消息分叉旧断言需要随本次入口调整更新，不能继续将旧行为测试当作助手分支已覆盖。

## Further Notes

### 当前源码调查及证据边界

本次调查的 Coko 基线为 `9ce6350823f3a401c3d78cbb214d160d812ed4f3`，参考项目 DeepSeek Harness 基线为 `8bd073392eef6f54e921a093b95076248eb08cbb`。调查中 Coko 使用与锁文件一致的 pi-ai 1.4.0；版本或相关源文件变化后需重新判断证据有效性。

已通过不落盘的最小校验确认：实际 RequestUsage schema 可接受基础规范对象，但分别添加 `reasoning: 0` 或 `cacheWrite1h: 0` 后均拒绝。现有界面会跳过不通过该校验的助手 usage，因此存在“真实用量被整体丢弃、合计显示为零”的源码与最小复现证据。没有读取用户私人会话，也未证明用户某一条真实回复的零值必由此路径产生。

当前统计还存在完整性盲点：适配器和部分记录转换会默认填零；重试只向外暴露最后尝试；失败压缩即使已有请求计量也不一定进入当前底栏汇总。这些调查结论说明本次不能仅隐藏旧行或换一个前端求和函数。

DeepSeek Harness 从真实流式 usage 及持久化请求尝试汇总整轮，能够检查请求生命周期和计数矛盾；缺失时隐藏入口。但它也存在适配器缺字段默认零、结束前取消未产出 usage 等限制，其详情卡不含费用，独立压缩也不自动计入该 footer。本规格借鉴它的请求级记录、汇总和详情交互，不照搬其缺失隐藏、仅最新可分支或默认统计范围。Coko 按本次明确确认的行为实现。

助手结束时间使用 Coko Run 结束记录，不直接复制参考实现实际采用的最终助手消息完成时间。
