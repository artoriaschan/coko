---

按以下顺序验证 Coko 的当前改动。选择范围、隔离和报告措辞的规则正文在 [测试约定](../../../docs/tech-stack/testing.md)；本 skill 只规定执行顺序和完成条件。

1. **列改动。** 有 Git 时用 `git status` 和 `git diff` 列出工作区与暂存区的全部改动；无 Git 时列出本次编辑的文件。完成条件：得到完整的改动文件清单。
2. **读真实入口。** 读取根和受影响 workspace 的 `package.json` scripts、`vitest.config.ts` 及已有的 CI 工作流。完成条件：后续要运行的每条命令都在这些文件里存在；技术规范中规划但尚未接入的检查标为"未接入"。
3. **映射检查。** 为每个改动文件选择能捕获其回归的最小检查：
   - Markdown 与 skill 文件：`pnpm run check:docs`；文档语义读回由 `coko-docs` 负责。
   - TypeScript 源码与测试：所属测试文件 `pnpm run test <文件路径>`，加 `pnpm run typecheck`。
   - 依赖、manifest、tsconfig 或 Vitest 配置：`pnpm install --frozen-lockfile`、`pnpm run typecheck` 和受影响的测试。
   - 构建、打包或进程入口：对应构建命令和产物 smoke；入口尚未接入时标为"未验证"。
   完成条件：每个改动文件都对应至少一项检查，或写明为何不需要。
4. **运行。** 逐项运行，保留精确命令、退出码和实际选中的测试数量。完成条件：每项都有结果；零用例或全部跳过记为未验证；失败按测试约定先定位再修复，修复后只重跑失效的检查。
5. **报告。** 按测试约定的"测试执行与结果报告"，列出命令、范围、数量和结果，区分通过、失败、跳过、未运行和 CI 等待中，并写明未覆盖的范围（真实模型、Electron、产物、CI）。完成条件：报告中的每个结论都对应第 4 步的实际输出。
