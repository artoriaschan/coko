# 04: 进入规划不再改变 Permission Mode

**What to build:** 权限与规划各走各的入口。用户用 `/plan` 进入规划后，模式菜单仍显示并勾选原来的 Permission Mode，读取、命令与 MCP 是否询问照旧按它判定；批准计划只结束规划，不恢复也不改变权限。Plan chip 与 `/plan` 经新的计划接口进入和退出。在“完全访问权限”下规划不再逐条弹审批。服务端与桌面必须在同一张票里改，否则 chip 与审阅卡会失效。见 [规格](../spec.md) 的“阶段一：判定、沙箱与注入”“阶段一：协议与入口”“阶段一：界面”与设计稿。

**User stories:** 1、2、3、4、5、6、15、16、17、18、19、20（动作部分）、21、22、25、26、27、28、29、30、32、38、39、40

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] Session 计划接口的进入与退出动作：已在规划中进入、不在规划中退出都不提交条目；Run 进行中动作可用，写入拒绝与沙箱档位即时生效或解除，系统消息与工具集到下一个 Run 才变化
- [ ] `/plan [消息]` 与 `/plan off` 调用同一组动作；Run 进行中以 `run-in-progress` 拒绝；新对话里 `/plan 消息` 以规划开始并提交该消息
- [ ] 进入规划不提交 `permission_mode` 条目；四种 Permission Mode 下进入后模式读回不变
- [ ] 规划中命令与 MCP 的询问与否和未规划时相同：完全访问权限下不询问，请求批准下询问；拒绝规则、询问规则与受保护路径照常生效
- [ ] 批准：条目顺序为审批决定、工具执行、已批准的 `plan`、计划阶段“无”、工具结果；不提交 `permission_mode`；模式读回不变；工具结果文本按设计稿，不再提及恢复到哪个模式
- [ ] 带 `mode` 的批准回答返回 400，请求保持等待；`editedPlan` 的规则不变，编辑后批准仍产生新修订
- [ ] 带反馈拒绝、无反馈拒绝、停止时取消的行为与条目不变；Goal Round 中审阅时 Goal 进入等待输入不变
- [ ] 切换 Permission Mode 的接口与首次发送对 `plan` 返回 400；无界面运行的 `--permission-mode plan` 为参数错误并列出合法取值
- [ ] Subagent 的有效 Permission Mode 为父 Session 模式与定义上限的较窄者，规划中不再被压成 read-only；03 的约束照常生效
- [ ] 规划中外部 Hook 收到的权限模式是真实的 Permission Mode
- [ ] 定时任务在规划中的 Session 上触发时照常注入规划说明并受约束
- [ ] `<plan_mode>` 的文本为设计稿的最终版（其余调用按当前权限处理）
- [ ] 桌面：计划阶段由条目派生；Plan chip 由计划阶段驱动，× 调用退出动作，失败时保留状态并提示，草稿与其他配置不变
- [ ] 桌面：模式菜单显示并勾选当前 Permission Mode，规划中切换不退出规划；Shift+Tab 只切换 Permission Mode
- [ ] 桌面：审阅卡主按钮为“批准并执行”，没有“批准并允许编辑”与“将恢复的模式”
- [ ] Sidecar 集成测试与 renderer 浏览器测试覆盖以上各项；现有断言 `prior` 与恢复模式的用例改为断言模式不变，并在评论中说明
- [ ] 文档：Plan Mode、权限判定与审批、子代理、无界面运行、外部 Hook、桌面工作台；`pnpm run check:docs` 通过
