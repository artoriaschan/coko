# 02: 计划阶段成为“是否在规划”的唯一来源

**What to build:** 预重构，用户可见行为不变。新增记录 Session 计划阶段的条目；现有的进入、退出与批准路径在改变 Permission Mode 的同时记录计划阶段；提交工具的注册、`<plan_mode>` 的注入、“调用时是否仍在规划”与“本次规划的起点”改为读取计划阶段。经协议可以读到 Session 的计划阶段与活动的 Plan。完成后，后面的票可以逐步把约束和入口从 `plan` 模式上挪走，每一步全仓保持通过。见 [规格](../spec.md) 的“两个阶段共用的数据形状”与设计稿（01 票产出）。

**User stories:** 20（读取部分）；支撑 22、30

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 新增计划阶段条目，payload 含“无”“规划中”“执行中”（带 planId）；agent 与 protocol 两侧 schema 编译期比对一致；renderer 收到新 kind 不报错
- [ ] `plan` 条目的 schema 增加已完成（带完成报告）与已放弃两个状态；现有条目照常读取，本票不写入这两个状态
- [ ] 现有每条进入路径（切换接口设为 `plan`、`/plan`、首次发送带 `plan`）提交“规划中”；已在规划中时不重复提交
- [ ] 现有每条退出路径（`/plan off`、Plan chip、从 `plan` 选择其他模式、批准计划）提交“无”；不在规划中时不提交
- [ ] `exit_plan_mode` 的注册、`<plan_mode>` 的注入、调用时“是否仍在规划”、planId 与 revision 的派生起点都读取计划阶段；faux 请求日志中的 section、工具集与条目顺序同改动前（新增的计划阶段条目除外）
- [ ] 分叉与交接：源在规划中时，新 Session 同时得到 `plan` 模式与“规划中”的计划阶段，两者一致
- [ ] 计划阶段的回放口径本票与 Permission Mode 相同，回退行为不变（改为跟随回退在 06）
- [ ] Session 计划接口的读取：返回当前阶段与活动的 Plan（规划中且有待审阅的计划时为它，否则为空）；未知 Session 的错误码与同类接口一致
- [ ] 审计序列包含计划阶段的转换
- [ ] 现有 Plan Mode 的集成测试、判定测试、界面测试与端到端用例不改断言即通过；新增断言覆盖阶段读回、条目顺序与分叉后的阶段
- [ ] 确认会话数据诊断的类型筛选是否需要处理新 kind
- [ ] 已知的过渡状态：升级前已停在 `plan` 模式的 Session 没有计划阶段条目，本票之后它不再注入 `<plan_mode>`，判定仍按 `plan` 模式；由 07 的读取迁移收尾。写入本票的评论
- [ ] 文档：Plan Mode 当前行为文档补充计划阶段条目与读取接口，协议与包 README 中的条目清单同步；`pnpm run check:docs` 通过
