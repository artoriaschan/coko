# 03: 摘要层

**What to build:** 超出正文预算的记忆不再从 Agent 眼前消失。正文层放不下的条目降为一行摘要：带 id、作用域、来源，以及正文第一个非空行截到 60 字符；第一行被截断或正文还有后续内容时以省略号结尾，单行且不超过 60 字符的完整显示。摘要层前有一句固定说明，告诉模型需要全文时用 `memory_list` 的 `ids` 读取。摘要层有独立的 6 000 字符预算，按与正文层相同的规则分两级（项目级先放至多 3 000，余量回流）。摘要也放不下的条目才只在段末计数。写入引导增加一句“把第一行写成能单独看懂的一句话”。条目没超正文预算时，段内没有摘要层与它的说明。

**规格场景:** [spec](../spec.md) 的 AC-01 至 AC-06、AC-09、AC-10、AC-11、AC-15、AC-30；实现决定“三层与候选顺序”“摘要层”“写入引导”；用户故事 1、3、6 至 13、23、24、26。

**文档影响:** [Memory](../../../docs/subsystems/memory.md) 的注入、工具与权限（`memory_list` 的描述）与验证各节及其 frontmatter 摘要；[上下文管理](../../../docs/subsystems/context.md)中上下文用量如有关于 Memory 段长度的说明则同步。

**Blocked by:** 01 注入的候选顺序：用户手写的在前；02 memory_list 按 id 读取

**Status:** ready-for-agent

- [ ] AC-01：可见条目没超正文层预算时，段内没有摘要层说明与摘要行。
- [ ] AC-02：不属于项目的 Session，用户级条目合计超过 12 000 字符时，正文层之后出现说明与摘要行；每行带 id、作用域、来源与不超过 60 字符的第一行；摘要行合计不超过 6 000 字符，正文层仍不超过 12 000 字符。
- [ ] AC-03：正文多行、首行超过 60 字符的摘要以省略号结尾；单行且不超过 60 字符的完整显示、没有省略号；截断不落在代理对中间。
- [ ] AC-04：摘要层也放不下时，段末注明的条数等于可见条目总数减去正文层与摘要层的条数，并提示用 `query` 检索。
- [ ] AC-05、AC-06：项目 Session 中摘要层项目级在前且不超过 3 000 字符；项目级摘要少时用户级用到剩余额度，项目级多而用户级少时余量给项目级；没有项目级候选时用户级可用满 6 000。
- [ ] 摘要层从正文层没放入的第一条接着取，沿用 01 的候选顺序；每一级遇到放不下的即停止。
- [ ] AC-09：摘要行中的结束标签被转义，正文第一行里伪造的开始标签与来源标注不改变段的结构与其他条目的来源（对手用例）。
- [ ] AC-10：保存时含凭据形态文本的条目落在摘要层时，请求中只有脱敏后的文本。
- [ ] AC-11：写入引导含“第一行写成能单独看懂的一句话”；有无摘要行两种情况下固定文本各自逐字不变，说明与引导不计入任何一层的预算。
- [ ] AC-15：子 Session 与 Headless Run 的请求中同样有摘要层，没有写入引导。
- [ ] AC-30：记忆开关关闭时请求中没有 Memory 段与记忆工具。
- [ ] 单元测试覆盖两层各自的两级分配与边界（恰好等于上限、单条放不下、余量回流）与摘要的截断；一条真实 Sidecar（faux 脚本）用例确认请求中各层的实际排列，并在同一用例中按 id 读出摘要层条目的全文。
- [ ] 按[测试约定](../../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关集与类型检查；实际执行的检查和文档影响记入 Comments。
