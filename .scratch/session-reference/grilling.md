# 输入区的 / 与 @：设计树与采纳记录

2026-11-21。用户调用 `/grill-me`，主题为“输入框支持 skill、插件和文件引用的功能，/ 和 @ 触发菜单”。四轮共 23 个问题。第 1 轮按“从零做”提问；现状调研返回后发现 `/` 菜单、`@` 文件菜单、Skill 与插件格式兼容都已上线，第 3 轮撤回了改动已上线行为的两条推荐（Q2、Q3），并作废了第 2 轮中已被现状回答的两问（Q6、Q7）。范围最终收敛为两件事：`/` 菜单增加“插件”分组、`@` 引用会话。用户对第 3、4 轮全部采纳推荐，并在最后确认了共识清单与“先写规格再拆票、两件事合入同一份规格”的下一步。

本文记录设计树与已采纳的决定。

## 已核对的事实

来源：访谈期间子代理对输入区、Skill、插件、文件候选与 UI 基建的调研，主会话阅读 [命令](../../docs/subsystems/commands.md)、[上下文管理](../../docs/subsystems/context.md)、[插件](../../docs/subsystems/plugins.md)、[交接](../../docs/subsystems/handoff.md) 与术语表；写规格前又核对了引用展开、有效条目派生、回退目标文本、命令目录与命令菜单的代码。除下文注明的一处探针外未运行测试。

- **`/` 命令菜单已上线。** 只在草稿第一个字符为 `/` 时出现，命令式（`/name 参数`），一条消息一个；按来源分组：内置、项目、用户、Skill、MCP。选中后插入纯文本 `/name `。
- **Skill 已在 `/` 菜单里。** 以 Skill 来源登记为命令，`$ARGUMENTS`、`$1` 等占位符已支持。
- **`@` 文件菜单已上线。** 词首触发，文件与目录都出，目录上 Tab 下钻，选中后插入 File Reference 节点（chip）。提交的文本就是 Sidecar 解析的语法 `@path`，请求体没有专门字段。
- **File Reference 在提交时内联内容。** 单文件 2000 行或 50KB，每条消息最多 10 个、合计 200KB；二进制、Workspace 外与 Read 拒绝规则覆盖的只附一行说明；块中已登记的 Secret 明文在生成时替换。
- **插件已兼容 Claude Code 格式。** 读 `.claude-plugin/plugin.json`，替换 `${CLAUDE_PLUGIN_ROOT}`；插件的 Skill 以 `插件名:skill名`、插件的命令以 `插件名:命令名` 进入命令目录。命令目录的来源取值里没有“插件”：插件命令记为用户来源，插件 Skill 记为 Skill 来源。清单里的 `userConfig`、`channels`、`outputStyles`、`settings` 被忽略并记诊断；安装来源只有本地目录与 git。
- **引用其他会话不存在。** 模型没有读取其他 Session 的工具；Session 存在 SQLite 中，不是文件。
- **会话列表与归属。** 会话列表接口不含子 Session；Session 带所属 Project（独立对话为空）、归档时间与最近更新时间。术语表中每个 Standalone Session 有自己的 Workspace，一个 Project 下的 Worktree Session 工作目录各不相同。
- **有效上下文有现成的派生。** 条目派生的唯一实现能给出“回退与压缩都已应用”的有效条目，最后一个有效的 Compaction 条目带摘要正文；回退用它恢复命令消息的原始调用 `/name 参数`。Q18 依赖的前提成立。
- **回退后引用以纯文本回到草稿。** 回退与分叉返回的文本经“替换编辑区文本”进入输入区，File Reference 不恢复成 chip，是纯文本 `@path`；再次提交仍被解析。Q20 的代价与文件引用相同。
- **回退目标文本带着引用块。** 写规格前用一次性探针直接调用回退目标的纯函数：一条带 File Reference 的用户消息，返回文本是原文加上整个 `<file_reference>` 块。界面是否在别处剥离没有运行验证。会话引用的块最大 50KB，不能照此回到草稿，规格把它列为必须处理的事项。

## 设计树

```text
输入区的 / 与 @
├── A 现状与范围 ── A1 插件是 / 菜单里的来源，不是可引用的对象 [已定 Q1，Q13 收敛]
│               ├── A2 Skill 保持命令式 [已定 Q11，撤回 Q2]
│               ├── A3 File Reference 保持提交时内联 [已定 Q12，撤回 Q3]
│               └── A4 非目标 [已定 Q5、Q13]
├── B / 菜单的插件分组 ── B1 只改展示，不动优先级 [已定 Q21]
├── C 会话引用 ── C1 提交时附上文字记录 [已定 Q14，取代 Q8]
│            │      ├── C2 压缩过的会话取有效上下文 [已定 Q18]
│            │      ├── C3 上限与 File Reference 共用 [已定 Q19]
│            │      └── C4 记录的细则 [已定 Q23]
│            ├── C5 可引用范围按 Project [已定 Q17，修正 Q15]
│            ├── C6 与文件同一个列表分两组 [已定 Q16，取代 Q10]
│            └── C7 文本语法与显示 [已定 Q20]
└── D 交付 ── D1 术语 [已定 Q22]
          ├── D2 一份规格，先规格后拆票 [已定]
          └── D3 留给规格的细节 [规格阶段]
```

## 已采纳的决定

### A 现状与范围

- **A1（Q1、Q13）插件。** 用户对 Q1 的回答是“插件兼容 Claude Code 插件”。格式兼容已是现状；对输入区而言缺的只是 `/` 菜单没有“插件”分组。菜单里没有“引用一个插件”的动作。
- **A2（Q11，撤回 Q2）Skill 保持命令式。** `/` 仍只在草稿开头触发，一条消息一个命令。Q2 曾接受“引用式、任意位置、可多个”，那会改掉已上线并有测试覆盖的触发位置、服务端调用识别、时间线命令 chip 与回退恢复；句中想点名某个 Skill 时直接写名字，模型能从系统提示的 Skill 索引自行加载。
- **A3（Q12，撤回 Q3）File Reference 保持内联。** Q3 曾接受“只传路径”；现状是内联，大文件、二进制与总量都已有截断和上限，术语表的定义也是“提交时附上其内容”。
- **A4（Q5、Q13）非目标。** `@` 引用 URL、代码符号、Git diff、终端输出、子代理与 MCP 资源；在菜单里管理 Skill 与插件；Workspace 之外的文件；插件 marketplace 与四个被忽略的清单字段。Q5 中用户补充“@ 还可以引用其他的会话”，由此开出 C 分支。

### B / 菜单的插件分组

- **B1（Q21）只改展示。** 命令目录的每一项多带一个可选的插件名；菜单把带插件名的条目归入单独一个“插件”组，位于 Skill 组之后、MCP 组之前，组内按名字排序。不按每个插件各开一组（条目名已带 `插件名:` 前缀）。同名优先级（内置 > 项目 > 用户 > Skill > MCP）与设置页的“Skills & Commands”分区不动。

### C 会话引用

- **C1（Q14，取代 Q8）内容。** 提交时附上被引用会话的文字记录：用户消息与助手的文字回复，不含工具调用。不发模型请求，不新增工具。与 File Reference 是同一条规则（提交时附上内容，带上限）。Q8 曾推荐“只传引用、按需读取”，那建立在文件只传路径上，A3 之后不再成立。
- **C2（Q18）压缩过的会话。** 取有效上下文的文字版：有压缩摘要时以摘要打头，接其后的消息。超限时保留最近的部分并注明省略。
- **C3（Q19）上限。** 单个会话引用 50KB，与单个文件一致；与 File Reference 共用每条消息最多 10 个、合计 200KB 的额度，超出时附同类的 `[Not attached: …]` 说明。
- **C4（Q23）细则，七条全部按默认。**
  1. 记录中已登记的 Secret 与 Credential 明文替换为标记，规则同 File Reference。
  2. 记录只含用户消息原文与助手的文字回复；不含思考、工具调用及结果、附件，以及那次会话自己带的引用块，所以不会递归展开。
  3. 用户消息是命令时，取原始调用 `/name 参数`，不取展开后的模板全文。
  4. 被引用会话正在运行时，只取已提交的条目，不含正在生成的回复。
  5. 提交时会话已被删除：不产生引用块，文本原样保留，与不存在的文件路径一致。
  6. Run 进行中的追加指令里可以引用会话；还没有 Session 的新对话草稿里也可以。
  7. `@` 菜单的键盘、输入法、定位行为沿用现有实现。
- **C5（Q17，修正 Q15）范围。** 按侧栏的分组：项目内的会话可引用同一 Project 的其他根会话（含它的 Worktree Session）；独立对话可引用其他独立对话；跨 Project 不出。排除当前会话与子代理会话。Q15 写的是“同一工作区”，但每个独立对话有自己专属的 Workspace，照字面执行独立对话什么都引用不了。
- **C6（Q16，取代 Q10）菜单。** 与文件同一个列表分两组，文件在前、会话在后，打字同时过滤两组。文件组行为不变；会话组空查询显示最近 5 个，按标题匹配，选中后插入显示标题的 chip。
- **C7（Q20）文本与显示。** 文本语法为 `@session:<id>`，请求体不加字段。草稿 chip 显示标题、整体选中删除、不可点击；时间线气泡正文显示 `@标题`，气泡下方另有可点击的会话 chip。代价：经回退等路径变回纯文本时用户会看到一串 id，再次提交仍然生效。

### D 交付

- **D1（Q22）术语。** 术语表新增 **Session Reference**，界面称“会话引用”：用户消息中以 `@` 指向同一 Project 内另一个 Session、提交时附上其文字记录的引用。File Reference 词条不动，避免使用 mention。
- **D2 交付方式。** 先写一份规格放进本目录，再拆实施票；插件分组很小，与会话引用放在同一份规格里。

## 推荐者保留的三处把握不足

用户问“你觉得呢”时列出，用户随后采纳了全部推荐。记录在此，便于以后复盘。

1. **C5 跨 Project 不出。** 只附文字记录时跨项目没有技术障碍，侧栏也已持有全部会话；选择限制是因为边界以后放开容易、收紧难，并与 File Reference“Workspace 外不附”一致。实际出现“在 A 项目里引用 B 项目的结论”的需要时，改为全部可引用、同项目排前。
2. **C2 的前提。** 当时未看代码；写规格前已核实有现成的有效条目派生可用（见上文事实）。
3. **C7 的代价。** 回退后显示 `@session:一串id`。写规格前已核实文件引用回退后同样是纯文本。

## 另行处理

`@` 文件候选的搜索根是 Workspace 根，而引用展开用的是 Session 的工作目录，两者在 Worktree Session 里可能不同。这是子代理从代码推断的，没有运行验证；不并入本次，单独验证。

## 留给规格的细节（D3）

讨论中没有逐条问过，规格需要给出并标明为规格补充的决定：

- 引用块的格式、记录的序列化标记与截断说明的文本。
- 压缩摘要与“保留最近的部分”同时出现时谁先被省略。
- 手写或粘贴的 `@session:<id>` 指向范围之外的会话时的结果。
- 归档会话是否可引用；被引用会话中由宿主合成的输入如何处理。
- 会话候选从哪里来，有查询时列多少个，同名标题如何区分。
- 回退与分叉返回的文本、压缩摘要请求等已对 File Reference 块做特殊处理的位置，如何对待会话引用块。
- 共用额度后超限说明的文本。
