# 06: 停止、失败与无最终回复的底栏

**What to build:** 本轮停止、失败或没有最终助手正文时，用户仍能在合理的结束位置看到可信结束时间、已知用量及完整性状态；没有正文不显示复制，停止或失败不提供分支，过程不会重复生成多个底栏。

**Spec:** [消息底栏与本轮用量规格](../spec.md)

**Spec scenarios:** AC-07、AC-08（异常结束时间）、AC-15（异常用量展示）、AC-21（异常状态布局）

**Blocked by:** 04 — 助手底栏与用量详情卡

**Status:** ready-for-agent

**Closed:** false

## Acceptance criteria

- [ ] 停止和失败的 Run 各自只有一个结束底栏；没有最终助手回复时，放在该轮已产出内容或结束状态之后，阶段回复不各挂一个底栏。
- [ ] 有助手正文时只复制可见对应正文；没有助手正文时不显示复制。停止、失败和仍在生成的回复不提供分支；无最终正文的成功结束也不产生空分支入口。
- [ ] 可信 Run 结束时间始终可见，默认本地 HH:mm，完整提示含日期与秒；只有中断恢复等状态而没有可信结束时刻时不伪造结束时间，也不将暂停、待审批或待结果确认包装成成功结束。
- [ ] 已取得的有效计数保留，必要计数未完整报告时显式标为“不完整”；详情说明存在未完整报告的请求，不将已知小计包装为精确整轮总量。
- [ ] 完全没有有效计数时仍有可识别的用量状态入口，表达未取得完整统计，不显示伪造的 0 tokens；明确实测零继续区别于未知。可选字段不支持与必要计数缺失按 01 的完整性契约判断。
- [ ] 最终移除这些场景的旧独立 token/费用行，异常底栏和详情卡同样不展示费用；保留错误、取消、审批、恢复等已有关键状态及可行动入口。
- [ ] 通过 01/04 已有契约构造可控异常结果即可独立演示，不等待 02 才能建立正确布局；02 提供真实尝试消耗后，使用同一计量事实自然显示，不另算一套异常用量。
- [ ] 用真实 App 装配验证无正文、有部分正文、阶段回复后失败、部分计数和无计数等状态，覆盖键盘、明暗主题、zh/en、窄窗口、重载和阅读位置；同步所属当前行为文档。

## 范围与衔接

本票只完成异常和缺少最终正文时的用户可见结束路径，不将领域中的 Interrupted Run 简化为普通失败，也不增加恢复、审批或副作用确认策略。完整的失败请求采集由 02 交付，07 联合验证真实异常请求到最终底栏的整条路径。

## 验证与回执

优先实际 App Browser Mode 验证状态到 UI 的外部结果，再补静默 Electron 代表性验收。异常时序用可控输入同步，不依赖固定 sleep。运行最小相关测试、类型与文档检查，记录已知统计、未知状态和未覆盖的恢复路径；在 Comments 追加证据后判断是否关闭。
