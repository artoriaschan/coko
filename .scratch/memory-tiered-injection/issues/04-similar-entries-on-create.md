# 04: 新建时返回相近条目

**What to build:** Agent 新记一条记忆时会被告知已经有相近的条目，可以更新旧的而不是再添一条重复的。存储层增加“按文本查找相近条目”的能力：把文本切成三字符片段，按与条目正文重合的片段排序，低于阈值的不算相近；工具端口相应提供这项能力，可见范围与列表、检索相同。`memory_write` 不带 `id` 时照常保存，然后在本次 Run 可见的其他条目中查找相近的，至多 3 条，在结果里列出每条的 id、作用域、来源与摘要，并提示合并进旧条目后删除新建的这条。相近的条目来源为用户时注明不能改动。系统不自动合并、替换或删除任何条目。运行时没有 FTS5 时没有相近结果，写入照常。

**规格场景:** [spec](../spec.md) 的 AC-16 至 AC-21；实现决定“新建时返回相近条目”“相近程度的判定”；Further Notes 中的“相近判定对中文的效果没有验证”；用户故事 14 至 17、25。

**文档影响:** [Memory](../../../docs/subsystems/memory.md) 的检索、工具与权限、验证各节，包括阈值的取值与依据；[@coko/session](../../../packages/session/README.md) 中记忆仓库契约的说明如有对应描述则同步。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] AC-16：已有一条“用户偏好 pnpm 而不是 npm”，模型新建一条内容相近的条目时，条目已保存，结果列出已有那条的 id、作用域、来源与摘要，并提示合并与删除。
- [ ] AC-17：没有相近的条目时，结果与现状相同。
- [ ] AC-18：相近的已有条目来源为用户时，结果列出它并注明由用户维护、不能改动。
- [ ] AC-19：带 `id` 替换时不查找，结果不列出相近条目。
- [ ] AC-20：相近的条目只存在于另一个项目的项目记忆中时，结果不列出它（对手用例）；不属于项目的 Run 只与用户级条目比较。
- [ ] AC-21：运行时没有 FTS5（包括测试用的强制降级）时，保存成功，结果不列出相近条目。
- [ ] 新建的条目自身不出现在相近结果中；至多 3 条，按相近程度排序；文本不足三个字符时没有相近结果。
- [ ] 结果中的摘要与来源取自已保存（已脱敏）的条目；工具结果的 details 与工具卡不变。
- [ ] 阈值用一组中文、英文与中英混合的样例确定：样例包含应判为相近与不应判为相近的成对文本，结论与所用样例记入 Comments，取值写入当前行为文档。对中文区分度不足的情形如实记录，不为通过用例而调低标准。
- [ ] 仓库契约测试覆盖排序、阈值、可见范围与不足三个字符的输入（内存实现与 SQLite 实现）；真实 Sidecar 用例在 FTS5 与强制降级下各跑一次。
- [ ] 按[测试约定](../../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关集与类型检查；实际执行的检查和文档影响记入 Comments。
