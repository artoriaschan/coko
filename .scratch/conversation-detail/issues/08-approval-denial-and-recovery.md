# 08: 审批、拒绝与恢复状态适配

**What to build:** 在新的详细模式中，用户始终能区分待审批、拒绝、沙箱或 Hook 阻断，以及中断后的结果待确认，并继续通过 Coko 原有入口回答、确认或继续执行。

**Spec:** [对话详情与工作步骤复刻规格](../spec.md)

**Spec scenarios:** AC-07（权限与恢复状态）、AC-13、AC-14、AC-23（授权焦点）、AC-24

**User stories:** 17、18、22、25—27、29—31

**Blocked by:** [03：详细模式与三级折叠](03-detailed-process-groups-and-folding.md)

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 消息区域中的待审批、审批决定、沙箱拒绝、Hook 阻断、无结果和 Outcome Confirmation 使用相同视觉语言并保留真实原因，不能合并成普通失败或成功。
- [ ] 整轮与组开合不隐藏关键状态和必要入口；父 Session 与子代理审批冒泡保持原有选择、路由及一次回答语义。
- [ ] 既有输入区审批卡、结果确认卡和继续入口保持原布局与操作方式；本票只适配消息区域及其衔接，不扩大为输入区重设计。
- [ ] 允许、拒绝、失效请求、暂停、中断与恢复后展示来自真实协议状态；单纯查看详情或 Inspect 不授予权限、不触发再次执行。
- [ ] 真实 Sidecar/Electron 的可控场景验证审批允许/拒绝、沙箱/Hook 拦截、子代理审批以及重启后的待确认；核对结果与执行外部事实，不能只依赖模型回复。
- [ ] 覆盖键盘回答、卡片接管及焦点恢复，保存正常与窄窗口、双主题下的关键状态对照；记录真实宿主或模型未覆盖的范围。
