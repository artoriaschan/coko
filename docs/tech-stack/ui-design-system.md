# 设计系统规格

项目级技术约定，不代表已有实现或已验证结果；适用范围与变更规则见 [专项导航](README.md)。本页规定 [界面约定](ui.md#设计系统) 中设计原则的具体档位、命名与 Tailwind 写法；交互、反馈、布局和验收仍以界面约定为准。

数值与规则参照 DeepSeek Harness 的 Web 设计系统（圆角档位、发丝线、superellipse 圆角、elevation 材质与菜单几何），由用户于 2026-10-28 确认采用，并改写为 Coko 已选的 Tailwind CSS 4 + shadcn/ui 写法。主题样式表位于 `packages/ui/src/styles/theme.css`，消费方以 `@coko/ui/styles/theme.css` 导入。

## Token 分层

主题样式表位于 `packages/ui`，是颜色、圆角、阴影、字体和动效数值的唯一来源。业务组件通过 Tailwind 工具类消费语义 token。

| 层 | 命名 | 定义位置 | 消费者 |
| --- | --- | --- | --- |
| 原始色板 | `--palette-*` | 主题样式表 | 只供语义 token 引用 |
| 语义 token | shadcn/ui 的 `--background`、`--foreground`、`--primary`、`--muted`、`--border`、`--ring` 等，加 Coko 扩展的 `--link`、`--overlay`、`--menu-fill`、`--card-fill`、`--card-stroke`、`--elevation-stroke`、正文用的 `--success-text` / `--warning-text` 与终端 ANSI 前景色 `--terminal-{red,green,yellow,blue,magenta,cyan,muted}` 等 | 主题样式表的 `:root` 与 `.dark` | 经 `@theme inline` 映射为 Tailwind 工具类 |
| Tailwind theme | `--color-*`、`--radius-*`、`--shadow-*`、`--text-ui-*` | 主题样式表的 `@theme` | 业务组件使用 `bg-background`、`rounded-md`、`shadow-panel`、`text-ui-body` 等类 |
| 组件局部变量 | `--local-*` | 所属组件 | 仅用于该组件的布局，可引用共享 token |

`@theme` 先用 `--color-*: initial` 等写法清空不使用的默认命名空间，再只登记项目 token，使 `bg-red-500` 这类默认色板类不再生成样式。[Tailwind theme 变量](https://tailwindcss.com/docs/theme)。Tailwind 对未登记的类名不报错、只是不输出样式，这类误用由 [样式守卫](#样式守卫) 发现。

修改共享 token 只在主题样式表中进行，业务包消费语义类。新增 token 档位属于共享设计规则变更，按 [界面约定](ui.md#设计系统) 的“局部修复保持局部”检查受影响组件。

## 颜色与主题

- 业务组件只使用语义颜色类。字面量颜色（`#hex`、`rgb()`、`oklch()` 等）只出现在主题样式表的原始色板中；业务组件不引用 `--palette-*`，也不写 `bg-[#…]` 这类任意颜色值。
- 明暗主题由主题样式表中 `.dark` 下的语义 token 取值解决。业务组件不写 `dark:` 变体和主题判断；shadcn/ui 组件源码引入时，把其中的 `dark:` 分支改写为语义 token。
- 文字与背景的组合在明暗两套主题下都需可读。弱化色适合装饰性表面，用于文字前在两套主题下分别核对对比度。`--success` / `--warning` 用于图标、状态点与填充；正文大小的成功与警告文字用 `--success-text` / `--warning-text`，终端输出用 `--terminal-*`，两套主题下对背景都不低于 4.5:1（Jobs tab 的浏览器测试按计算样式核对）。

## 字体与链接

- 字号与行高成对登记为 `text-ui-*`，例如 `--text-ui-body` 与 `--text-ui-body--line-height`。业务组件在已有角色匹配时选用对应档位，不为单个元素新造字号；同一页面的字号种类保持少量。行与明细的常用档位为 13px（`text-ui-body`）；完整档位为 `caption` 11/14、`small` 12/18、`body` 13/20、`body-lg` 14/22、`title` 16/24、`heading` 20/28、`display` 24/32，登记于主题样式表。
- 业务界面字重上限为 500，使用 `font-normal` 与 `font-medium`。Markdown 正文的排版字重由 `MarkdownRenderer` 管理，是唯一例外。
- 对话消息区域的详细过程使用局部语义档位 `text-ui-process`（13px/24px）及 `text-ui-code-small`（11px/16px）；字体取 `font-conversation-sans` 与 `font-conversation-mono`，对应参考项目默认的系统文字与 SF Mono 优先代码字体栈，不更改设置、侧栏或输入区字体。过程文字、输入/输出发丝线和 Inspect 使用 `--conversation-process-*`、`--conversation-detail-stroke` 与 `--conversation-inspect-*`，明暗映射及动效参数集中在主题表；共享 ToolCard 仅在显式 `row` 变体中消费这些值。
- 可点击的产物链接（Markdown 链接、文件提及、来源链接、产物文件标签）使用 `text-link` 与 `font-medium`，静止时无下划线；hover 与键盘焦点时显示点状下划线，偏移 3px。
- 代码、终端和 diff 中需要保持列对齐的内容不换行，在所属区域内横向滚动，滚动条使用共享样式。

## 图标与文本对齐

- **横向组合统一垂直居中。** 按钮、菜单项、导航与列表项、选择器、胶囊、提示及拖拽浮层中，图标与文本并排组合时必须垂直居中。前导图标、文字容器、尾部箭头和关闭图标共用同一水平中心线；多行文本以整个文字块的垂直中心与图标对齐。
- **由组合容器负责对齐。** 使用 flex / inline-flex 的 `items-center`，或 grid 的 `items-center`；图标保留所属组件规定的绘制框尺寸，禁止被挤压。SVG 使用块级显示，避免行内基线空隙；不依赖文本基线或图标字体默认排版完成居中。文字使用成对的字号与行高 token，不为凑齐位置缩放图标或随意改变字号、行高。
- **同时核对字面视觉中心。** 容器中心相等后，仍须检查实际字形，不能让文字看起来下沉或上浮。字体度量造成的偏差在共享文字容器或已登记的组件变体中统一做光学校正，同一字体、字号和控件变体复用相同规则，不逐个移动图标。现有 Noto Sans SC 13/20、H28 文字容器的下内边距 2px 校正沿用所属组件约定，不将该偏移强制套用到所有字号或字体。
- **状态切换不改变对齐。** normal、hover、pressed、selected、disabled、focus、菜单展开，以及图标替换为关闭或加载状态时，保持组合高度、中心线与文字起点稳定，不出现上下跳动。
- **验收实际渲染。** 核对图标框、文字容器的中心坐标，并检查中文、英文与数字的可见字面；不能仅以已有 `items-center` 类名或外框中心相等作为通过依据。

## 圆角

### 档位

H 指设计外框高度（含边框），R 指 `border-radius`。先按组件角色选档，再按尺寸变体选择；宽度、标签长度、偶然换行或内容增高不单独决定更大的圆角。

| 角色 | 典型尺寸与示例 | R | Tailwind 类 |
| --- | --- | --- | --- |
| 细小元素 | H20 以下；键帽、行内代码、微型控件 | 4px | `rounded-xs` |
| 紧凑控件 | H20–28；小按钮、紧凑图标按钮、紧凑菜单项 | 8px | `rounded-sm` |
| 标准控件或单行单元 | H32–40；按钮、输入框、选择器、通用导航行 | 12px | `rounded-md` |
| 侧栏分类列表项 | H32；置顶项目与会话、独立会话、项目及其会话 | 8px | `rounded-sm`；使用下文的圆弧变体 |
| 侧栏底部设置入口 | H36；左侧设置图标与“设置”文本组成的整行入口 | 8px | `rounded-sm`；使用下文的圆弧变体 |
| 输入区工具栏控件 | H32；附件按钮、权限与模型选择；发送按钮为 R28 圆形底 | 附件 8px；权限与模型胶囊 | 附件 `rounded-sm`；权限与模型 `rounded-round`；发送 `rounded-round` 圆形 |
| 输入区归属栏 | H36 容器；归属按钮 H28、设置按钮 H24 | 胶囊 / 8px | 归属按钮 `rounded-round`；设置按钮 `rounded-sm` |
| 大控件或成组内容 | 大按钮、有意设计的多行单元、嵌套表单组、代码块、diff、预览卡 | 16px | `rounded-lg` |
| 独立内容卡 | 设置卡、消息气泡、引导入口卡 | 20px | `rounded-xl` |
| 主容器面 | 输入区、对话框、主面板与浮动面板 | 28px | `rounded-panel` |

`@theme` 只登记以上六档（`--radius-*: initial` 后重新定义），沿用 shadcn/ui 的 `xs`/`sm`/`md`/`lg`/`xl` 名称并新增 `panel`。`cn()` 的 `extendTailwindMerge` 同时登记 `rounded-panel` 与下文的 `rounded-round`，以便与其他圆角类正确合并。

- 尺寸介于两档之间时，优先采用已有共享尺寸变体。更高的卡片仍是卡片，不因高度超过按钮升为 R28；普通按钮的标签换行后保留按钮变体，有意设计为多行的单元才用 R16。
- Button 的 `sm` 为 H28/R8，`default` 为 H36/R12；filled、outline、ghost、loading 和 disabled 变体保持相同尺寸与圆角。标准 H32 输入框与 H36 选择器使用 R12。固定外框尺寸使用 `box-sizing: border-box`。
- **输入区双层结构。** 主输入卡片 H120/R28 不再提供外层内边距；编辑区四周 12px、底部 8px，底部工具栏 H40、左右 12px、底部 8px，编辑区与工具栏之间不绘制分隔线。归属栏保持 H36，位于输入卡片之上；工具栏内的权限、模型胶囊与发送按钮沿用 H32 几何。
- **新对话导航的 hover 分层。** 新对话行常态透明，与插件、定时任务一致；hover 行内文字区域时整行铺 accent（含右侧搜索按钮所在区域），hover 搜索按钮时整行恢复透明、只有按钮自身铺 accent。行背景由行容器绘制，内部按钮在行 hover 时保持透明；分类标题、项目行和会话行的 hover 背景与新对话相同，统一使用 accent。
- hover、pressed、selected、focus 状态不改变圆角。
- 档位外的组件专属几何写在组件局部变量中，并在守卫例外表中逐文件、逐选择器登记，不整包豁免。由真实内边距推导的 `calc()` 几何不算新档位。

### 侧栏分类列表项

按用户于 2026-11-02 提供的桌面侧栏悬停参考，分类下的列表项使用 H32/R8 圆弧变体：截图中 64px 的行高和 16px 的圆角按 2 倍像素比例换算为 32px 与 8px。该变体复用已有 `--radius-sm`，不新增圆角档位。

- **范围与几何。** 适用于置顶分类中的项目和会话、对话分类中的会话、项目分类中的项目及展开后的所属会话。行高 32px、行间距 2px、圆角 8px，曲线使用 `corner-shape: round`。normal、hover、pressed、selected 与 focus 保持相同外框和圆角；项目内会话保留空图标位，使会话标题与父项目名称对齐；背景仍覆盖完整列表行。
- **悬停表面。** normal 为透明背景；hover 使用 `bg-accent`，移出后恢复原有背景，已有 selected 等业务状态继续保留。不添加中性描边或 elevation 阴影，不改变文字位置、行高、宽度或圆角。背景覆盖行内图标与文字所在的整个可点击表面。
- **实现归属。** 实现时由 `packages/ui` 的共享侧栏列表项变体统一设置 `rounded-sm` 和圆弧曲线，包括实际绘制表面的伪元素；业务页面消费该变体，不自行覆盖圆角曲线。hover 仍遵守下文的输入能力约束，键盘焦点和选中状态独立可见。

置顶、对话、项目三个分类的标题栏统一使用上外边距 8px、下外边距 8px；首个分类与折叠状态同样适用。标题栏整行的名称、箭头及空白区域均可点击以展开或收起，右端操作按钮与拖拽手柄不冒泡触发分类切换；名称按钮保留键盘操作与展开状态。分类容器不再额外叠加分组间距，标题栏高度、文字档位及列表行几何保持各自约定；增加的内容高度由侧栏列表滚动承接，底部设置区域保持固定。

### 分类拖拽跟随卡片

“对话”与“项目”分类按住左键拖拽时，使用跟随光标的呈现型浮层：白色 `--menu-fill`、H32/R12、左右内边距 12px、图标与名称间距 8px，六点手柄 14px / 1.1 线宽，名称使用 13/20 正文；图标与名称容器在卡片中垂直居中，名称复用 H28、下内边距 2px 的文字容器，使字面上移 1px 完成光学校正，不移动或缩放图标；轮廓与阴影沿用 `shadow-panel`。卡片固定于视口前景，默认在指针右下各偏移 12px，边缘处平移避让，设置 `pointer-events: none`，不改变原分类的点击区和拖拽捕获。卡片不包含新建、排序或展开按钮；不为置顶分类增加拖拽入口。合法插入位置使用 `ring` 色的 2px 圆端水平线，左端带直径 8px、1.5px 同色描边、白色中心的空心圆点；线与圆点垂直居中，覆盖在目标分类前后留白内，不占布局高度。指示线与圆点不可拦截鼠标，浮动卡片在其上方；窗口或滚动裁剪边缘处保留圆点的完整轮廓。按下、移动、释放与取消由同一次拖拽管理，释放、取消、丢失捕获、Escape、窗口失焦时均清理卡片、抓取光标与插入提示，取消不提交排序。

### 侧栏选项的共同对齐轴

按用户于 2026-11-03 澄清的规则，导航项、分类标题栏、项目项、独立 / 置顶 / 项目内会话项和底部设置入口共用行背景的左右边界。默认侧栏宽 280px 时，行背景左右各留 8px，行内左右内边距各 8px；各选项的首个可见元素沿距侧栏左侧 16px 的轴对齐：有前导图标时以图标槽左缘对齐，无图标的分类标题、独立对话和普通展开 / 折叠入口直接以文字左缘对齐，不预留图标空槽。

**空图标位仅用于项目展开后的会话项。** 项目行的前导图标槽为 16 × 16px，图文间距 8px；所属会话不显示图标，但保留该槽及间距，使会话标题与父项目名称从距侧栏左侧 40px 的位置对齐。项目内的空状态与展开 / 折叠入口沿同一子项文字轴；项目分类列表自己的展开 / 折叠入口仍沿 16px 主轴。图标绘制尺寸保持各自约定，在槽内居中；不为占位补充额外图标。

**空状态按所属层级对齐。** 分类展开但没有项目或没有独立对话时，显示 H32 的空状态文案（“暂无项目” / “暂无对话”），文字从 16px 主轴开始，与分类标题、独立会话的左缘一致；项目展开后没有所属对话时，空状态保留 16px 图标槽，文字与项目名称同样从 40px 开始。空状态不显示图标、不占额外高度，分类折叠时随列表一起隐藏。

分类名称后的展开箭头留在名称右侧，右侧操作组整体靠右；行尾按钮统一 24px 点击框，最右按钮的右边缘距行右侧 8px。标题栏上 / 下 8px 外间距、列表项 H32、底部设置行 H36 沿用所属规则。滚动条预留空间由容器统一处理，不能使列表行比导航项窄或改变操作列；固定侧栏与临时悬浮侧栏复用上述几何。

### 会话与项目名称的横向滚动

侧栏会话标题和项目名称复用单行横向滚动视口。未 hover 且操作按钮隐藏时，按钮不占布局空间，名称视口与右侧渐隐延伸至行右内边距；hover、焦点进入或菜单打开后显示行尾按钮，名称视口与左右渐变遮罩一起缩短至按钮组之前，图标和按钮保持固定，不随文字滚动。行外框、文字左起点和行尾按钮右对齐轴保持稳定。

按当前实际溢出范围显示 12px 渐隐：起点仅右侧，中段两侧，终点仅左侧，无溢出时不显示。名称支持触控板、滚轮、拖动和键盘横向查看；行悬停时从最左缓慢自动滚到最右后停止，离开悬停立即停止并回到最左，手动滚轮、拖动或键盘操作会接管并暂停本次悬停的自动滚动。自动滚动使用 Web Animations API 对文本层做 `translateX` 位移，手动交互直接更新偏移；按钮出现导致视口缩短时按新的终点重新计算并继续。自动滚动不误触项目展开或进入会话。项目展开、折叠及置顶区域使用相同规则；完整名称仍可在详情卡片中折行读取。

### 侧栏空状态

分类已展开且对应列表为空时，项目分类显示“暂无项目”，对话分类显示“暂无对话”；两者不显示图标或图标占位，文字直接沿主内容左轴（侧栏左侧 16px）对齐。项目已展开且内部无会话时显示“暂无对话”，左侧保留 16px 空图标槽与 8px 图文间距，文字沿子项左轴（侧栏左侧 40px）与父项目名称对齐。行高统一 32px，文字沿用 `text-ui-body` 13px/20px、normal 字重及 `muted-foreground`，背景透明，垂直居中；不增加按钮、插画、hover 背景或点击行为。分类 / 项目折叠时隐藏所属空状态，创建首条对应数据后替换为空间内的正常列表；空列表不显示“展开”“折叠”数量控制。

### 新对话导航与搜索

### 曲线、圆形与胶囊

主题样式表默认对所有元素及其 `::before`、`::after` 设置 `corner-shape: superellipse(1.5)`；该属性不继承，所以伪元素需要显式覆盖。Electron 41 的 Chromium 支持该属性（Chromium 139 起提供）。上文的侧栏分类列表项和底部设置入口使用共享的圆弧变体，圆形与胶囊按下文规则处理；其余组件不另行设置平滑曲线，使填充与轮廓的弧线一致。[MDN 兼容数据](https://github.com/mdn/browser-compat-data/blob/main/css/properties/corner-shape.json)

圆形头像、状态点、显式胶囊和全圆轨道使用主题提供的 `rounded-round` 工具类，它同时输出全圆半径与 `corner-shape: round`，保持圆弧；业务组件不单独使用 `rounded-full` 或 `rounded-[50%]`。小按钮不因高度小而改为胶囊。头像容器及其中的图片都保持圆形，宽高相等。

贴边停靠的表面与相邻单元在共享边上可为 R0。与卡片平齐的标题、页脚或图片只圆化外露的角，内部接缝保持直角。

### 嵌套与 hover

修改子元素圆角前，先区分三种布局：

| 布局 | 规则 | 示例 |
| --- | --- | --- |
| 同心内嵌 | 内 R = max(0, 外 R − 内边距)；两条弧同心 | 外 R16、内边距 4px、内 R12 |
| 填充贴着外容器边缘 | 外容器负责可见圆角，用 `overflow-hidden` 裁剪，子元素用直角或继承匹配的角 | 分体按钮卡片中两个独立的 hover 区域 |
| 另一表面内的独立卡片或表单组 | 选子元素自身的语义档位，不机械减去父级内边距 | R20 设置卡中的 R16 编辑区 |

| 组件 | 外框 | 内边距 | 项与指示器 |
| --- | --- | --- | --- |
| 标准菜单（DropdownMenu、ContextMenu、Select、Command） | R16 | 4px | R12 |
| 紧凑菜单 | R12 | 4px | R8 |
| 分段控件（ToggleGroup 等） | R12 | 4px | R8 |
| 分段标签（Tabs） | R16 | 4px | R12 |

调整内边距时同步检查指示器偏移、宽度计算、子菜单对齐与指针桥接区域。圆角相减是嵌套 superellipse 的名义尺寸规则，对角方向的间隙可能与边上的内边距不同；需要严格等距时改用 `rounded-round` 的圆弧。

单个可点击表面在自身上绘制 hover。贴边的伪元素或覆盖层使用与可见外轮廓相同的圆角和曲线，避免背景与边框之间出现月牙形缝隙。分体卡片把圆角和裁剪放在外层，内部按钮用直角，各自的 hover 色由外层裁剪成同一轮廓；下拉菜单通过 portal 留在被裁剪的子树之外，键盘焦点环保持可见。

## 材质、边框与浮层

- **抬升表面用阴影，不用边框。** 菜单、Popover、HoverCard、对话框、浮动面板、浮动按钮和输入区使用 `border-0`，配合 `shadow-panel`、`shadow-prominent`，输入区使用模糊更大、透明度更低的 `shadow-soft`。这些阴影的第一层是 0.5px 发丝描边，颜色取 `--elevation-stroke`，可按表面或状态重新绑定或取消。中性边框与 elevation 阴影不叠加；shadcn/ui 中 `border` 配 `shadow-md`/`shadow-lg` 的浮层组件引入时按此改写。
- **平面中性线统一为 0.5px。** 按钮、输入框、卡片、行分隔线，以及以填充块绘制的分隔线（菜单分隔线、标题栏接缝、Markdown `hr`、竖向分隔）使用主题登记的 0.5px 发丝线宽（`--hairline`；工具类 `border-hairline`、`border-{t,b,l,r}-hairline`、`h-hairline`、`w-hairline`），在 Retina 屏上绘制为一个设备像素。Tailwind 默认的 `border` 为 1px，中性线不使用。虚线提示与警告、错误等状态色边框保持 1px；加载圈的轨道宽度作为显式例外登记。
- **设置卡材质。** 设置类卡片使用 `rounded-xl`、0.5px 的 `--card-stroke` 描边与 `--card-fill` 背景；selected、warning、error 和 expanded 状态改用已有语义色并保持几何。卡内的嵌套编辑区使用 R16。普通平面卡片不为区分标签页而加阴影。
- **侧栏磨砂玻璃。** 桌面工作台左侧栏复用 deepseek-harness 的 macOS 侧栏材质：顶部蓝色 `rgb(122 155 240)` 10% 向 35% 高度淡出，底部紫灰 `rgb(143 137 184)` 从 68% 高度透明渐入到 9%；底色先将 `--sidebar` 与蓝色按 97% / 3% 混合，再保留 40% 不透明度。暗色主题顶部 / 底部为 8% / 7%，底色取 `--sidebar` 50% 不透明度，不混蓝色。数值维护在主题的 `--sidebar-glass-background`，配套色与浏览器滤镜由 `--sidebar-glass-blue`、`--sidebar-glass-violet`、`--sidebar-glass-backdrop-filter` 维护。原生 macOS 使用透明窗口背景、`vibrancy: sidebar`、`visualEffectState: active`；高斯模糊由系统材质提供，不把它声明为固定 CSS 半径。HTML 原型与画布使用 40px 背景高斯模糊，浏览器再加 150% 饱和度作近似；不得模糊文字、图标与列表本身。窗口与侧栏内部背景保持透明链路，右侧内容区单独绘制不透明底色；分隔线绘制在不透明内容侧。侧栏玻璃背景放在独立伪元素上，浮层继续通过 portal 使用既定菜单材质。浏览器不支持背景模糊或请求减少透明度时恢复 `--sidebar` 实底；原生减少透明度跟随系统材质并采用 90% 侧栏填充。参考实现为 deepseek-harness 的 `packages/client/ui-layout/src/client/AppFrame.module.css`、`packages/client/ui-sidebar/src/client/SidebarRoot.module.css` 与 `apps/desktop/src/main.ts`。共享实现为主题工具类 `.sidebar-glass`：宿主列建立 `isolate` 与透明背景，玻璃层落在 `::before`，macOS 原生材质下关闭 CSS 滤镜。
- **侧栏收缩浮层。** 侧栏收起时整列隐藏，不留 rail；主内容左上角显示宽 216px、高 48px 的控制条，依次是展开、后退、前进和新对话四个 28px 按钮，首键从窗口左侧安全区 + 12px 开始，标题栏从 216px 处开始排版。悬停展开按钮 200ms 后浮出侧栏卡片；卡片宽为当前侧栏宽度（默认 280）、R28、`--popover` 与 `shadow-prominent`，覆盖在主内容左侧，指针离开按钮与卡片 180ms 后关闭，Escape 关闭并把焦点还给展开按钮。浮层只响应指针悬停，键盘用户点击展开按钮在宽窗口固定展开、在窄窗口打开抽屉；浮层与主内容之间不绘制额外边框。
- **权限风险确认。** 选择完全访问权限时使用宽 560px 的确认对话框，标题行 20px 警示图标与 20px/28px 标题，正文后接 `--accent` 底、R16 的能力列表：每行至少 56px、内边距 10px/16px，行间 0.5px 分隔线，图标 20px（文件与网络用 link 色，终端用前景色），标题 500 字重、说明 12px/18px muted；底部右对齐“取消”与“仍要开启”，确认按钮使用 warning 色浅底并带 14px 警示图标。
- **启动加载屏。** 工作台渲染前使用品牌加载屏：覆盖整个窗口、背景 `--background`、R28 裁剪，顶部 48px 为窗口拖拽带，正文居中展示 250px 宽（窄窗口取 `calc(100% - 64px)`）的 1:1 圆形品牌角色；使用 `role="status"`、`aria-busy`。加载屏不绘制模拟的红绿灯。设置进入 `ready` 或 `error` 后先应用保存的语言和主题，再切换到工作台；连接失败或超时同样进入工作台展示错误。
- **侧栏分类列表。** 分类分组之间留 16px，标题行与列表项同为 H32、左右内边距 8px，标题使用 13px/20px 中等字重；列表项之间 2px，项目内会话保留空图标位并与父项目名称对齐，hover 背景覆盖整行。分类标题右侧的拖拽手柄与新建 / 排序入口只在标题行 hover 或焦点内出现，展开时标题后的箭头同样随 hover 出现，折叠时向右箭头常驻。
- **菜单材质。** 下拉、右键、子菜单和选择菜单都通过共享的 Menu 组件渲染，或用共享的菜单表面包裹自定义内容。背景取 `--menu-fill`，亮色主题统一映射为不透明白色；模糊取主题的菜单 backdrop-filter。业务与平台样式不覆盖这两项，也不重新定义它们。backdrop-filter 放在独立的伪元素层上，因为直接加在菜单元素上会使其成为 fixed 定位后代的包含块，嵌套菜单与固定覆盖层会错位。
- **二级菜单叠加。** 上一级菜单保持打开时，所有二级菜单必须以更高的共享浮层层级叠加在上一级菜单前方，并与父菜单表面产生几何重叠。父菜单保留打开状态、选择状态及可识别的上下文；子菜单覆盖相交区域，并沿用共享菜单材质与阴影。通过 portal 和共享层级管理避免父容器裁剪或遮挡子菜单；窗口边缘避让时保持父子关系和必要操作可达。关闭子菜单时先退出当前层并将焦点返回父菜单触发项，父菜单继续显示。分支选择菜单遵循此规则。
- **模态遮罩。** 对话框遮罩使用 `bg-overlay`（统一半透明暗色），不模糊、不滤镜父页面；替换 shadcn/ui 默认的 `bg-black/50`。
- **滚动条与焦点。** 滚动条按[全局滚动条](#全局滚动条)统一为 4px / R2，只由主题样式表管理，组件不写自己的 `::-webkit-scrollbar` 选择器；滚动条与容器边缘保留小间距，不越界、不被圆角裁断。内容会从不满一屏变为溢出的主体滚动容器（会话消息、侧栏列表、设置详情、工作台页和右侧面板列表）带 `data-scroll-stable` 钩子，由主题统一预留滚动条槽位（`scrollbar-gutter: stable`），避免滚动条出现时内容宽度变化引起重排；短内容的菜单、输入框和卡片不使用该钩子，避免常驻留白。焦点环使用 `ring` token 和共享的 `focus-visible` 样式，不被 `overflow-hidden` 的外层裁掉。菜单在指针点选关闭后仍把焦点归还触发器，但不显示焦点环；键盘关闭保留焦点环。

## 全局滚动条

用户于 2026-11-03 确认采用参考图中的细圆角滚动条。所有显示滚动条的滚动容器统一由 `packages/ui/src/styles/theme.css` 管理，包含侧栏、菜单与浮层、设置、对话、编辑区、代码和 diff，不在业务组件另设样式。

- **几何。** 纵向滑块宽 4 CSS px，横向滑块高 4 CSS px；两端使用 R2 的圆弧（`corner-shape: round`），hover、pressed 与拖动不加粗。轨道、交角透明，无方向箭头、边框与阴影。滑块长度由可视区与内容比例决定；轨道两端保留 2px 间距，不顶住容器端部。无溢出时不为此规则额外显示滚动条。
- **颜色。** 普通 / hover / active 使用 `--scrollbar-thumb`、`--scrollbar-thumb-hover`、`--scrollbar-thumb-active`。浅色主题分别为黑色 8% / 16% / 24%，深色主题为白色 12% / 16% / 20%；仅改变颜色，不改变几何。hover 样式遵循输入能力查询。
- **实现。** 4px 尺寸、R2 与端部间距由 `--scrollbar-size`、`--scrollbar-radius`、`--scrollbar-end-gap` 维护。Electron / Chromium 使用共享 `::-webkit-scrollbar` 系列伪元素，并将标准 `scrollbar-width` 与 `scrollbar-color` 设为 auto，以免它们接管精确几何；不支持该伪元素的引擎沿用 thin 回退。macOS 的覆盖式滚动条可以不占布局宽度，不能把轨道占位当成滑块宽度。
- **交互。** 保留滚轮、触控板、拖动及键盘滚动；不因统一样式拦截滚动事件。既有 `fading-title` 明确隐藏横向滚动条，仍按原约定用渐隐提示可滚动，不额外占用会话行高。

### 项目与会话详情卡片

项目详情 HoverCard 基准宽 320px，会话详情 HoverCard 基准宽 280px；空间受限时按共享浮层的窗口避让规则缩小，高度由内容决定，超出可用窗口高度时在浮层内部纵向滚动。两种卡片均沿用白色 `menu-fill`、R16、共享 panel elevation，不叠加额外中性边框。

标题统一 `text-ui-body` 13px/20px、500 字重；完整标题、项目源文件夹地址及会话归属允许自然换行，连续长文本也需在可用宽度内折行，不使用省略号、单行裁剪或行数限制。会话相对时间使用 12px/20px 次级样式，保留在标题右上侧；项目标题的文件夹与置顶操作、路径行图标与多行文字按共享居中规则对齐。详情只由悬停触发，键盘焦点或点击行尾操作都不打开卡片。每次悬停只展示一次详情，指针在行与卡片之间移动不重复弹出，离开行与卡片后再次悬停才重新展示。卡片与对应行顶部对齐、水平间距 2px，窗口边缘沿用共享避让。

## 应用启动加载

启动首屏使用共享 `background` 实底及 R28 应用窗口外轮廓，顶部只保留 macOS 三色窗口按钮，位置和尺寸与工作台一致；不展示侧栏、导航、输入框或内容区。在窗口整体水平和垂直中心展示应用现有 `brand/rukie-avatar.png` 角色图，基准 250 × 250px、圆形裁剪（`rounded-round`），保持比例，窄窗口按可用宽度缩小。启动图直接使用角色原图，不叠加欢迎页的底部渐隐层或渐变蒙版。沿用参考图的简洁构图，不增加加载文字、额外图标或虚构进度。

启动加载是应用级状态：工作台初始化和必要资源就绪后退出，真实产品不为展示启动页添加固定等待。页面为辅助技术提供“应用正在启动”状态，加载期间工作台控件不可聚焦或操作；完成后恢复正常工作台。交互原型仅用 1.2 秒模拟加载，并提供原型控制区的“预览启动 / 进入工作台”，这些控件不属于产品启动界面。

## 状态与输入能力

- Tailwind CSS 4 的 `hover:` 变体只在 `(hover: hover)` 下生效，组件直接使用 `hover:`，不改写该变体。[Tailwind v4 升级说明](https://tailwindcss.com/docs/upgrade-guide)。手写 CSS 中的 `:hover` 放进 `@media (hover: hover)`，与视口宽度无关。
- selected、expanded、pressed 状态使用 `data-[state=…]:`、`aria-selected:`、`aria-expanded:`、`aria-pressed:` 等变体，键盘焦点使用 `focus-visible:`，都不放在 hover 条件内。
- 依赖指针精度的表现使用 `pointer-coarse:`：粗指针下文本输入框字号不低于 16px，精细指针保持紧凑尺寸。
- JS 悬停预览在 `(any-hover: hover)` 下接受鼠标进入，忽略 `pointerType === "touch"` 的事件。
- 动效时长与缓动使用主题登记的值，并提供 `motion-reduce:` 下的替代或关闭。
- **可点击文案不可选中。** 按钮与菜单选项属于界面文案：主题统一为 `button`、`[role=button]` 和菜单选项（含 listbox `option`）设置 `user-select: none`，菜单表面整块沿用该规则，避免点击、双击时选中文案；按钮内以 `data-user-content` 标记的用户内容保持可选择。共享 Button 的基础类同样带 `select-none`，覆盖 `asChild` 渲染的非 `<button>` 元素。

## 样式守卫

对话消息的局部 Markdown 代码栏使用 `--conversation-code-banner`（亮色 `gray-50`、暗色 `gray-800`），保留共享 Markdown 的其他消费者。`messages.css` 中 `backdrop-filter: none` 是精确登记的例外：它关闭 Streamdown 行内代码工具栏自带的浮层模糊，使其落在代码标题栏中；该区域不是菜单，不改变菜单背景或共享菜单材质。思考标识使用参考版本的 16px think artwork、1px regular 线宽，限于对话详情复刻区域；原有 Coko 回退、分叉等动作继续使用现有图标库。

已接入：`packages/ui/src/guards/style-guard.ts` 以 Vitest 静态检查 `packages/ui/src` 与 `apps/desktop/src/renderer` 中的 CSS 文件和 TSX（测试文件除外；TSX 经 TypeScript 语法树解析，忽略注释）。例外按文件、规则与匹配文本登记在同目录的 `style-guard-exceptions.ts`，失效的例外同样使测试失败；修改例外需在评审中说明原因。

| 守卫 | 拒绝的写法 |
| --- | --- |
| 颜色 | 主题样式表以外的字面量颜色、`--palette-*` 引用、任意颜色值、业务组件中的 `dark:` 变体 |
| 圆角 | 六档以外的 `rounded-*`、任意圆角值、未登记的 `--radius-*`、组件 CSS 中 4–99px 的字面圆角 |
| 圆角曲线 | 未使用 `rounded-round` 的全圆写法（`rounded-full`、50%、999px） |
| 材质与边框 | 中性边框与 elevation 阴影叠加；宽于 0.5px 的中性实线（虚线、状态色边框与登记的加载圈轨道除外） |
| 菜单 | 未经共享 Menu 或菜单表面渲染的菜单与 listbox；覆盖菜单背景或模糊；重新定义菜单 token |
| 状态 | 不在 `@media (hover: hover)` 内的手写 `:hover` |
| 滚动条与拖拽区 | 组件自定义滚动条选择器；交互控件落入窗口拖拽区 |
| 文案 | 未经 zh/en 字典的产品文案 |

按 [测试约定](testing.md#测试用例生成与维护)，每个守卫接入时先临时引入违规样例，确认因预期原因失败，再撤销样例。守卫只能拒绝档位外数值和未知 token，不能判断合法 token 是否适合该组件或两个轮廓是否真正对齐；这两点按 [界面约定](ui.md#ui-状态与验收) 在真实渲染中检查。
