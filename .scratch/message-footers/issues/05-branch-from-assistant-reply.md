# 05: 从助手回复创建新对话分支

**What to build:** 用户可以从任意成功完成的助手最终回复创建新 Session，保留截至该回复的有效上下文，自动打开且输入为空；原对话、草稿与文件保持原样，继续使用当前工作目录。

**Spec:** [消息底栏与本轮用量规格](../spec.md)

**Spec scenarios:** AC-04、AC-05、AC-06、AC-18（分支用量归属）、AC-21（分支操作）

**Blocked by:** 04 — 助手底栏与用量详情卡

**Status:** ready-for-agent

**Closed:** false

## Acceptance criteria

- [ ] 实施前补齐助手包含边界的功能设计，说明请求契约、来源、有效历史、压缩及旧用户锚点调用兼容；按领域流程同步 Fork 术语，对已实施的长期决定记录明确后继关系，保留 append-only 和既有回退约束。
- [ ] 在助手底栏的复制与用量之间提供“在新对话中分支”icon 操作；最新及非最新历史的成功最终回复均可使用，不照搬参考产品只允许最新回复分支的限制。
- [ ] 新 Session 的模型上下文保留直到所选助手回复的有效用户输入、助手内容、思考及配对的工具调用和结果，排除后续内容；含压缩历史时保留当时有效摘要与保留区间，不借用边界之后生成的摘要泄露后续上下文，也不伪造已不存在的原文。
- [ ] 分支成功后自动打开新 Session，输入框为空，不把目标用户文本或助手回答当作新草稿；源 Session 的记录、当前草稿和源文件逐字节不变。
- [ ] 沿用源 Session 的项目归属、模型及必要配置，使用相同的实际工作目录；源绑定 Worktree 时不跳回项目默认目录，不复制目录、不恢复历史文件、不自动创建 Worktree。
- [ ] 来源可追溯，复制历史的计量仍属于源 Session，不计作新 Session 新增用量；新 Session 发出的下一请求实际包含保留上下文，新发生的用量正常计入。
- [ ] 停止、失败、流式回复和阶段回复不提供此分支能力；运行中、待审批、待结果确认及只读等原有限制仍生效，服务端同样校验资格，不能只靠隐藏按钮防止绕过。
- [ ] 分支失败不假报成功或清空源草稿，用户能看到错误；旧用户锚点调用保持原有语义，不因新助手入口静默改变。
- [ ] 真实 Sidecar 集成检查新分支下一次模型请求上下文、压缩边界、源文件及用量归属，实际 App/Electron 检查新 Session 自动打开、空输入及键盘入口；更新旧入口断言与所属当前行为文档。

## 范围与衔接

本票是在 04 已有底栏上交付完整的分支行为，不单独发布后端或占位按钮。它复用 01 的归属规则，01 已通过 04 成为传递前置，不新增对 02 的人为依赖。源 Session 和 Workspace 共享当前文件的事实不能被表达为历史代码副本。

## 验证与回执

通过真实 Sidecar、真实持久化和下一次模型请求验证上下文，不以界面复制出了相同文字或助手回答声称记得历史为证据。界面操作补实际 App 浏览器及静默 Electron 验证。运行最小相关测试、类型与文档检查，记录旧契约回归、长期文档后继关系和限制；在 Comments 追加结果后再判断是否关闭。
