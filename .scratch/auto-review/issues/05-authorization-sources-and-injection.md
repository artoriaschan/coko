# 05: 授权来源与抗注入

**What to build:** Reviewer 判断“这个动作是否在用户授权范围内”时，只把用户亲自输入的消息、当前 Goal 的目标与 Success Criterion、已批准的 Plan 当作授权；模型自己写的内容只作为“助手委派的任务”供参考；工具结果与助手正文完全不给它。输入有上限，待审调用过长时不发请求而直接问用户。审查不成为 Secret 的新泄露通道。

**User stories:** 42–47。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 审查输入分为用户授权、助手委派的任务、动作三个分区，标注与数据边界取自设计稿
- [ ] 用户授权分区包含有效模型上下文中用户亲自输入的消息文本，不含宿主附加的块（State Update、Hook 追加的上下文）
- [ ] 存在 Goal 时，用户授权分区包含它的目标与 Success Criterion
- [ ] 存在已批准且仍适用的 Plan 时，用户授权分区包含它（适用范围按规格 Further Notes 中与计划生命周期的关系）
- [ ] 压缩摘要、定时任务的提示词、Goal Round 中宿主合成的继续提示归入助手委派的任务，标注为不构成授权
- [ ] 动作分区包含本 Run 已发生的工具调用的名字与参数，以及待审的调用；待审的是 MCP 工具时附带它的描述
- [ ] 审查输入不含工具结果、助手正文与思考、图片内容
- [ ] 输入超过上限时从最早的内容开始丢弃并标注
- [ ] 待审调用自身的参数无法完整放入时不发审查请求，出现带“内容过长”代码的待审批请求
- [ ] 审查请求的输入与请求快照经与其他模型请求相同的按值脱敏
- [ ] 集成测试：先前工具结果中的标记文本与助手正文中的标记文本不出现在审查请求里；用户消息与待审命令出现在各自的分区
- [ ] 集成测试：Goal 的目标、已批准的 Plan 出现在用户授权分区；压缩后的摘要、定时任务提示词、Goal Round 的继续提示出现在委派分区
- [ ] 对手用例：待审命令的参数与先前工具调用的参数中含伪造的放行指令时，这些文本只出现在数据边界之内，系统提示逐字不变
- [ ] 对手用例：用户消息中伪造的宿主块标签不被当作宿主附加的块而丢弃或升格
- [ ] Secret 的集成测试沿用现有 secrets gate 的通道写法，覆盖审查请求、保存的理由与请求快照
