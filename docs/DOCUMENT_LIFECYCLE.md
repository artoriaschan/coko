# 文档生命周期与会话入口

适用于人工和 Agent 维护的项目文档。文档变更完成意味着正文、入站引用、导航及任务入口同时一致。只改正文而留下误导入口，不能报告维护完成。文档类型与所属位置见 [文档体系](DOCUMENTATION_SYSTEM.md)；本页只维护状态与同步方法。

## 新会话如何找到有效资料

1. 从根 AGENTS 的入口读取 [文档导航](README.md)，进入所属正式规范或模块索引；具体任务由用户引用或 [tracker 规则](agents/issue-tracker.md) 定位。正式导航不链接工作区材料，引用方向遵循 [文档体系](DOCUMENTATION_SYSTEM.md#正式文档与任务材料的引用方向)。
2. 打开相关正文，检查文档职责、生命周期、适用范围和该类型的业务状态。按 [归属边界](DOCUMENTATION_SYSTEM.md#需求已选型与实现的边界) 区分需求、已选技术和实现说明：active 设计仍可能是 draft，已选技术与 accepted ADR 仍可能未实现；当前行为需有实现证据。
3. 遇到 deprecated 页面，先读页首的替代或退出说明，再进入后继文档；遇到 archived 页面只将其作为历史证据。若后继仍已弃用，继续追到有效目标；分拆后按任务范围选择相关目标。
4. 直接从用户给出的旧链接或搜索结果进入，也执行相同状态检查。文件名、搜索排名和修改时间都不能证明内容有效。
5. 缺失目标、替代循环、两个相互矛盾的当前正文或无说明的弃用页面，视为文档缺陷。能从授权范围和证据确定的差异直接修正；无法确定的语义明确报告，不自行选一个当作事实。

旧文档没有 lifecycle 字段时，不自动认定为已归档或已验证。结合所在入口、类型状态及源码/确认依据判断；实际维护时再补字段。每次重新进入任务或发生相关变更后读回入口与正文，不以旧会话摘要替代现有文件。

## 状态和元数据

`lifecycle` 表达文档是否仍作为维护入口，与规格/ADR 的 `status` 和 ADR 的 `implementation` 分开。

| lifecycle | 含义 | 可否作为当前依据 |
| --- | --- | --- |
| active | 仍在维护且有读者用途 | 按文档类型、批准状态和证据范围使用 |
| deprecated | 已退出当前正文的位置，等待消费者迁移或保留兼容入口 | 仅用于迁移与追溯；采用页首说明中的后继 |
| archived | 已封存，只保留历史价值 | 仅作历史证据，正文冻结 |

新建的维护正文写 `lifecycle: active`。弃用时写 `lifecycle: deprecated` 和 `deprecated-at: YYYY-MM-DD`；归档时写 `lifecycle: archived` 和 `archived-at: YYYY-MM-DD`。日期只记状态事件，不维护每次编辑都刷新的日期。

弃用和归档页面在标题后、历史正文前增加“文档状态”说明：状态、适用的旧范围、退出原因、后继的 Markdown 链接；无后继时明确能力已移除或方案已放弃，并链接依据。后继文档在相关设计/来源处反向链接前身。分拆、合并可以有多个链接，逐个说明覆盖范围；不再维护另一份 YAML 路径表。

规格/design 被替代时同时设置 `status: superseded`；ADR 被替代时沿用其 status 和 implementation 规则，并同步 lifecycle。未采用的提案先标 rejected/withdrawn，生命周期可为 deprecated，但不能直接归档暗示曾经实施。仍解释当前约束的 ADR 保持 active。

切换当前入口以新正文对相应范围生效为条件：新草案不能仅因更新就替换已批准规格，新目标设计不能替换仍符合实际实现的当前说明。过渡期分别标注“当前行为”和“目标方案”。原正文已经失真但后继尚无充分证据时，明确标出失效范围和待核实项，不继续把旧说法作为有效事实，也不把新猜测晋升为事实。

文档弃用不等于 API 弃用。旧版本接口仍受支持时，其适用版本说明仍是 active；只有被取代或退出维护的页面才 deprecated。

## 一次更新的完整步骤

1. **确定正文与影响范围。** 列出变更的事实、证据、所属文件及旧路径/标题/锚点。一般内容修订保持稳定路径；拆分、合并或改变决定时再创建后继。需要新增类别或职责目录时，先更新文档体系的归属与目录图；纯拆分保留每项选择的确认状态、适用范围及候选标记。
2. **查找消费者。** 检查根和子目录 AGENTS、CLAUDE 的实际目标、docs/README、所属目录 README、已有 docs/agents 配置、相关规格/设计/票/研究以及项目 skills。搜索旧路径、文件名、标题、锚点和关键结论，包含 `.scratch` 等隐藏目录；不能仅依靠 Git 默认可见文件或 Markdown 链接解析。
3. **更新正文及状态。** 原地修订有效事实；弃用或归档按下节操作。改章节标题时核对锚点；改变含义时检查引用它的摘要、示例、任务前提与验收，不能只替换 URL。
4. **同步入口。** 先更新最近的目录索引，再核对上层导航、AGENTS 触发入口和受影响的任务入口。入口只记录用途与链接；已有简短摘要被正文推翻时同步重写。全局共享 skills 不作项目索引，项目约定由项目入口传入。
5. **核查活动任务。** 尚未完成的票改为引用有效正文，记录范围/阻塞/验收变化；已经完成的票、历史证据与已交付规格不改写当时结论，必要时追加更正或后继提示。实际操作仍遵守任务 tracker 的授权与状态规则。
6. **从入口重新读取。** 以无旧上下文的新会话视角，从 AGENTS → 导航 → 所属正文验证路径、状态和适用范围；从旧链接进入也应能辨认旧状态及下一步。完成下列检查后记录维护回执。

这些修改属于同一交付批次：有 Git 时尽量同一提交/PR；无 Git 时完成全部文件后读回核对。中途被打断时，在所属任务的证据或交接记录列出未同步项；未完成同步不能标记文档维护完成。无所属任务时在最终回复明确未完成文件和缺口。

## 弃用、移动与归档

| 操作 | 正文动作 | 引用及入口动作 |
| --- | --- | --- |
| 原地更新 | 保持路径，修正事实、示例和证据 | 核对摘要与锚点；仍准确的入口不作无意义改动 |
| 移动或重命名 | 先建立新正文，原位置留短跳转页，标记 deprecated | 活动引用直接改到新正文，跳转页用于旧链接兼容 |
| 拆分或合并 | 每项事实明确唯一新归属；旧页给出按范围区分的后继链接。保留实质正文的总览继续 active；纯旧入口才 deprecated | 活动引用指向具体正文/章节，相关目录入口和文档体系目录图同步调整 |
| 决定改变 | 新建后继 ADR，旧 ADR 保留原理由并标 superseded/deprecated | 当前设计和活动票采用新决定；历史引用保留当时语义 |
| 无后继地退出 | 页首说明停止使用原因、影响和依据 | 移出当前推荐入口；有必要保留的历史链接显式标“历史”或“已弃用” |
| 归档 | 原路径封存，先完成状态说明和 archived-at，再冻结正文 | 从当前推荐区移除；确需检索时由所属索引的“历史资料”区链接 |

归档前必须满足：工作已结束、仍有效的事实已移交给当前正文、活动消费者已迁移或明确仅作历史引用、后继/退出说明可追溯。对于 ADR，另须实现已完成且不再承担当前约束。年龄、篇幅或目录数量都不是归档理由。

归档默认保留原路径，避免再次移动破坏历史引用。冻结后不修订其历史正文与出站链接；发现错误时建立独立更正/后继记录，由所属历史索引提示。历史链接失效记录为已知限制，不能当作有效执行入口。产品当前入口不得以无历史标注的方式指向归档页。

跳转页本身不复制事实，只说明新位置、范围和迁移原因；已有多级跳转在维护时压缩到最终有效目标。删除跳转页或无长期价值文档前检查入站引用及唯一证据；外部引用无法查全时保留短入口。不得删除未完成工作或唯一历史证据。

## 索引的职责

- `docs/README.md` 是文档总入口，区分当前规范、规划材料和必要历史入口；不维护全量任务状态或所有子文档摘要。
- 各目录 README 负责本目录直接内容。新增正式文档必须从所属正式索引可达，任务材料从 tracker 入口可达；新建正式目录索引后，上层补链接。
- `.scratch/<feature>/map.md` 或所属 spec/票承担该功能的继续工作入口；文档替代影响任务前提时更新链接和说明，决策历史保留原意。
- AGENTS 只维护读取触发条件和入口。当前文档失效时修复其实际链接目标，不往 AGENTS 复制整份新结论。
- 仅在有归档内容时增加“历史资料”区或独立历史索引。历史条目说明适用范围、归档原因及后继，不能与当前推荐正文混排。

## 完成检查与回执

| 检查 | 通过条件 |
| --- | --- |
| 路径与引用 | 活动文档的本地链接、锚点存在；旧路径搜索结果均已迁移或有兼容/历史理由 |
| 语义同步 | 摘要、示例、任务前提与新正文一致；仅移动文件时不改变原结论 |
| 归属与权威 | 新目录已在文档体系登记；已选型未降格为需求提案、草案未晋升为已确认规范，技术约定未冒充实现事实 |
| 引用方向 | `.scratch/` 外不存在指向其具体材料的链接或读取依赖；必要的长期结论和证据已提炼，路径模式仅用于操作说明 |
| 生命周期 | 弃用/归档有原因和后继或退出说明；替代链无环，末端用途明确 |
| 当前入口 | 正式正文从正式导航可达，任务材料从 tracker 可达；历史引用有显式标注；不存在两个相互冲突的有效正文 |
| 新会话读入 | 从入口独立读回可判断有效范围、批准/实施状态及未决项，不依赖聊天记忆 |
| 历史保留 | 已归档正文保持冻结；活动义务和唯一证据均有归属 |

在所属任务证据中记录“正文变化 → 受影响引用/入口 → 已完成动作 → 检查结果及缺口”，使用 [证据模板](templates/evidence.md)。纯文档小改动可直接在交付回复给回执，无须额外建日志。路径与引用、引用方向、当前入口可达及弃用/归档元数据由本地 `pnpm run check:docs` 检查；语义同步、替代链、归档冻结仍由 Agent 执行和评审核对。检查尚未接入 CI，不能表述为合并前的强制保障。
