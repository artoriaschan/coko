# 08: 乐观加载

**What to build:** 模型直接调用目录中尚未加载的工具时，这次调用失败，结果提示“已加载，请直接重试”，并写入来源为乐观加载的加载记录；从下一次请求起该工具可用，再次调用成功。名称不在目录中时，照常返回原有的未找到错误，不加载任何工具。工具结果已提交、加载记录尚未写入时崩溃，恢复后没有这次加载；模型再直接调用时由乐观加载补上，恢复过程不重跑业务工具。

**规格场景:** [spec](../spec.md) 的 AC-12；对应 TS-17。

**设计依据:** [design.md](../design.md) 第 5 节“加载”与第 6 节“失败”；第 6 节“实施时需确认”的第 3 项在本票处理。

**文档影响:** [MCP](../../../docs/subsystems/mcp.md) 补充乐观加载的行为。

**Blocked by:** 03 按需加载最小闭环：目录、按确切名称加载与加载记录

**Status:** ready-for-agent

- [ ] AC-12：目录中有未加载的工具 C，模型直接调用 C，结果为“已加载，请直接重试”，下一次请求包含 C，再次调用成功；直接调用一个不在目录中的名称，返回原有的未找到错误，不写加载记录。
- [ ] 乐观加载与 `tool_search` 的加载使用同一种条目，来源标为乐观加载，在对应工具结果提交后写入；写入失败时 Run 以 commit_failed 停止。
- [ ] 核实在提交前改写结果文字是否可行。不可行时不要自行换做法：设计稿给出的替代做法是在下一轮衔接时补一条宿主提示，它与 AC-12 的写法不同，需先经用户确认。
- [ ] 工具结果已提交、加载记录未写入时中断 Sidecar：恢复后没有这次加载；再直接调用时由乐观加载补上；恢复不重跑业务工具。
- [ ] 场景经真实 Sidecar（faux 脚本）验证；模型可见文本的变化同步到会话回放或快照。
- [ ] 按[测试约定](../../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关集与类型检查；实际执行的检查和文档影响记入 Comments。
