# 对话详情与工作步骤复刻规格

Status: ready-for-agent

## Problem Statement

Coko 当前在消息时间线中逐项显示用户消息、助手回复、思考和独立工具卡，工作过程的组织与工具详情外观尚未达到用户要求的 DeepSeek Harness 对话体验。用户需要完整复刻参考项目的消息区域，让阅读答案、观察实时过程、展开历史步骤及检查工具输入输出具有相同的视觉与交互。

仅调整颜色、卡片外框或静态截图不能满足要求。分组边界、三级展开收起、流式更新、完成后的呈现、错误与停止、阅读位置和工具专用详情都属于复刻范围；同时 Coko 现有能力与数据必须继续有效。

## Solution

### 范围与依据

1. 修改 Coko 实际运行的 Session 消息区域，包括用户消息、助手阶段回复和最终回答、思考、工作步骤、工具详情、消息及轮次操作、运行与结束状态。
2. 工作步骤固定采用参考项目的 `detailed`（详细）模式。详细模式不等于完全展开模式，也不等于自动打开每个工具正文。
3. 区域内字体、字号、行高、内容宽度与对齐、间距、颜色、圆角、材质、图标、动效和交互以参考版本为准；同时适配明暗主题及主内容宽度至少 390 CSS px 的窗口。
4. 顶部栏、底部输入框、侧栏和其他页面保持现状。消息列与既有输入框的对齐在消息区域内解决；不借此重做输入框。
5. 保留 Coko 现有业务能力，以 Coko 当前 Session Entry、协议和运行状态适配显示。参考项目缺少对应物的内容采用相同视觉规则，继续表达其原有语义。
6. 参考项目的 Inspect 能力映射到 Coko 现有追踪入口，不另行复制 Trajectory 子系统或新增固定详情侧栏。

视觉与行为基线为本次调查时 DeepSeek Harness 的 Web/Electron 共用聊天实现，具体版本见 Further Notes。用户后续明确修订优先于该基线；本规格未特别改写的对应行为按该版本的详细模式执行，不改用参考桌面端默认的标准模式。设置项未纳入范围的部分采用基线默认行为：完成时收起、保留全部助手回复。

### 工作步骤的可观察规则

| 编号 | 要求 |
| --- | --- |
| FLOW-01 | 以 Coko Run 的真实归属和时序组织过程，不能把参考项目的 Turn/Step 结构当作 Coko 协议。不同 Run 的过程不混组。无归属记录保持独立，不从文本猜归属。 |
| FLOW-02 | 同一 Run 中相邻的思考与工具归为过程组；助手可见回复、中途输入及独立状态边界截断组。工具类别变化或同一 Run 内模型请求变化本身不拆组。只有真实成员才创建组。 |
| FLOW-03 | Run 运行中隐藏所有过程组头，过程行直接平铺，不设组级限高；被阶段回复截断的早期组也按运行中的详细模式显示。 |
| FLOW-04 | Run 结束后恢复历史组头，组正文初始收起并支持独立开合。展开后的组使用基线的限高、边缘渐隐与内部滚动；失败或停止的 Run 保持整轮过程可见，不等于强制展开每个工具正文。 |
| FLOW-05 | 对正常结束、有过程内容且过程开始后没有中途可见输入的 Run，整轮过程默认收起；开场连续输入不阻止收起。阶段回复、最终回答、输入和页脚保持可见。没有最终回答时仍可按条件收起过程。 |
| FLOW-06 | 运行中、失败、停止或过程开始后出现 Steering 等可见输入的 Run 不提供整轮折叠，保持输入与各段过程的原顺序。暂停、中断、审批及结果待确认按 Coko 状态表达，不能伪装为正常完成并隐藏待处理内容。 |
| FLOW-07 | 显隐由外到内依次为整轮、过程组、单条思考或工具；内层开合不能越过外层。按基线收起整轮时重置内部开合，其他流式更新、工具结算及组状态变化不无故重置阅读位置或行身份。 |
| FLOW-08 | 已结束组按参考规则显示排名靠前的工具类别摘要和图标，不因调用失败扣除该次活动，也不把调用数描述为成功操作数；没有工具类别时使用分析摘要。类别与调用身份来自 Coko 数据。 |
| FLOW-09 | 思考仅在非空白时显示独立行，默认收起，包括流式期间。收起时采用参考的最近已完成首行预览规则；未完成的单行不冒充完整预览。展开显示紧凑 Markdown。 |
| FLOW-10 | 过程行间距 4px，助手回复周围间距 12px，整轮控件与输入及紧随其后的可见行间距 16px，展开组头与正文间距 8px；历史组限高为 min(400px, 50vh)，方向渐隐 24px。其余几何逐项对照基线样式，不用近似卡片替代。 |

### 消息、工具详情与状态

| 编号 | 要求 |
| --- | --- |
| DETAIL-01 | 用户消息、附件、助手回复、Markdown 及消息操作按参考布局复刻；原始用户与模型内容保持原文。Coko 的命令调用与展开全文、文件引用、图片、回退和分叉继续可用。 |
| DETAIL-02 | 工具从紧凑摘要行进入行内详情，复刻图标、标题、摘要分隔、状态、悬停/焦点反馈、开合及正文容器；单个工具正文仍由用户手动展开。命令和编辑工具不再仅因工具类型默认打开。 |
| DETAIL-03 | 对 Coko 已有且参考项目有对应物的工具，完整复刻对应专用详情：命令终端、文件读取、写入/编辑 diff、搜索、图片及结构化结果。正文的工具栏、复制反馈、行号、增删统计、错误与截断提示等实际存在的能力一并对照；只展示当前调用有真实数据支持的字段。 |
| DETAIL-04 | 字段不等同于外观：按当前工具的参数、结果与进度提取内容。不得为了凑参考卡片而显示虚构的完整文件、diff、退出码、耗时、图片尺寸、链接、计数或成功状态；缺少专用数据时保留可检查的真实输入/输出。 |
| DETAIL-05 | Coko 独有工具、未知工具和 MCP 工具保留名称及完整可查看的真实参数/结果，采用参考的通用输入/输出布局；不因无法识别类别而消失、合并或改成成功。 |
| DETAIL-06 | 准备、运行、成功、失败及停止等参考状态映射到 Coko 实际可证明的状态。待审批、无结果、中断后的结果待确认与执行失败可区分；实时 partialResult 与已提交结果不能重复成两个工具调用。 |
| DETAIL-07 | 工具状态和结果通过调用身份配对；参数相同的不同调用仍各自显示。流式变为已提交结果时保持同一个显示实体，用户展开状态、选区和滚动不因 key 变化丢失。 |
| DETAIL-08 | 原有审批决定、沙箱拒绝、Hook 阻断、子代理审批冒泡、Outcome Confirmation 与只读限制继续生效；不能用展开详情或 Inspect 绕过审批或触发再次执行。 |
| DETAIL-09 | Coko 的 Plan、Goal、Todo List、Background Job、Hook、子代理通知、团队消息与任务、定时触发、Handoff、用量、压缩分隔及被回退区间均保留。其可操作状态和关键通知不因过程折叠不可达。 |
| DETAIL-10 | 运行指示、耗时、完成、停止、失败和重试采用参考呈现并由 Coko 状态驱动。仅有可信起止记录时显示耗时；缺少起点时不以首个已加载工具时间代替。时钟更新不重复播报，状态变化可被辅助技术感知。 |
| DETAIL-11 | Inspect 使用 Coko 现有追踪入口及其实际可支持的定位能力；不产生死按钮，也不额外引入参考项目的服务协议。路径、链接、附件和复制操作沿用 Coko 已有安全与宿主边界。 |

### 阅读、交互与视觉完整性

| 编号 | 要求 |
| --- | --- |
| READ-01 | 位于底部时跟随新输出；用户向上阅读后暂停跟随，回到底部或主动返回底部后恢复。外层消息区与限高组内部的跟随状态独立，不因工具结算或 Run 完成强拉回底部。 |
| READ-02 | 手动展开历史组从顶部开始；运行内容的增长与恢复限高不重置已有阅读位置。折叠和新输出协调为连续变化，不留下无依据的底部空白或完成后再跳一次。 |
| READ-03 | 历史恢复或在现有入口加载更早内容时，保持原有可见内容的锚点、实体身份与手动开合；新加载内容若揭示中途输入，重新计算整轮折叠资格并保留真实时序。不为本功能另造历史分页协议。 |
| READ-04 | 动效、hover、pressed、focus、展开和加载状态完整对照基线；尊重 reduced-motion。键盘可操作每层开合、消息操作与详情按钮，自动收起不能隐藏当前键盘焦点，手动收起先恢复焦点到控制项。 |
| READ-05 | 中文与英文产品文案进入 Coko 类型化字典；代码、路径、协议值和用户内容保持原文。长内容可完整查看，代码、终端与 diff 在局部横向滚动，不造成整页横向溢出。 |
| READ-06 | 明暗主题、正常宽度和 390 CSS px 主内容宽度均可阅读和操作；不靠缩小整体字号、裁剪错误或隐藏主要操作掩盖空间不足。 |
| READ-07 | 对应元素逐项比较字体、行高、间距、图标形状和线宽、颜色、边框、曲线、阴影及动效；对有对应物的视图不能以“近似”或静态截图相似作为完整复刻通过依据。 |

## User Stories

1. 作为用户，我希望 Coko 的实际消息区域与参考项目一致，以便得到完整的对话阅读体验。
2. 作为用户，我希望消息改版保持顶部栏、输入框和侧栏现状，以便继续使用熟悉的工作台。
3. 作为用户，我希望工作步骤直接采用详细模式，以便运行时看清每个步骤。
4. 作为用户，我希望过程在运行时平铺，以便不用先展开分组才能观察进展。
5. 作为用户，我希望完成后能收起整轮过程，以便集中阅读阶段回复和最终回答。
6. 作为用户，我希望单独展开某个历史过程组，以便只检查有关步骤。
7. 作为用户，我希望工具类别变化不打散连续过程，以便按实际工作顺序阅读。
8. 作为用户，我希望追加指令仍留在原来的位置，以便理解之后步骤为何改变。
9. 作为用户，我希望思考默认紧凑并提供已完成首行预览，以便按需查看完整推理。
10. 作为用户，我希望阶段回复和最终回答始终可读，以便收起过程后仍能理解进展和结果。
11. 作为用户，我希望点击工具行后看到与参考相同的专用详情，以便检查调用内容。
12. 作为用户，我希望命令详情展示真实命令、输出和已有退出状态，以便判断执行结果。
13. 作为用户，我希望文件读取与修改使用对应的读取视图或 diff，以便核对实际操作。
14. 作为用户，我希望搜索与图片结果可完整查看，以便理解工具发现的内容。
15. 作为用户，我希望未知工具和 MCP 工具仍可查看参数与结果，以便不丢失扩展能力。
16. 作为用户，我希望运行中的工具详情持续更新且不重复，以便查看最新进度。
17. 作为用户，我希望审批、拒绝、失败、中断及结果待确认可区分，以便做正确的下一步操作。
18. 作为用户，我希望失败或停止后仍能检查过程，以便定位问题和按现有规则重试。
19. 作为用户，我希望现有 Plan、Goal、待办与后台任务保持可用，以便继续当前工作。
20. 作为用户，我希望子代理、团队和定时触发的消息保留来源与顺序，以便理解协作过程。
21. 作为用户，我希望命令全文、文件引用、图片及消息操作继续可用，以便不因改版丢失信息。
22. 作为用户，我希望回退、分叉、压缩和交接仍遵循原有约束，以便安全处理 Session 历史。
23. 作为用户，我希望在工具详情进入已有追踪视图，以便检查执行记录。
24. 作为用户，我希望向上阅读时不被新输出拉回底部，以便连续读完历史。
25. 作为用户，我希望流式结算、展开和折叠保持合理的阅读位置，以便不反复寻找刚才的内容。
26. 作为用户，我希望重新打开已有 Session 后仍可查看真实历史，以便直接继续工作。
27. 作为用户，我希望用键盘操作每层详情且焦点不丢失，以便无需鼠标也能完成检查。
28. 作为用户，我希望减少动态效果的偏好被遵守，以便舒适阅读。
29. 作为用户，我希望明暗主题和窄窗口都能看到完整状态与主要操作，以便适应不同工作环境。
30. 作为用户，我希望中文与英文界面一致可用，以便语言切换不改变能力。
31. 作为用户，我希望改版使用 Coko 当前数据且不改写原有记录，以便已有 Session 继续可靠回放。
32. 作为用户，我希望复刻有真实运行与视觉对照证据，以便确认交付不只是外框相似。

## Implementation Decisions

- **数据所有权不变。** Session Entry 继续是已提交事实，SQLite 与 Sidecar 保持原有权威边界，遵守 [ADR 0003](../../docs/adr/0003-settings-and-sessions-in-sqlite.md)。不导入参考项目的存储、消息模型或旧格式兼容逻辑。
- **在展示层适配。** 复用现有时间线派生、工具调用与结果配对、实时进度以及应用状态订阅。建立满足分组、开合和专用详情的显示模型，不把纯展示状态写回业务记录。
- **实体身份稳定。** 使用现有 Session、Run、条目与工具调用身份跨流式/持久化阶段关联显示实体；折叠、工具结算与主题变化不能通过重挂载整段内容实现。
- **区分两种完成。** 组被回复截断和 Run 结束分别建模；详细模式的平铺与历史呈现由所属 Run 状态决定，不能仅看某个组已关闭或某个工具已完成。
- **保留模块边界。** 业务流程、网络、审批和执行仍在 Coko 应用与服务层；展示组件接收明确数据与回调。现有右栏消费者共用时间线时也要验证，不能因主区域改版破坏子 Session 阅读。
- **局部视觉适配。** 复用 Coko 现有技术栈与共享组件能力。需要补充视觉变体或语义 token 时集中维护并限制影响范围；用户允许复刻区域以参考为准，不等于允许全局改变邻页。确需调整共享规则时同步约定、消费者和样式守卫的精确例外。
- **工具详情按真实数据建模。** 优先复用现有结果、diff、图片、终端与宿主回调，专用字段不足时显示真实通用详情。参考项目独有的工具不因展示需求而被新增为 Coko 可执行能力。
- **业务限制保持原义。** Rewind、Fork 与被回退区间遵守 [ADR 0006](../../docs/adr/0006-file-checkpoints-and-rewind.md)；审批、确认与只读状态由原有机制决定，展示改版不改变执行授权。
- **既有数据直接可读。** 不更改 Session Entry payload、数据库 schema、对外 API 或持久化格式；发现现有数据无法表达某项承诺时记录具体缺口，先用真实内容保证可检查，不静默虚构字段或扩大后端范围。
- **默认配置确定。** 本轮固定详细模式、完成时收起、保留全部回复；不新增四档模式选择、延后收起和“仅最终回答”等设置。原有应用设置保持原作用。

## Testing Decisions

### 验证接缝与先例

主要接缝优先采用**真实应用装配入口**：通过已有可控协议夹具向 App 输入 Coko Session Entry 与实时事件，在 Vitest Browser Mode 中断言实际可见内容、操作、焦点、几何和滚动。它覆盖时间线投影、业务适配与组件组合，避免只测试孤立卡片。

纯函数测试用于精确覆盖分组、时序和调用配对边界；只补充真实应用入口难以表达的组合，不以内部数组形状替代用户可观察结果。涉及持久化历史、审批、恢复及宿主动作时，复用真实 Sidecar/Electron 入口，以 faux 模型确定输入，不替换后续业务实现。静默 agent-browser/CDP 用于视觉对照和交互验收。

### 完整复刻的证据要求

- 使用脱敏、等价内容分别覆盖用户消息、阶段/最终回复、思考、运行中详细过程、完成后整轮收起、历史组展开、各已支持的工具专用详情，以及失败、停止、审批和无结果。
- 为上述状态保留同环境的参考/Coko 截图和对应操作记录，逐项核对实际几何与计算样式；动效、滚动、焦点和流式转换另有交互证据，静态截图不能替代。
- 对 Coko 独有内容核对业务状态、时序、关键操作和参考风格的一致性；数据差异与视觉差异分别解释，不以“数据格式不同”掩盖样式遗漏。
- 记录参考版本、Coko 对象版本、主题、语言、内容区尺寸、设备像素比和字体环境。系统字体不可用、状态无法构造或真实指针/原生层未验证时写明缺口，不能声称完整验收通过。
- 只验证消息区域需要的最小相关用例，受共享变更影响时扩展消费者；遵守现有测试隔离、完成信号等待与进程清理规则。分别报告本地通过、失败、跳过、未运行及 CI 状态。

### 后续执行入口

已核对现有入口：`pnpm run check:docs` 用于文档；`pnpm run test <文件路径>`、`pnpm run typecheck` 用于后续代码与相关测试；Browser Mode 项目为 `desktop-renderer`，Electron 项目为 `desktop-e2e`，后者由现有 globalSetup 构建当次产物。具体文件范围在实施时按实际改动选择，本规格不声称已运行。

桌面视觉验收遵守项目 agent-browser 流程，默认静默 CDP，不抢用户焦点；不另引入自动化依赖。现有实例与测试进程先核对身份，验证结束等待所属进程和连接实际退出。真实指针与原生窗口层不属于消息区域的主要变更，若确需验证并占用前台，先告知用户。

## Out of Scope

- 更新空白的对话详情 `.pen` 或将设计稿作为本次交付。
- 重做顶部栏、输入框、侧栏、新对话欢迎页、设置页及其他页面。
- 改为标准、简洁或完全展开模式，增加展示模式、延后收起及仅最终回答的设置。
- 引入参考项目的 Session/Turn/Step 存储、Host、Gateway、Trajectory 或工具执行系统；增加 Coko 当前没有的可执行工具。
- 为凑齐详情而变更数据库、重写历史、迁移/回填旧记录，或引入未要求的兼容层。
- 改变审批、权限、沙箱、恢复、回退、分叉、归档/只读及其他既有业务语义。
- 为视觉对齐复制参考项目的品牌名称和真实用户数据，或把用户/模型内容翻译为产品文案。
