# 03: 详细模式与三级折叠

**What to build:** 用户能在运行中的 Session 直接阅读平铺工作步骤，Run 完成后按参考规则收起整轮过程，再逐层打开过程组和单条详情。复用 01 的消息/思考和 02 的稳定工具实体，在展示层按 Coko 的真实 Run 与条目时序组织内容。

## Acceptance criteria

- [x] 实现前明确消息、思考、工具及独立业务条目的显示身份、Run 归属、分组边界和生命周期契约；必要的投影整理在本票内先完成，既有协议、payload 和数据库格式不变。
- [x] 相邻思考与工具在同一 Run 内成组，工具类别或模型请求变化本身不拆组；可见助手回复、中途输入、独立状态边界和不同 Run 正确截断；没有成员时不创建空组。
- [x] 固定详细模式：运行中所有过程组头隐藏，过程行平铺、4px 行距且无组级限高，包括已被阶段回复截断的早期组；阶段回复及最终回答独立显示。
- [x] 历史组头、类别摘要、排序及图标符合参考；调用按真实身份计一次，失败调用参与活动计数但不被解释成成功操作。展开组的间距、限高及渐隐采用规格值。
- [x] 正常完成且有过程、没有过程开始后的中途可见输入时，整轮默认收起；全部助手回复、输入和页脚保留。没有最终答案仍按条件折叠，纯回复 Run 不提供空折叠。
- [x] 运行中、失败、停止或中途输入的 Run 不提供整轮折叠；暂停、中断、审批与结果待确认不能伪装为正常完成，既有关键业务条目与操作保持可达。
- [x] 整轮、组、单条详情三级显隐和开合符合参考；收起整轮按基线重置内部开合，普通增量、工具结算和组状态变化不随意重置其他状态。
- [x] 运行、完成、停止、失败和重试抬头由当前 Coko 状态驱动；有可信起止记录才显示耗时，缺少起点不猜测，计时不连续播报，适用的断线计时行为对照参考。
- [x] 自动收起不隐藏当前键盘焦点，手动收起先恢复焦点至控制项；短内容的跟随与过渡可正常使用，不能留下已知阅读或授权回归等待后票修复。
- [x] 真实 App 验证跨回复、跨 Run、Steering、正常/异常结束、无最终答案和类别统计；保存运行平铺、整轮收起及组展开的双主题证据，复核右栏子 Session 消费者。

## 范围与衔接

依赖 01、02 是因为此票需要将已复刻且身份稳定的消息/思考与工具行组合为三级结构。12 负责长内容、历史加载和尺寸变化的完整阅读协调；本票交付时基础交互及所有既有业务能力必须有效。

规格锁定的参考提交、Coko 数据边界与非目标持续适用。不得修改数据库、协议和既有执行授权来凑齐展示数据，也不得用全局样式变化影响范围外页面。每票按实际变更更新所属当前行为文档；长期文档不反向链接本票。
