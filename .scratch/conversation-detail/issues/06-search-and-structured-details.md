# 06: 搜索与结构化工具详情

**What to build:** 用户可以展开 Coko 已有搜索调用和结构化工具结果，以参考项目对应的结果视图检查匹配、位置、字段与列表；LSP、Memory 等已有能力继续使用当前数据。

**Spec:** [对话详情与工作步骤复刻规格](../spec.md)

**Spec scenarios:** AC-10（搜索与结构化结果）、AC-11、AC-18（已有结果入口）、AC-24

**User stories:** 11、14、15、18、23、27、29—31

**Blocked by:** [02：工具摘要行与通用详情](02-tool-rows-and-generic-details.md)

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 对现有搜索与有对应物的结构化结果，逐项对照参考标题、摘要、分区、列表、字段、工具栏和错误/空结果样式；未知结果继续完整使用 02 的通用详情。
- [ ] 搜索位置、路径、行号、结果数量与截断提示只来自可证明的当前数据；保留完整可查看内容，不从结果文字随意猜造结构或成功计数。
- [ ] LSP 和 Memory 等既有工具保留原操作语义、可检查参数/结果及已有位置入口；没有参考对应物时使用同套视觉规则，不增加新的工具能力。
- [ ] 搜索结果中的代码与用户内容保持原文；长路径、长匹配行、空集合、失败及字段缺失在正常宽度和 390 CSS px 下均可查看。
- [ ] 详情里的链接、文件或追踪操作遵循现有回调与键盘规则，不误触整行折叠、不出现死入口。
- [ ] 真实 App 覆盖有结果/无结果/失败、长内容、现有 LSP/Memory 结果与通用结果；提交对应双主题视觉及交互证据。

## 范围与衔接

仅依赖 02，结果展示不依赖 05 的文件修改视图。需要跨票共用样式时明确共享所有者，不能为并行工作复制近似组件。

规格锁定的参考提交、Coko 数据边界与非目标持续适用。不得修改数据库、协议和既有执行授权来凑齐展示数据，也不得用全局样式变化影响范围外页面。每票按实际变更更新所属当前行为文档；长期文档不反向链接本票。

## 验证与回执

- 采用规格的真实 App 装配入口及本票要求的现有 Sidecar/Electron 入口；纯函数测试只补充边界，不代替用户可见路径。
- 按当前实际改动选择相关测试，运行类型和文档检查；保留精确命令、实际数量、退出码、参考/当前对象版本、主题/语言/尺寸及可访问证据。只更新失效证据，不用盲目重试、固定 sleep 或放宽断言制造通过。
- 视觉与交互默认静默 agent-browser/CDP。获取资源后登记清理，结束时等待所属会话和进程实际退出，保留无关运行实例与用户数据。
- 完成后在 Comments 追加实施、验证、文档影响和实际交付状态；仍有必要验收缺口时如实记录，不提前关闭。不因前置票以 wontfix 关闭就自动认定阻塞解除。
