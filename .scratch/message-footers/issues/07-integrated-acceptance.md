**What to build:** 在同一最终实现状态下，用户能够可靠完成消息复制、回退、历史助手分支和整轮用量检查；用实际跨模块证据核对整份规格，补齐组合回归并完成文档与交付回执。

**Spec:** [消息底栏与本轮用量规格](../spec.md)

**Spec scenarios:** AC-01—AC-21（联合验收，不代替前置票各自的必要测试）

**Blocked by:** 02 — 完整统计重试与压缩消耗；03 — 用户消息底栏；05 — 从助手回复创建新对话分支；06 — 停止、失败与无最终回复的底栏

**Status:** ready-for-agent

**Closed:** false

## Acceptance criteria

- [ ] 逐项确认前置票真正交付所需行为与契约；01 和 04 已由传递依赖覆盖。不能因票已关闭或存在局部绿灯就认定整份规格已完成。
- [ ] 在同一最终实现状态串联真实 Sidecar、持久化、实际 App 和静默 Electron，完成 AC-01—AC-21 的覆盖清单；复用仍有效的单票证据，仅为组合行为、变更或缺口新增必要验证。
- [ ] 联合验证多请求工具循环、失败后重试、正常与失败压缩、部分 usage 后中止到真实底栏和详情的全过程；统计完整性、去重、标题/子代理排除与四分桶计数均符合独立预期。
- [ ] 从压缩前后及非最新成功助手回复创建分支，发出下一请求核对上下文边界；验证源记录、草稿和文件未改变，目标输入为空，历史用量不重复记账，工作目录不偏移。
- [ ] 验证正常结束、停止、失败和无正文的底栏数量、时间、操作资格及不完整状态；同时核对用户回退三模式、取消、不追踪 bash 的原有约束。
- [ ] 在真实 Electron 中验证消息复制与宿主剪贴板，检查重连、重新打开和重启后的计量与界面一致性；Browser Mode 证据不冒充原生或真实模型验证。
- [ ] 检查明暗主题、zh/en、390 CSS px 及以上宽度、长模型名、键盘、无 hover 可达性、浮层边缘和阅读位置；默认静默调试，确需前台原生层或真实鼠标时先告知，结束时清理所属会话与进程。
- [ ] 新底栏和详情卡没有费用，既有累计费用、预算、定价及审计消费者仍有效；录制会话或可见输出预期已逐项审查，未用实际输出覆盖独立期望消除失败。
- [ ] 当前行为文档、术语和长期决定的后继关系与最终实现一致，正式文档不反向依赖任务材料；检查需求一致性与仓库规范，发现问题修复并更新失效证据。
- [ ] 按实际最终改动运行最小相关检查，记录精确命令、实际数量、退出码和对象版本；分别报告真实 Provider、协议回放、Electron、CI、跳过及未验证范围，无理由不跑全仓测试。
- [ ] 交付回执如实区分本地、提交、推送、合并与发布，按当前会话授权和开发流程执行对应动作，不以测试通过冒充发布成功；本次任务发布不改变父级记录的确认或实施状态。

## 范围与衔接

本票收敛最终组合结果，不接收没有必要单票测试的未完成切片，也不以大规模重跑替代明确回归证据。必要的新发现应修复到实际责任模块并同步受影响票的证据，不降低校验或覆盖标准来完成验收。

## 验证与回执

采用用户已确认的 Sidecar 协议集成、实际 App Browser Mode 和静默 Electron 边界。通过文件、实际请求、持久化、真实渲染和剪贴板事实判定成功，不只检查内部函数或文字声称。完成后在 Comments 汇总全部验收映射、检查结果、文档影响、资源清理、交付状态及剩余限制，再判断是否关闭。
