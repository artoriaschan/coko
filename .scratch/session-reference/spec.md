本规格包含两件互不依赖的事：`/` 命令菜单增加“插件”分组，以及在 `@` 菜单中引用同一 Project 的其他会话（Session Reference）。`/` 的触发位置与命令语义、File Reference 的语法与内联行为、插件的格式兼容范围都不变。

## Problem Statement

- **插件带来的命令认不出来。** 用户装了插件后，它的命令混在“用户”组、它的 Skill 混在“Skill”组，只能靠 `插件名:` 前缀辨认。命令一多，用户分不清哪些是自己写的、哪些是插件带来的。
- **一次对话的结论带不进另一次对话。** 用户在一个会话里和 Agent 讨论清楚了方案，想在另一个会话里照此实施，只能手动复制粘贴或者重讲一遍。模型没有任何途径读到其他 Session 的内容。交接（Handoff）会新建会话，解决不了“在已有会话里引用另一个会话”。

## Solution

- **`/` 菜单多一个“插件”组。** 已启用插件贡献的命令和 Skill 都归到这一组，排在 Skill 组之后、MCP 组之前。条目的名字、调用方式、同名时谁生效都与现在相同。
- **`@` 菜单多一个“会话”组。** 输入 `@` 后，文件候选下方列出同一 Project 里最近的其他会话，继续打字按标题过滤。选中后输入区出现一个显示会话标题的 chip。
- **提交时附上那次会话的文字记录。** 模型收到这条消息时同时看到被引用会话里用户说过的话和助手的文字回复；长会话压缩过的，以压缩摘要打头。不发额外的模型请求。内容上限与 File Reference 共用：单个 50KB，每条消息最多 10 个引用、合计 200KB。
- **时间线上看得出引用了谁。** 用户消息的气泡里显示 `@会话标题`，气泡下方有一个会话 chip，点击打开那次会话。

## User Stories

**`/` 菜单的插件分组**

1. As a 用户, I want 插件贡献的命令和 Skill 在 `/` 菜单里归入单独的“插件”组, so that 我一眼分得清哪些命令来自插件。
2. As a 用户, I want “插件”组排在 Skill 组之后、MCP 组之前, so that 我自己写的命令和 Skill 仍然排在前面。
3. As a 用户, I want “插件”组内的条目按名字排序, so that 同一个插件的命令和 Skill 因 `插件名:` 前缀自然排在一起。
4. As a 用户, I want 插件条目的名字、参数提示、描述与调用方式都不变, so that 分组不改变我已经习惯的用法。
5. As a 用户, I want 同名命令的取舍与现在相同, so that 分组不会让另一个命令突然生效。
6. As a 用户, I want 停用的插件命令照旧不出现在菜单里, so that 停用仍然有效。
7. As a 用户, I want 没有启用任何插件时菜单里没有“插件”组, so that 界面不出现空分组。
8. As a 集成方, I want 命令目录的每一项标明它来自哪个插件, so that 我能在自己的界面里做同样的分组。

**选择会话**

9. As a 用户, I want 输入 `@` 时在文件候选之外看到同一 Project 的其他会话, so that 我不用离开输入区就能引用一次对话。
10. As a 用户, I want 文件组在前、会话组在后, so that 最常用的文件引用位置不变。
11. As a 用户, I want 没有输入查询时会话组显示最近活动的 5 个会话, so that 刚聊过的那次对话触手可及。
12. As a 用户, I want 继续打字时按标题过滤会话, so that 我能找到更早的对话。
13. As a 用户, I want 同一段查询同时过滤文件与会话, so that 我不用先选类别。
14. As a 用户, I want 同名的会话能靠最近活动时间区分, so that 我不会引用错。
15. As a 用户, I want 候选里没有当前会话自己, so that 我不会把正在进行的对话引用给它自己。
16. As a 用户, I want 候选里没有子代理的会话, so that 列表里只有我自己发起的对话。
17. As a 用户, I want 候选里没有已归档的会话, so that 我收起来的对话不占位置。
18. As a 用户, I want 项目内的会话只列出同一 Project 的会话（含它的 Worktree Session）, so that 另一个项目的内容不会被带进当前项目。
19. As a 用户, I want 独立对话列出其他独立对话, so that 不属于任何项目的对话之间也能互相引用。
20. As a 用户, I want 还没有 Session 的新对话草稿里同样能引用会话, so that 我可以用“接着那次对话”开始一次新对话。
21. As a 用户, I want 没有任何会话可引用时菜单与现在完全一样, so that 新功能不打扰只引用文件的用法。
22. As a 用户, I want 菜单的键盘、Esc、输入法与定位行为和现在一样, so that 我不需要重新学习。

**草稿**

23. As a 用户, I want 选中会话后输入区出现一个显示 `@会话标题` 的 chip, so that 我看得懂自己引用了什么。
24. As a 用户, I want 会话 chip 作为整体选中与删除、不能在其中输入, so that 它和文件 chip 的手感一致。
25. As a 用户, I want 一条消息里可以同时引用文件和多个会话, so that 我能把代码与讨论一起交给模型。
26. As a 用户, I want 带会话 chip 的草稿在切换会话或重启后还在, so that 写了一半的消息不丢。
27. As a 用户, I want 从输入区复制出的文本是 `@session:<id>`, so that 粘贴回来再提交仍然有效。

**提交与内容**

28. As a 用户, I want 提交后模型看到被引用会话里我说过的话和助手的文字回复, so that 它能接着那次讨论的结论工作。
29. As a 用户, I want 引用不触发额外的模型请求, so that 引用既不让我等待也不多花钱。
30. As a 用户, I want 被引用会话压缩过时，附上的记录以压缩摘要打头, so that 长会话里早期的决定不丢。
31. As a 用户, I want 记录里不含工具调用、工具结果与思考, so that 一个长会话不会撑满当前上下文。
32. As a 用户, I want 记录里不含那次会话附带的文件内容与它引用的其他会话, so that 引用不会层层展开。
33. As a 用户, I want 那次会话里的命令消息以 `/name 参数` 出现, so that 模型看到的是我当时输入的内容而不是模板全文。
34. As a 用户, I want 被回退掉的消息不出现在记录里, so that 模型看到的是那次对话的当前状态。
35. As a 用户, I want 引用一个正在运行的会话时只附上已经完成的部分, so that 记录不含半截回复。
36. As a 用户, I want 记录里已登记的 Secret 与 Credential 明文被替换, so that 引用不会成为新的泄露通道。
37. As a 用户, I want Run 进行中的追加指令里同样可以引用会话, so that 我能在 Agent 工作途中补充背景。
38. As a 用户, I want 模型知道被引用会话的标题, so that 它在回复中能指明信息来自哪次对话。

**上限**

39. As a 用户, I want 单个会话引用最多附 50KB，超出时保留最近的部分并注明省略, so that 最能决定接下来工作的内容被保留。
40. As a 用户, I want 记录被截断时压缩摘要仍然保留, so that 早期的决定不会因为会话太长而消失。
41. As a 用户, I want 文件引用与会话引用共用每条消息 10 个的上限, so that 我只需要记住一个数字。
42. As a 用户, I want 文件引用与会话引用共用合计 200KB 的额度, so that 一条消息不会把上下文占满。
43. As a 用户, I want 超出上限的引用附上一行说明而不是悄悄消失, so that 模型和我都知道哪些没有附上。

**范围与失效**

44. As a 用户, I want 手写或粘贴的引用指向另一个 Project 的会话时不附内容并说明原因, so that 项目之间的边界不能被绕过。
45. As a 用户, I want 引用当前会话自己或子代理会话时不附内容并说明原因, so that 无意义的引用不占额度。
46. As a 用户, I want 引用的会话在提交时已被删除，消息照常发送、文本原样保留, so that 一个失效的引用不会挡住我发消息。
47. As a 用户, I want 引用已归档的会话照常附上内容, so that 归档只是收起列表，不影响我已经写好的引用。
48. As a 用户, I want `@session:` 之外的写法（`@路径`、`@某人`）行为不变, so that 新语法不影响已有的文件引用。

**时间线**

49. As a 用户, I want 时间线里我的消息显示 `@会话标题` 而不是一串 id, so that 历史消息读得懂。
50. As a 用户, I want 消息气泡下方有一个会话 chip, so that 我看得出这条消息附了哪次对话。
51. As a 用户, I want 点击会话 chip 打开那次会话, so that 我能回去核对原文。
52. As a 用户, I want 被引用的会话后来改名或删除后，时间线仍显示提交时的标题, so that 历史消息不会变成乱码。
53. As a 用户, I want 被引用的会话已删除时 chip 不可点击, so that 我不会点进一个不存在的会话。
54. As a 用户, I want 附上的会话记录不出现在气泡正文里, so that 时间线保持可读。

**回退、分叉与压缩**

55. As a 用户, I want 回退或分叉到一条带引用的消息时，回到输入区的只有我当时输入的文本, so that 输入区不会被几十 KB 的记录淹没。
56. As a 用户, I want 回到输入区的 `@session:<id>` 再次提交仍然生效, so that 回退后重发不需要重新选择。
57. As a 用户, I want 带会话引用的消息被压缩时，摘要请求里只留一行“附了哪次会话”, so that 压缩不因引用的记录而超限或走样。
58. As a 用户, I want 分叉出的新会话保留消息里已附上的记录, so that 新会话里的模型看到的上下文不缺。（批准后变更，2026-11-23 用户确认：原文是“分叉或交接出的新会话”，意图是新会话里的模型不缺上下文。交接按既有设计不复制任何消息，新会话只有交接摘要，被引用会话的记录只经摘要间接进入；改变交接的设计不在本规格范围，所以本条改为只对分叉成立。见 Further Notes 的“实施中的改变”第 1 条。）

**其他入口**

59. As a 用户, I want 新对话的第一条消息带会话引用时，自动标题里不出现一串 id, so that 侧栏的标题可读。
60. As a 无界面运行的使用者, I want 提示词中的 `@session:<id>` 按同样的规则展开, so that 脚本也能让一次运行接着另一次会话。
61. As a 集成方, I want 会话引用只用提交的文本表达、请求体不加字段, so that 我按 File Reference 的方式就能使用它。
62. As a 运维者, I want Sidecar 日志记录会话引用的数量与状态而不记内容, so that 排查时不泄露对话。

## Implementation Decisions

### `/` 菜单的插件分组

- **命令目录的每一项增加可选的插件名。** 由插件贡献的命令与 Skill 带上所属插件的名字；其余条目没有这个字段。来源取值不变：插件命令仍记为用户来源，插件 Skill 仍记为 Skill 来源。
- **只改展示。** 菜单把带插件名的条目归入单独的“插件”组，位于 Skill 组之后、MCP 组之前；组内按名字排序。其余各组只含不带插件名的条目。前缀匹配在前、包含匹配在后的规则在组内照旧。
- **不变的部分：** 同名优先级（内置 > 项目 > 用户 > Skill > MCP）、遮蔽诊断、启停、提交时的展开、`command` 条目的来源字段、设置页“Skills & Commands”分区。
- **文案** 中英文同时提供“插件”组名。

### Session Reference 的语法

- **`@session:<id>`**，`<id>` 为 Session 的 id。与 File Reference 相同，`@` 必须在开头或空白之后；id 在空白或结尾标点处结束。
- **`@session:` 前缀保留给会话引用**：这样的 token 不再作为文件路径解析。其他 `@` token 的解析不变。
- **请求体不加字段。** 提交、追加指令与首次发送都只靠文本。
- **同一个会话在一条消息里只附一次。**

### 展开

- **与 File Reference 同一个展开步骤。** 命令先展开，随后在展开后的文本中解析引用；文件引用与会话引用按在文本中出现的顺序处理，每个引用在同一条 user message 中追加一个文本块，原文在引用块之前。引用块不是独立的条目 kind，不新增条目版本。
- **展开入口沿用 File Reference 的：** 提交的文本、Run 进行中的追加指令、首次发送、无界面运行的提示词。不新增入口。
- **块的形状：** 以 `<session_reference id="…" title="…">` 开头、`</session_reference>` 结尾。`title` 是展开那一刻被引用会话的标题，按 XML 属性转义。
- **记录的内容** 取被引用会话有效上下文（回退与压缩都已应用）中已提交的条目：
  - 有效的 Compaction 时，以其摘要打头，标为早先对话的摘要。
  - 用户消息：只取用户提交的文本。宿主附加的块不进入记录：State Update、File Reference 与 Session Reference 的块、附件块、图片。
  - 用户消息由命令展开而来时，取原始调用 `/name 参数`，判定方式与回退恢复原始调用相同。
  - 助手消息：只取文字回复。思考、工具调用与工具结果不进入记录。
  - 每条以 `[User]:` 或 `[Assistant]:` 标出说话方，标记与压缩摘要请求的对话序列化一致。
  - 没有任何可附内容时块中写明没有消息。
- **被引用会话正在运行** 时只取已提交的条目，不等待，不含正在生成的回复。
- **Secret。** 块在生成时替换已登记的 Secret 与 Credential 明文，与 File Reference 的块相同；用户自己输入的原文不变。
- **不递归。** 记录中出现的 `@session:<id>` 与 `@path` 是文本，不再展开。

### 上限

- **单个会话引用 50KB**（UTF-8 字节，与单个文件相同）。超出时保留压缩摘要与最近的消息，从摘要之后最早的消息开始省略，并在省略处注明省略的条数。摘要自身放不下时截断摘要并注明。
- **与 File Reference 共用额度：** 每条消息最多 10 个引用、内容合计 200KB，按出现顺序计入。接近合计上限的那个会话引用按剩余额度截断。
- **超限说明。** 第 11 个及之后的会话引用、合计额度用尽后的会话引用，各附一行 `[Not attached: …]` 说明。File Reference 已有的说明文本不改。

### 范围与失效

- **可引用的会话：** 与当前会话属于同一 Project 的根 Session（含 Worktree Session）；当前会话不属于任何 Project 时，为其他同样不属于任何 Project 的根 Session。新对话草稿按草稿所选的 Project 判定。
- **范围在展开时由 Sidecar 判定**，不依赖界面的过滤。

| 情形 | 结果 |
| --- | --- |
| 范围内的会话 | 附上记录 |
| 范围内但已归档 | 附上记录 |
| 属于另一个 Project，或一方是独立对话而另一方不是 | 附一行说明：不属于当前项目，未附上 |
| 当前会话自己、子代理的会话 | 附一行说明：不能引用，未附上 |
| id 不存在或会话已删除 | 不产生块，文本原样保留 |

- **说明块同样带标题**（会话存在时），计入 10 个的数量上限，不计入字节额度。
- **日志。** Sidecar 的引用日志增加会话引用的数量、各状态的数量与截断数，不记 id、标题与内容。

### 已对 File Reference 块做特殊处理的位置

会话引用的块在以下位置与 File Reference 的块同样对待，实施时逐一核对并补齐：

- **回退与分叉返回的文本。** 返回到输入区的文本不含引用块，只含用户当时输入的文本。现状下带 File Reference 的消息会连同引用块一起返回（见 Further Notes）；本规格要求两种引用块都不返回。
- **压缩摘要请求的对话序列化。** 会话引用块缩为一行，写明附了哪个会话的标题。
- **时间线。** 块不进入气泡正文。
- **会话标题。** 首条消息的自动标题与由消息文本派生的标题中，`@session:<id>` 以被引用会话的标题显示。
- 其他从用户消息提取文本的位置（如 Reviewer 的输入）沿用各自对 File Reference 块的做法。（交付时 Reviewer 的输入没有沿用：会话引用块缩为一行，见 Further Notes 的“实施中的改变”第 6 条。）

### `@` 菜单

- **一个列表两组。** 文件组在前、会话组在后，同一段查询同时过滤两组。文件组的候选、排序、目录 Tab 下钻不变。
- **会话候选来自界面已持有的会话列表**，不新增接口。条件：与当前会话（或新对话草稿）同一范围、未归档、不是当前会话。会话列表本身不含子 Session。
- **排序与数量。** 按最近更新时间从新到旧。空查询显示 5 个；有查询时按标题匹配（不区分大小写，前缀匹配在前、包含匹配在后），最多 20 个。
- **条目显示** 会话标题与最近活动时间。
- **两组都没有匹配时菜单不出现**；只有一组有匹配时只显示那一组。
- **键盘、Esc、输入法、定位与指针选择** 沿用现有 typeahead，不新增规则。

### 草稿中的 Session Reference 节点

- **行内的原子节点**，与 File Reference 节点并列：以链接色 chip 显示 `@会话标题`，作为整体选中与删除，不能在其中输入，不可点击。（原文为“token 模式的节点”；交付时改为 Lexical DecoratorNode，外部行为不变，见 Further Notes 的“实施中的改变”第 2 条。）
- **序列化文本为 `@session:<id>`**：提交的文本、读出的纯文本、复制出的文本都是这个形式。
- **标题是选中那一刻的快照**，随草稿保存；草稿载入后不随会话改名刷新。
- **草稿持久化** 沿用 EditorState JSON；节点缺少 id 或标题时按现有“未知节点”规则丢弃草稿。
- **回退、分叉与退回未送达的追加指令** 以纯文本回到输入区，会话引用显示为 `@session:<id>`，不恢复成 chip；与 File Reference 的现状一致。

### 时间线

- **气泡正文** 中的 `@session:<id>` 在该消息带有对应的会话引用块时显示为 `@标题`，标题取自块；没有对应块时原样显示。
- **气泡下方的 chip。** 会话引用块按出现顺序显示为会话 chip，与文件、目录 chip 同一行列。点击打开该会话；会话已不在会话列表中时 chip 不可点击。（交付时界面的会话列表不含已归档的会话，所以归档会话的 chip 同样不可点击，见 Further Notes 的“实施中的改变”第 4 条。）
- **说明块**（未附上）同样显示 chip。

### 文档与术语

- 术语表新增 **Session Reference**（界面称“会话引用”）：用户消息中以 `@` 指向同一 Project 内另一个 Session、提交时附上其文字记录的引用。避免使用 mention。File Reference、Command 与 Plugin 词条不改。
- 不写 ADR：没有新的持久化格式、权限或进程边界，范围限制可以放开，内容规则沿用 File Reference 的既有决定。
- 不单独写设计稿：实现决定在本节给出。
- 随实施更新的当前行为文档：上下文管理（Session Reference 的语法、展开、上限、`@` 菜单与节点、时间线 chip）、命令（命令目录的插件名与菜单分组）、插件（菜单中的分组）、Checkpoint 与分叉中关于返回文本的说明，以及涉及的包 README。

## Testing Decisions

- **好的测试只断言外部事实：** faux 请求明细日志中实际发给模型的内容、经协议读回的条目与命令目录、界面在真实浏览器中的输出。不断言内部函数的调用次数或中间结构。
- **不新增测试接缝，沿用现有五处：**
  - **真实 Sidecar 集成测试（主接缝）。** 经 HTTP 与 WS 驱动，faux 模型，以请求明细日志断言模型看到的内容。先例：File Reference、命令、回退与 Secret 的集成测试。
  - **agent 包的纯函数测试。** 引用 token 的解析、记录的序列化与截断。先例：File Reference 的解析与展开测试、压缩的序列化测试、回退目标的测试。
  - **Sidecar 上下文贡献的单元测试。** 命令目录的内容。先例：命令贡献的测试。
  - **renderer 的 Browser Mode 测试。** 先例：typeahead、File Reference 节点、composer 与时间线的浏览器测试。
  - **Electron E2E。** 后台模式运行。先例：File Reference 与草稿、命令的端到端用例。
- **集成测试覆盖：**
  - 命令目录：插件贡献的命令与 Skill 带插件名，其余条目不带；来源取值与同名取舍不变。
  - 引用一个有两轮对话的会话：发给模型的 user message 含原文与一个会话引用块，块中有那次会话的用户文本与助手文字，没有工具调用与工具结果中的标记文本、没有思考、没有那次会话附带的文件内容。
  - 被引用会话压缩过：块以摘要打头，摘要之前的消息不出现。被引用会话有被回退的消息：不出现。
  - 被引用会话的命令消息以原始调用出现，不含模板正文中的标记文本。
  - 超过 50KB 的会话：块不超过上限，最近的消息在，开头注明省略。
  - 额度：文件与会话混合超过 10 个、合计超过 200KB 时，按出现顺序附上并给出说明。
  - 范围：另一个 Project 的会话、当前会话自己、子代理会话各得到说明块且不含对方内容；不存在的 id 不产生块，消息照常提交。
  - 追加指令与首次发送中的会话引用同样展开。
  - 被引用会话正在运行：提交不被阻塞，块中没有未提交的回复。
  - Secret：块中没有登记明文（沿用现有 secrets gate 的写法）。
  - 回退与分叉到带 File Reference 或 Session Reference 的消息：返回文本只有原文。
  - 带会话引用的消息进入压缩：摘要请求中没有被引用会话的记录正文。
- **纯函数测试覆盖：** `@session:<id>` 的词首规则与结尾标点；`@session:` 不再作为路径；序列化的各类消息取舍；截断时摘要保留、省略条数正确。
- **界面测试覆盖：**
  - `/` 菜单：插件条目出现在“插件”组且位置正确，没有插件条目时没有该组。
  - `@` 菜单：两组的顺序、空查询的 5 个、标题过滤、范围过滤（另一个 Project、归档、当前会话都不出现）、只有一组有匹配时的显示。
  - 节点：chip 显示标题，读出的文本为 `@session:<id>`，整体删除，草稿保存后恢复。
  - 时间线：气泡显示 `@标题`、下方有会话 chip、点击切换会话、会话不在列表中时不可点击、没有对应块时原样显示。
- **E2E 一条：** 在一个会话中完成一轮对话；在同一 Project 的另一个会话中经 `@` 菜单选择它并提交；faux 的请求中含前一会话的文本；时间线显示 chip，点击后切换到前一会话。
- **现有测试的处理：** 以五个来源分组为全集的菜单断言按新增分组更新；File Reference 的集成测试继续通过，其说明文本不变。
- **未覆盖并在交付时写明：** 真实模型拿到会话记录后的使用效果不做自动化评估。

## Out of Scope

- 改变 `/` 的触发位置或命令语义：句中触发、一条消息多个命令、把 Skill 作为可引用对象。
- 改变 File Reference：只传路径、新的上限、Workspace 之外的文件。
- 插件 marketplace，以及清单中被忽略的 `userConfig`、`channels`、`outputStyles`、`settings`。
- 按每个插件各开一组、在菜单里安装或启停插件与 Skill、设置页的插件分组。
- 跨 Project 引用会话；引用子代理的会话。
- 为被引用的会话生成摘要；让模型按需读取其他会话的工具。
- 附上被引用会话的工具调用、工具结果、思考、附件或图片。
- `@` 引用 URL、代码符号、Git diff、终端输出、子代理、MCP 资源。
- 请求体中的结构化引用字段；回退后把纯文本恢复成 chip。
- 草稿中的 chip 随会话改名刷新。
- `@` 文件候选的搜索根与引用展开根在 Worktree Session 中可能不一致的问题：另行验证。

## Further Notes

- **来源。** 产品决定来自 [grilling.md](grilling.md) 的四轮 23 个问题。事实核对来自阅读当前行为文档与术语表，以及引用解析与展开、有效条目派生、回退目标文本、压缩摘要的对话序列化、命令目录与命令菜单、编辑区节点、时间线对引用块的处理的代码。除下一条的探针外未运行测试。
- **调查中发现的现状问题。** 写规格前用一次性探针直接调用回退目标的纯函数：一条带 File Reference 的用户消息，返回的文本是原文加上整个 `<file_reference>` 块。界面收到返回文本后直接替换编辑区内容，没有看到再剥离的步骤，但这一点没有在真实应用中验证。按现状，回退带文件引用的消息可能把文件内容整段放回输入区。本规格把“返回文本不含引用块”列为两种引用共同的要求，由票 03 先在真实 Sidecar 上确认现状再处理。
- **本规格补充的决定（讨论中没有逐条问过；2026-11-23 用户确认全部接受，第 5 条以“实施中的改变”第 7 条收紧后的为准）：**
  1. 范围由 Sidecar 在展开时判定。访谈只确定了菜单里“跨 Project 不出”，但理由是不把另一个项目的内容带进当前项目；只在界面过滤的话，手写或粘贴一个 id 就能绕过。
  2. 范围之外但存在的会话附一行说明，不存在的不产生块。前者对应 File Reference 的“Workspace 外”，后者对应“路径不存在”。
  3. 归档的会话不出现在菜单里，但已写好的引用照常附上内容。
  4. 截断时压缩摘要优先保留，从摘要之后最早的消息开始省略。访谈定的是“以摘要打头”与“超限时保留最近的部分”，两者同时出现时若一律从最早处省略，先丢的正是摘要。
  5. 被引用会话中由宿主合成的输入（定时任务的提示词、Goal Round 的继续提示）按 user 消息的文本原样进入记录，不区分来源；只去掉 State Update、引用块、附件块与图片。（交付时宿主通知也不进入记录，见“实施中的改变”第 7 条。）
  6. 文件引用与会话引用按出现顺序共用额度；会话引用的超限说明用自己的文本，File Reference 已有的说明文本不改，避免改动模型可见的既有契约。
  7. 块的开标签带标题。时间线据此显示提交时的标题，模型据此知道内容来自哪次对话。
  8. 会话候选取自界面已有的会话列表，不新增接口；有查询时最多 20 个；条目显示最近活动时间以区分同名会话。
  9. 草稿 chip 的标题是选中时的快照，不随改名刷新。
  10. 首条消息的自动标题中 `@session:<id>` 以被引用会话的标题显示。
  11. 压缩摘要请求把会话引用块缩为一行。不这样做的话，一条带引用的消息会让摘要请求多出最多 200KB 的输入。
  12. 不写 ADR 与单独的设计稿。
- **已知的局限。**
  - 记录是提交那一刻的快照。被引用的会话之后继续进行，当前会话里的模型不会知道。
  - 附上的只有文字。那次会话里读过、改过哪些文件，只在压缩摘要中（如果压缩过）或助手的文字回复中体现。
  - 回退后 chip 变成 `@session:<id>` 纯文本。
  - 归档会话的 chip 不可点击（界面的会话列表不含已归档的会话），尽管它的引用照常附上记录。
  - 一个 50KB 的会话引用约占一万多 token，引用多个长会话会明显压缩当前会话的可用上下文。
- **可以放开的边界。** 跨 Project 引用只是范围判定与菜单过滤两处条件；实际出现这个需要时再议，不需要迁移数据。
- **调查中发现的现状问题的结局。** 票 03 在真实 Sidecar 上确认：修改前 Checkpoint 列表、回退与分叉返回的文本都是原文之后接整个引用块（两种块相同）；修改后两种块都不返回，命令消息仍返回原始调用。回退或分叉后输入区的实际显示没有在真实应用中操作确认。
- **实施中的改变（票 06 回写，2026-11-21；6–10 为代码评审修复回写，11–12 为用户确认时回写，均为 2026-11-23）。** 以下与规格原文不同，实现与当前行为文档按这里交付。2026-11-23 用户确认全部接受；第 5 条按确认结果修了竞态，第 11 条是确认时新增的改动。
  1. **交接不保留已附上的记录（Story 58）。** 分叉复制的用户消息保留引用块。交接按既有设计不复制任何消息，新会话只有交接摘要；被引用会话的记录只经摘要请求（引用块在源会话的有效上下文中原样存在）间接进入摘要。`/handoff` 指令本身不经引用展开，其中的 `@session:<id>` 不附记录，目标标题里也不换成会话标题。本次没有改变交接的设计。用户确认接受，Story 58 已改为只对分叉成立。
  2. **草稿节点是 Lexical DecoratorNode，不是 token 模式的文本节点。** chip 显示 `@标题`，文本内容是 `@session:<id>`，两者长度不同；文本节点的选区偏移按显示文本计算，覆写文本内容会让部分选中时的切片与光标位置错位。外部行为与规格一致；方向键直接越过 chip。草稿 JSON 中节点的 `type` 为 `session-reference`，带 `id` 与 `title`。
  3. **无障碍名称改了两处。** `@` 菜单列表由“文件 / Files”改为“文件与会话 / Files and sessions”；时间线引用列表由“引用的文件 / Referenced files”改为“引用 / References”。两者现在都可以含会话。
  4. **归档会话的 chip 不可点击。** 界面的会话列表不含已归档的会话，规格写的条件是“不在会话列表中”，所以归档与删除在 chip 上表现相同；归档会话的引用仍照常附上记录（Story 47）。有 Browser Mode 用例（代码评审修复 C1 补上）。用户确认接受为已知局限。
  5. **查询匹配会话标题时，`@` 之后的 Enter 选中会话。** 此前没有文件结果时菜单不出现、Enter 直接发送；现在文件没有匹配而查询匹配某个会话标题时，菜单只有会话组，Enter 选中会话。没有可引用的会话时与原来相同（Story 21）。用户确认保留。票 04 的实现里会话候选不等文件候选，带查询时菜单可能在文件结果返回前先只以会话组打开，输入 `@src` 回车想选文件的人选中的是标题含 src 的会话；2026-11-23 修掉：有查询时，会话组在这次查询的文件请求结束（成功、失败或无匹配）之后才显示，文件组先以上一次的结果显示出条目时同时显示；空查询与没有 Workspace 时会话组立即显示。
  6. **自动审查的输入不含被引用会话的记录（代码评审修复 A1，2026-11-23）。** 规格“已对 File Reference 块做特殊处理的位置”要求会话引用块在 Reviewer 输入中沿用 File Reference 的现状（原样进入用户消息）。沿用的结果是被引用会话里的助手正文、宿主通知与压缩摘要进入 `user_authorization`，而 Reviewer 在当前会话中刻意不把这三类内容当作授权。现在审查输入把会话引用块缩为一行 `[session reference attached: <标题>]`（与压缩摘要请求相同），File Reference 块不变；基础提示的宿主块清单加上 `<session_reference>`。涉及授权判断；用户确认接受，包括会话标题仍以这一行进入授权分区。
  7. **宿主通知不进入记录（代码评审修复 A2，2026-11-23）。** 补充决定第 5 条写的是“只去掉 State Update、引用块、附件块与图片”，按字面，被引用会话里的后台任务完成通知（含内联的任务输出）、后台子代理的结束通知、团队消息与 Hook 追加的上下文会以 `[User]:` 进入记录，与 Story 31（记录不含工具结果）冲突。现在这四类也不进入记录；第 5 条保留的定时任务提示词与 Goal Round 继续提示仍按原样进入。宿主块按文本块开头的标签识别，不核对前置条目：被引用会话里用户自己输入的、以这些标签开头的文本同样不进入记录。用户确认接受。
  8. **Secret 的替换先于转义与截断（代码评审修复 A3，2026-11-23）。** 此前替换在块生成之后：标题与路径中带 `&`、`<` 的登记明文以转义后的形态留在开标签里，被截断边界切开的明文留下前缀。现在标题与路径在转义之前替换，会话记录逐条、文件内容整体在截断之前替换。File Reference 的块同样受益；其说明文本不变。属于缺陷修复，不改变规格的要求（Story 中的“块中没有登记明文”）。
  9. **单条消息超限时保留结尾（代码评审修复 A5，2026-11-23）。** 票 02 的实现保留开头，Story 39 要求保留最近的部分。现在保留这条消息的结尾，说话方标记之后写一行 `[Earlier part of this message omitted to fit the session reference limit]`；原说明文本 `[Message truncated to fit the session reference limit]` 不再出现。摘要自身超限时仍保留开头。
  10. **以 `session:` 开头的文件路径自动加引号（代码评审修复 A4，2026-11-23）。** 从 `@` 菜单选中名为 `session:x` 的文件时，节点序列化为 `@"session:x"`，按路径解析；此前序列化为 `@session:x`，会被当作会话引用。
  11. **轮次指示器的提示词预览显示 `@标题`（2026-11-23）。** 票 05 交付时预览显示原文 `@session:<id>`（规格只要求气泡）。用户确认改为与气泡相同：消息带有对应的会话引用块时显示为 `@标题`，没有对应块时原样显示。
