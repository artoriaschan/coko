# 04: 转交理由与审查失败

**What to build:** Reviewer 没有放行时，用户在审批卡上看到它的理由；审查没能完成时，用户看到“自动审查未完成”及原因，调用不会未经判断就执行。覆盖的失败为超时、请求报错、输出无效、没有可用模型。预算与内容过长两种原因分别在 06 与 05 接入，本票定义它们的代码与文案。

**User stories:** 22、38–41。

**Blocked by:** 03

**Status:** ready-for-agent

- [ ] 审批请求条目按设计稿升版，新增可选的审查信息：转交时带 Reviewer 的理由，失败时带失败原因的代码；旧版本读取正常
- [ ] 审查信息只出现在经过 Reviewer 的请求上；其他询问的审批请求没有它
- [ ] 理由按设计稿的上限截断，入库与推送前替换已登记的 Secret 明文
- [ ] 审查超过超时时长：取消请求，出现带超时代码的待审批请求，调用未执行
- [ ] 审查请求报错、输出不是合法的结构化结果、缺字段或取值不合法：出现带相应代码的待审批请求
- [ ] Session 没有可用模型：不发审查请求，出现带相应代码的待审批请求
- [ ] 失败不重试
- [ ] 失败的审查请求照常记为 purpose `review` 的模型请求（带错误代码）
- [ ] 审批卡在请求带审查信息时显示 Reviewer 的理由，或“自动审查未完成”及按代码本地化的原因；键盘、焦点、“总是允许”与拒绝交互不变
- [ ] 审查理由不出现在发给主模型的任何请求中（集成测试以标记文本断言）
- [ ] 集成测试用测试时钟覆盖超时，用 faux 覆盖报错与非结构化输出
- [ ] gate 的运行时级测试覆盖迟到的审查结果在超时之后到达时不生效
- [ ] renderer 的 Browser Mode 测试覆盖转交理由与各失败原因的显示
- [ ] 中英文文案齐全
