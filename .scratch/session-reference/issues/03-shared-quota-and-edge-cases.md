# 03: 共用额度、其余入口与引用块的善后

**What to build:** 一条消息里混用文件引用与多个会话引用时，它们共用 10 个与 200KB 的额度，超出的各有一行说明。追加指令、首次发送与无界面运行里的会话引用同样生效；引用一个正在运行的会话不被阻塞。回退或分叉到带引用的消息时，回到输入区的只有用户当时输入的文本；带引用的消息被压缩时，摘要请求里不含被引用会话的记录。

**User stories:** 25、35、37、41–43、55–60。

**规格：** [spec.md](../spec.md) 的“上限”中共用额度的部分、“展开”的入口、“已对 File Reference 块做特殊处理的位置”。

**Blocked by:** 02

**Status:** ready-for-agent

- [ ] 文件引用与会话引用按在文本中出现的顺序共用每条消息 10 个的上限；第 11 个及之后的会话引用附一行说明
- [ ] 两者共用合计 200KB 的额度；接近上限的那个会话引用按剩余额度截断，额度用尽后的会话引用附一行说明
- [ ] 范围之外的说明块计入数量上限，不计入字节额度
- [ ] File Reference 已有的说明文本与其现有测试不变
- [ ] 同一个会话在一条消息里只附一次
- [ ] Run 进行中的追加指令、首次发送、无界面运行的提示词中的会话引用按同样的规则展开；首次发送按新建 Session 所属的 Project 判定范围
- [ ] 被引用会话正在运行时，提交不等待，块中只有已提交的条目
- [ ] 先在真实 Sidecar 上确认现状：回退与分叉到带 File Reference 的消息时返回文本是否含引用块（规格的 Further Notes 记有纯函数层面的探针结果），把确认结果写进本票评论
- [ ] 回退与分叉返回的文本不含 File Reference 与 Session Reference 的块，只含用户当时输入的文本；命令消息仍返回原始调用
- [ ] 回到输入区的 `@session:<id>` 再次提交仍然展开
- [ ] 压缩摘要请求的对话序列化把会话引用块缩为一行，写明被引用会话的标题
- [ ] 首条消息的自动标题与由消息文本派生的标题中，`@session:<id>` 以被引用会话的标题显示
- [ ] 逐一核对其他对 File Reference 块做特殊处理或从用户消息提取文本的位置（如 Reviewer 的输入、分叉与交接复制的消息），在本票评论中列出核对过的位置与各自的处理
- [ ] 分叉或交接出的新会话保留消息中已附上的记录
- [ ] 集成测试（真实 Sidecar）：文件与会话混合超过 10 个、合计超过 200KB；追加指令与首次发送中的引用；被引用会话运行中；回退与分叉到带两种引用的消息；带会话引用的消息进入压缩时摘要请求中没有记录正文
- [ ] 当前行为文档同步：上下文管理（共用额度、入口）、命令或 Checkpoint 相关正文中关于返回文本的说明
- [ ] 记录实际运行的检查与未验证项
