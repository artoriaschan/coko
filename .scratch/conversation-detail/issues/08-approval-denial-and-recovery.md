## Acceptance criteria

- [x] 消息区域中的待审批、审批决定、沙箱拒绝、Hook 阻断、无结果和 Outcome Confirmation 使用相同视觉语言并保留真实原因，不能合并成普通失败或成功。
- [x] 整轮与组开合不隐藏关键状态和必要入口；父 Session 与子代理审批冒泡保持原有选择、路由及一次回答语义。
- [x] 既有输入区审批卡、结果确认卡和继续入口保持原布局与操作方式；本票只适配消息区域及其衔接，不扩大为输入区重设计。
- [x] 允许、拒绝、失效请求、暂停、中断与恢复后展示来自真实协议状态；单纯查看详情或 Inspect 不授予权限、不触发再次执行。
- [x] 真实 Sidecar/Electron 的可控场景验证审批允许/拒绝、沙箱/Hook 拦截、子代理审批以及重启后的待确认；核对结果与执行外部事实，不能只依赖模型回复。
- [x] 覆盖键盘回答、卡片接管及焦点恢复，保存正常与窄窗口、双主题下的关键状态对照；记录真实宿主或模型未覆盖的范围。
