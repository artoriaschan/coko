# 02: 完整统计重试与压缩消耗

**What to build:** 用户看到的本轮消耗包含每一次实际模型请求尝试已经报告的用量，包括失败、重试、停止和上下文压缩；重载后不漏计、不重复计数，未取得完整统计时明确表达限制。

**Spec:** [消息底栏与本轮用量规格](../spec.md)

**Spec scenarios:** AC-12、AC-15（计量事实）、AC-18（请求尝试与重放）

**Blocked by:** 01 — 正常请求的真实用量

**Status:** ready-for-agent

**Closed:** true

## Acceptance criteria

- [x] 在 01 已交付的请求归属与完整性契约上，记录每一次真正启动的请求尝试；仅计划但未发出的重试不产生虚构请求，不用相同数值判定两次请求为同一次。
- [x] 失败后重试时，前次已报告的消耗与后次消耗分别保留并各计一次，不只暴露最后一次尝试的 usage；没有报告计数的尝试参与完整性判断，不被当作实测零。
- [x] 工具循环、正常压缩、失败或中止压缩中已报告的消耗进入所属 Run；不能只依赖成功助手消息或成功 compaction 记录判断是否计入。
- [x] 提前取消、断流和失败保留当时已取得的有效计数；持久化中保留已知、未知及不完整状态，不在错误处理时将真实计数清空或以全零替代。
- [x] 当前 Run 的计数不混入其他 Run、标题生成或子 Session；同次请求在消息、追踪、压缩等多个载体出现时仍只计一次。
- [x] 经 Sidecar 协议读回、重新订阅、重启及旧记录混合加载后，已报告消耗与完整性结果一致；新增尝试不会让此前请求重复记账。
- [x] 在 01 已有可见用量入口展示本票的累计结果和完整性；本票不等待 04 的新卡片或 06 的异常底栏布局即可独立演示。
- [x] 用可控的真实适配响应验证失败后重试、部分 usage 后中止、失败压缩以及多种记录共存，核对独立预期计数；同步当前行为文档，记录预算等受影响消费者的相关回归。

## 范围与衔接

保持现有重试准入、次数、取消和压缩策略，不为计量主动增加请求。01 必须实际提供可用契约才能解除阻塞；其仅以 wontfix 关闭不表示本票就绪。最终新底栏消费相同事实，不另造一套汇总算法。

## 验证与回执

以真实 Sidecar、真实持久化和实际用量输出为主；使用可控响应与同步屏障证明异常发生时序，不靠固定 sleep 或盲目重跑。按实际改动运行相关测试、类型及文档检查，分开报告协议回放和真实 Provider 证据。完成后在 Comments 记录结果与限制，再判断是否关闭。
