# 界面约定

项目级技术约定，不代表已有实现或已验证结果；候选、可选和待决项沿用原标注，适用范围与变更规则见 [专项导航](README.md)。新增或修改界面前，先读本页并检查目标页面、相邻页面及 `packages/ui` 中已有的组件和样式；涉及样式、token 或组件几何时，再读 [设计系统规格](ui-design-system.md)。

## 技术接入

React 订阅在 app 层通过 `useSyncExternalStore` 接入；store 模块保持无 React 边界。通用 UI 包以 peerDependencies 声明 react/react-dom，并在 devDependencies 中提供相同版本用于本地测试和构建。

组件统一基于 shadcn/ui，源码纳入仓库并使用本地设计 token；新增组件和现有组件的适配沿用同一套约定。类名合并通过 `extendTailwindMerge` 识别 `text-ui-*` 及项目圆角类，见 [设计系统规格](ui-design-system.md#档位)；ProviderIcon 仅深导入 @lobehub/icons 的 Mono / Color SVG 组件。

消息输入采用 Lexical，编辑区通过 @lexical/react 接入 React，工具栏、菜单和弹层沿用 shadcn/ui。草稿保存 Lexical EditorState JSON，提交时转换为应用协议约定的消息内容；Markdown 导入导出使用 @lexical/markdown。会话消息和静态文档统一通过 Streamdown 展示。lexical 与实际引入的 @lexical/* 包统一精确锁定为 0.52.0。[Lexical React 集成](https://lexical.dev/docs/getting-started/react)、[Lexical 版本元数据](https://registry.npmjs.org/lexical/0.52.0)

## 设计系统

共享设计规则由 `packages/ui` 维护，业务页面消费这些规则。以下是原则；token 分层与命名、圆角档位、材质与边框数值、状态写法及样式守卫见 [设计系统规格](ui-design-system.md)。

- **先复用，再扩展。** 控件统一基于仓库内的 shadcn/ui 组件，通过共享 variant 扩展尺寸、外观和状态；菜单、弹层、Toast、Tooltip、HoverCard、侧栏和工具卡优先复用已有容器与交互。跨页面通用能力放入 `packages/ui`，一次性业务组合留在所属 feature，避免复制一套近似控件。
- **语义 token 是样式入口。** 颜色、字体、字号与行高、间距、圆角、阴影、层级和动效使用共享语义 token，并映射到 Tailwind；业务组件不复制原始色板、不写字面量颜色，也不另建全局主题。明暗主题映射由共享主题统一管理，组件内不散落主题判断。组件局部变量仅用于自身布局，动态行内样式只传递测量值或局部 CSS 变量。
- **保持统一的视觉尺度。** 同类内容使用同一字号与行高，图标与相邻文字保持比例和对齐；业务界面字重不超过 500，通过字号与文字层级区分重点，Markdown 正文排版由共享渲染组件独立管理。
- **先定对齐轴，再调间距。** 复杂布局先确定文字起点、图标列、标题行和分隔线的共同对齐轴，并计入 hover、selected、展开/折叠状态及相邻面板，再调整局部间距。侧栏纵向各行对齐文字起点与前导图标，行的 hover 和 selected 背景与列表上方按钮对齐；列表内容沿同一左边缘对齐，行 hover 背景可以超出该边缘而内容不动；相邻面板的标题首行和次行分别等高对齐，分隔线落在共同水平基线上。元素之间保留有意的间隙，平行元素保持对称；无法解释的单次偏移通常说明遗漏了共享值。
- **按组件角色选择圆角。** 小控件、标准控件、卡片、菜单和主面板使用各自的共享尺寸与圆角变体；不因标签换行、内容增高或状态变化另造圆角。hover、selected、disabled、loading 和 focus 保持外轮廓一致；贴边子元素由外容器统一裁剪，独立子卡片使用自身语义层级。全局使用 superellipse 圆角曲线，圆形头像与胶囊显式使用 `round` 曲线保留圆弧。
- **材质由共享组件统一。** 菜单与浮层沿用同一套背景、透明度、模糊和 elevation token；业务页面不得覆盖菜单材质。若阴影已包含描边，不再叠加中性边框；普通平面卡片和分隔线沿用统一细线，警告、错误等状态边框使用语义色。模态遮罩使用统一半透明暗色，不自行模糊父页面。滚动条由共享样式管理，避免越界或被圆角裁断。
- **局部修复保持局部。** 单个页面的间距、圆角或标题栏避让问题在所属组件或变体中修复，不通过修改全局 token 改变所有页面。确需改变共享设计规则时，在同一变更中检查受影响组件、更新规则及相关预期。
- **图标与文案统一归属。** 图标使用技术栈指定的现有图标库，优先选语义匹配的图标。所有产品文案，包括无障碍名称、Tooltip、placeholder、错误、状态和单位格式，都通过类型化的 zh/en 字典提供；共享组件接收已本地化标签，不内置兜底文案。用户输入、模型输出、协议值和代码内容保持原文，逻辑判断使用稳定 ID 或枚举，不匹配翻译文本。

## 交互、反馈与布局

- **反馈匹配消息生命周期。** 操作成功或失败使用应用级 Toast，Toast 宿主必须比发起操作的页面或弹层活得更久；处理中使用控件状态，不提前报告结果。操作失败保留原数据和用户输入；查询失败、字段校验等持续状态在所属区域提供提示及重试入口。有内容时保留内容并显示紧凑提示，仅无内容时使用完整空状态或错误状态。错误提示优先一句话说清，最多两句；不超过两句的中文提示省略末尾句号。
- **加载和错误不扰乱布局。** 列表使用匹配结构的 skeleton，其余页面级加载使用居中的 spinner，不放在页面角落；同一组件或页面使用一致的加载样式，并行区域不各自闪现不同样式。只有确有必要时显示加载文案，窄侧栏通常不需要。错误使用简短、可行动的用户语言，技术详情放入诊断入口；预留提示空间或采用适当覆盖层，避免无关元素跳动。
- **浮层必须可关闭、放得下、不被裁剪。** 菜单、Popover、Tooltip 和 HoverCard 使用共享 Radix/Floating UI 封装，处理窗口边缘的平移、翻转、可用高度和边距；需要时通过 portal 脱离 overflow 与 containing block。验证外部点击、适用的 Escape、嵌套层级及焦点返回；最上层先消费关闭事件，不能误关背后的对话框。
- **键盘和指针均能完成操作。** 交互控件有正确语义和可访问名称，键盘焦点清晰可见；仅图标操作提供 Tooltip，需要停留、阅读或选择的内容使用 HoverCard。保持对话框焦点约束与关闭后的焦点恢复，输入法组合期间不触发提交或快捷键。动效遵守 reduced-motion 偏好。
- **先重排，再截断。** 窄窗口、侧栏收缩和长文案下优先调整空间分配或换行，再考虑省略文字、仅图标形式或 More 菜单。主要操作、错误和关键状态始终可达；截断内容必须有查看全文的入口。不得通过全局裁剪、统一缩小字号或缩小点击区域掩盖溢出；代码、终端和 diff 中需要保持列对齐的内容使用局部横向滚动。主内容区以 390 CSS px 宽度为验收下限，此宽度及以上不得出现意外重叠、裁剪、整页横向滚动或无法到达的主要操作；低于该宽度可放宽布局要求。
- **截断与仅图标有条件。** 标签页导航、可见选择器、按钮和标签优先单行截断；页面标题优先完整显示，必要时把操作区移到下一行，卡片标题优先自然换行，限制行数时保留查看全文的入口。错误等关键信息不截断，其他位置看不到的重要信息完整显示。控件改为仅图标需同时满足：图标含义清楚或操作为用户熟悉，且 hover 时有 Tooltip；跳转到独立页面的入口不改为仅图标。
- **布局与输入能力分别判断。** 用宽度决定布局断点，用 `hover`、`pointer` 等能力查询决定交互样式，不按 user agent 分支布局，也不把窄窗口等同于触屏。hover 样式限定在 `(hover: hover)`，JS 悬停预览忽略 touch；无 hover 时操作仍可通过可见按钮或明确入口到达。selected、expanded、pressed 和键盘焦点不依赖 hover。调整宽度不重挂载仍可用的控件，保留焦点与草稿。
- **适配实际桌面窗口。** 标题栏、新页面和浮层遵守共享的窗口安全区与拖拽区约定，避免覆盖 macOS 窗口按钮，交互控件不能落入拖拽区。按当前支持平台验证，总偏移同时计入标题栏安全区和页面 inset，评审时写明预期的总偏移；某一页面的偏移问题不得改写全局安全区，在该页面自身的 inset 上以平台作用域覆盖（如 `[data-platform=darwin]`）。

## UI 状态与验收

- **展示与业务状态分层。** 共享 UI 组件接收明确的数据与回调；业务流程、网络和会话状态留在应用层，store 保持 React 无关，通过应用层订阅接入。只订阅组件需要的状态，派生值直接计算，不用 effect 在父子组件或多个 store 间镜像同步。工具卡由协议事件和持久化结果派生，未知工具数据使用通用展示；纯展示状态不混入会话业务记录。
- **保持身份与更新稳定。** 组件定义保持稳定，key 表达真实实体身份；不因流式更新或布局切换无意重挂载子树，导致输入、选区、滚动或展开状态丢失。只有 CSS 无法表达且确有测量需求时才使用布局测量，并说明测量时机与必要性。
- **验证实际渲染结果。** 按 [测试执行规则](testing.md#测试执行与结果报告) 选择最小相关场景，在真实浏览器或 Electron 中检查明暗主题、正常/hover/pressed/selected/disabled/loading/focus 状态，以及适用的窄窗口、长标签、空数据、错误、浮层边缘和键盘路径。检查实际几何、对比度与交互结果，断言不只检查 class 名或复述 CSS 常量；静态 token 检查与 [样式守卫](ui-design-system.md#样式守卫) 不能替代视觉检查。
- **共享变化覆盖消费者。** 修改 token、基础控件或公共布局时，验收代表性消费者，尤其是菜单、对话框、输入区与相邻面板的对齐。确认外观符合意图后再更新快照；报告已检查的主题、状态、窗口范围及尚未验证的部分。

## Markdown 渲染

封装统一的 `MarkdownRenderer`，共享插件配置、标题、链接、图片、表格、代码块组件和明暗主题，组件样式使用现有设计 token。它经 `@coko/ui/markdown` 子路径导出、不在包的聚合入口中，消费方按需懒加载，使 Shiki、Mermaid 与 KaTeX 不进入首屏 chunk。

| 场景 | 配置 |
| --- | --- |
| 流式聊天 | `mode="streaming"`；`isAnimating` 跟随实际生成状态，结束后设为 false |
| 静态文档 | `mode="static"`；按完整 Markdown 渲染，关闭流式分块和未闭合语法补全 |

两种模式共用 code、math、mermaid 和 cjk 插件。静态文档的目录与标题锚点通过 remark / rehype 扩展按需接入；新增扩展时再声明精确版本。Markdown 渲染直接接收应用维护的文本与生成状态，接入 pi-agent-core 的消息协议。[Streamdown 模式与插件用法](https://streamdown.ai/docs/usage)、[配置与扩展](https://streamdown.ai/docs/configuration)

Tailwind CSS 4 的 `@source` 覆盖 Streamdown 及已启用插件的分发文件，路径按 workspace 布局配置；数学公式样式从锁定的 `katex/dist/katex.min.css` 导入。[样式接入](https://streamdown.ai/docs/getting-started)

字体优先使用本机 Noto Sans SC 和 JetBrains Mono，缺失时回退系统字体，不额外打包或请求字体文件。
