## Acceptance criteria

- [ ] 先核对每个前置票实际交付其要求的能力，保留各票有效证据；不能仅凭 Closed 字段或代理汇报认定依赖已完成。
- [ ] 为 AC-01—AC-25 建立最终覆盖清单，标明负责票、实际场景、对象版本、命令/操作、选中数量、结果及证据；源代码或基线变化后只复用仍有效的证据。
- [ ] 在相同环境以脱敏等价内容对照锁定参考版本，覆盖用户消息、阶段/最终回复、思考、运行平铺、整轮收起、历史组展开及所有适用的专用工具详情，逐项核对几何、字体、图标、颜色、材质和状态。
- [ ] 联合验证流式提交、终端/文件/图片正文的高度变化、分组与三级折叠、历史加载、阅读暂停、键盘焦点及 reduced-motion；静态截图不能替代交互结果。
- [ ] 验证审批/恢复、Plan/Goal/Job、子代理/团队/定时/Handoff、历史回退与只读同新结构组合后有效；复用真实 Sidecar/Electron 入口核对外部事实。
- [ ] 覆盖明暗主题、zh/en、正常和 390 CSS px 主内容宽度、长路径/代码/错误、空数据及失败；检查顶部栏、输入框、侧栏、右栏子 Session 及受共享样式影响的消费者。
- [ ] 运行当前改动所需的最小相关检查及类型、文档门禁，列出精确命令、退出码与实际数量；零选中或全部跳过不算通过，不把局部结果表述为全仓或 CI 通过。
- [ ] 完成独立 Standards 与 Spec 评审，处理实际发现并重验失效证据；不以未解释的视觉差异、未验证状态或未解决缺陷结束为完整复刻通过。
- [ ] 同步当前行为正文、导航和本功能实施状态，保留各票历史证据，正式文档不反向依赖具体任务材料；未完整验收前不将整份规格标为 delivered。
- [ ] 核对并关闭本次创建的 CDP 会话、测试应用与其他资源，等待实际退出；不按目录批量停止无关进程，不删除其他工作树或用户数据。
- [ ] 最终报告区分本地保存、提交、推送、CI、合并与发布，以及真实模型、原生指针/窗口层、系统字体等限制；自动化或人工验收缺口存在时如实列出，不声称已完整验证。

## 范围与衔接

仅等待 04—12 的实际能力；01、02、03 已由依赖链覆盖。各前票仍须各自测试、视觉检查并更新所属文档，本票负责最终对象版本的组合验收和遗漏收敛，不承接前票故意延期的基本验证。

规格锁定的参考提交、Coko 数据边界与非目标持续适用。不得修改数据库、协议和既有执行授权来凑齐展示数据，也不得用全局样式变化影响范围外页面。每票按实际变更更新所属当前行为文档；长期文档不反向链接本票。

## 验证与回执

- 采用规格的真实 App 装配入口及本票要求的现有 Sidecar/Electron 入口；纯函数测试只补充边界，不代替用户可见路径。
- 按当前实际改动选择相关测试，运行类型和文档检查；保留精确命令、实际数量、退出码、参考/当前对象版本、主题/语言/尺寸及可访问证据。只更新失效证据，不用盲目重试、固定 sleep 或放宽断言制造通过。
- 视觉与交互默认静默 agent-browser/CDP。获取资源后登记清理，结束时等待所属会话和进程实际退出，保留无关运行实例与用户数据。
- 完成后在 Comments 追加实施、验证、文档影响和实际交付状态；仍有必要验收缺口时如实记录，不提前关闭。不因前置票以 wontfix 关闭就自动认定阻塞解除。
