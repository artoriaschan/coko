# 02: 提交 `@session:<id>` 时附上会话的文字记录

**What to build:** 用户提交的文本里写有 `@session:<id>`（此时还没有菜单，手写即可），且它指向同一 Project 的另一个根 Session 时，模型在这条消息里同时看到那次会话的文字记录：用户说过的话与助手的文字回复，压缩过的以摘要打头。范围之外的会话只得到一行说明，不存在的会话不影响提交。本票交付单个引用的完整路径；多个引用的额度、其余入口与边角在 03。

**User stories:** 28–36、38–40、44–48、62。

**规格：** [spec.md](../spec.md) 的“Session Reference 的语法”“展开”“上限”中单个引用的部分、“范围与失效”。

**Blocked by:** None（可立即开始）

**Status:** ready-for-agent

- [ ] 术语表新增 Session Reference 词条，文字按规格的“文档与术语”
- [ ] `@session:<id>` 按 File Reference 的词首规则与结尾标点规则识别；`@session:` 前缀的 token 不再作为文件路径解析，其他 `@` token 的解析不变
- [ ] 展开与 File Reference 在同一步骤，位于命令展开之后；引用在同一条 user message 中追加一个 `<session_reference id="…" title="…">` 文本块，原文在块之前；没有新的条目 kind 与条目版本
- [ ] 记录取被引用会话的有效上下文：被回退的消息不出现；有有效 Compaction 时以摘要打头，摘要之前的消息不出现
- [ ] 用户消息只取用户提交的文本：State Update、File Reference 与 Session Reference 的块、附件块、图片不进入记录
- [ ] 由命令展开的用户消息以原始调用 `/name 参数` 出现，判定方式与回退恢复原始调用相同
- [ ] 助手消息只取文字回复；思考、工具调用、工具结果不进入记录
- [ ] 记录中的 `@session:<id>` 与 `@path` 不再展开
- [ ] 单个引用不超过 50KB：超出时保留摘要与最近的消息，从摘要之后最早的消息开始省略并注明条数；摘要自身放不下时截断并注明
- [ ] 没有可附内容的会话，块中写明没有消息
- [ ] 范围由 Sidecar 在展开时判定：同一 Project 的根 Session（含 Worktree Session 与已归档的）附上记录；当前会话不属于任何 Project 时，范围为其他不属于任何 Project 的根 Session
- [ ] 另一个 Project 的会话、当前会话自己、子代理的会话：各附一行 `[Not attached: …]` 说明，块中没有对方的任何内容
- [ ] id 不存在或会话已删除：不产生块，文本原样保留，提交照常被接受
- [ ] 块在生成时替换已登记的 Secret 与 Credential 明文；用户输入的原文不变
- [ ] 引用日志含会话引用的数量、各状态的数量与截断数，不含 id、标题与内容
- [ ] 纯函数测试：token 的解析规则；记录序列化对各类消息的取舍；截断时摘要保留、省略条数正确
- [ ] 集成测试（真实 Sidecar，faux 请求明细日志）：两轮对话的会话被引用后，请求中有其用户文本与助手文字，没有工具调用与工具结果中的标记文本；压缩过、回退过、命令消息、超过 50KB、三种范围之外、不存在的 id 各一条
- [ ] Secret 的集成测试沿用现有 secrets gate 的写法，断言块中没有登记明文
- [ ] File Reference 的现有集成测试继续通过，其说明文本不变
- [ ] 当前行为文档同步：上下文管理新增 Session Reference 的语法、展开、单个上限与范围
- [ ] 记录实际运行的检查与未验证项
