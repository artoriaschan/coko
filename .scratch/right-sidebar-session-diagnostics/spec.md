# 右栏与会话数据诊断规格

Status: ready-for-agent

## 来源、确认与实施状态

本规格按 `to-spec` 汇总 2026-11-04 本会话中经 `grill-me` 确认的需求。Q1—Q21 中用户改了一项：Q6 改为合成一个需求、一份规格，在实施票里先做右栏、再做会话数据诊断。其余采用推荐。Q8 更正了第一轮的叫法：已批准的标题栏规格已经把右栏开关定为“打开侧边栏”。Q19、Q20 是对照 Coko 界面约定补充的两条规则。Q21 是 `to-spec` 第 2 步要求核对的测试接缝。产品需求因此为 `approved`。当前实施状态为 **未实施**；实施进度与证据记入各实施票的 Comments 和本文。

本需求在已批准的[对话状态栏与标题栏规格](../conversation-status-and-header/spec.md)全部交付之后实施，以交付后的标题栏为基线（Q14）。界面布局、交互与文案参考 DeepSeek Harness 的右侧 Sidebar 与“会话数据诊断”。视觉使用 Coko 的组件、语义 token、图标和共享浮层组件；视觉稿 [双栏布局.pen](../../docs/ui/双栏布局.pen) 本次不修改（Q4、Q5）。既有约束见[术语表](../../GLOSSARY.md)、[界面约定](../../docs/tech-stack/ui.md)、[设计系统规格](../../docs/tech-stack/ui-design-system.md)、[测试约定](../../docs/tech-stack/testing.md)、[tracker 协议](../../docs/agents/issue-tracker.md)和[开发流程](../../docs/DEVELOPMENT_WORKFLOW.md)。

在本文的修订范围内，本次确认优先于以下内容：[工作台](../../docs/subsystems/workbench.md)、[Plan Mode](../../docs/subsystems/plan-mode.md)、[后台任务](../../docs/subsystems/jobs.md)、[子代理](../../docs/subsystems/subagents.md)、[Agent Teams](../../docs/subsystems/teams.md)、[定时任务](../../docs/subsystems/schedules.md)、[追踪](../../docs/subsystems/tracing.md)中关于右栏的当前行为说明；标题栏规格中 HEAD-01“右栏头部与标题行同为 48px”和 HEAD-06“右栏自带的 X”两项约定。右栏中现有页面的内容仍按各自的子系统说明执行。任务材料不加入正式文档导航。

**叫法。** 界面文案把右侧面板叫“侧边栏”，与 HEAD-06 一致；本文、正式文档和代码仍叫“右栏”；左侧列表仍叫“侧栏”（Q8）。

## Problem Statement

右栏现在是固定的六个 tab，不能关闭、排序或拖宽。选中哪个 tab 只存在内存里，整个窗口共用一个值：切换 Session 时不跟随，应用重启后也不保留。窗口变窄时右栏会覆盖在中栏上。展开右栏用标题栏的“打开侧边栏”，收起却用右栏头部自带的 X，是两套开关。参考实现 DeepSeek Harness 的右侧 Sidebar 是另一种做法：每个 Session 有一组自己的 tab，从引导页按需打开，可以关闭和排序；宽度可以拖拽；空间不够时收起，窗口很窄时自动全屏；重启后恢复。

开发 Coko 的人排查 Agent 的行为时，界面上看不到当前 Session 的原始数据。Trace tab 只给出每个 Run 的汇总；导出的 ndjson 只能离线阅读，看不到流式增量，也对不上时间线上的位置。时间线上的过程分组、工具卡和思考块由哪些条目投影而来、投影出什么结构，现在只能读代码才知道。

## Solution

右栏改为 DeepSeek Harness 式的单格 tab 容器，Coko 现有的六个页面迁入其中，内容不变。另外新增一个默认关闭的开发者页面“会话数据诊断”：用“原始数据”和“对话分组”两种形式展示当前 Session 的数据，并与主时间线互相定位。

### 右栏容器与 tab

| 编号 | 已确认行为 |
| --- | --- |
| RP-01 | 右栏是单格 tab 容器，承载六个页面：计划、后台任务、子代理、定时任务、团队、追踪。诊断开关打开时，再加上“会话数据诊断”页。另有引导页“开始”。六个页面的内容与行为保持现状，只换容器。不做分栏和浮窗（Q1、Q9、Q10）。 |
| RP-02 | tab 按 Session 区分。每个 Session 有自己的 tab 列表、顺序、选中项、展开状态和全屏状态，切换 Session 时右栏显示该 Session 自己的状态。没有选中 Session 时不显示右栏和它的开关，包括新对话页、插件页和定时任务内容页（Q11）。 |
| RP-03 | 右栏展开时，如果该 Session 还没有 tab，就打开引导页“开始”。从入口直接打开某个页面时，展开后只显示这个页面，旁边不补引导页（Q11）。 |
| RP-04 | 一种页面在一个 Session 中最多开一个 tab，再次打开时聚焦已有的那个。从任何入口打开页面时，右栏都会展开并选中该页面。如果被打开的 tab 本来就显示在屏幕上，它所在的格向内发光约 600ms。需要切到后台 tab 或展开右栏时不发光，因为这一变化本身已经可见。系统要求减少动态效果时，发光在同样时长内保持，不淡出。 |
| RP-05 | 引导页“开始”居中排列各页面的入口卡片，顺序与 RP-01 相同，诊断页排在最后。卡片超过四张，因此只显示图标和标题，不显示描述。点击卡片后，引导页原位换成被打开的页面。一个格最多只有一个引导页。tab 条上的“+”只在没有引导页时显示，点击后在本格打开引导页。引导页列出全部六个页面：定时任务页是新建定时任务的唯一入口，追踪页除了“查看”也没有别的入口（Q11）。 |
| RP-06 | tab 条就是右栏的上沿，没有标题行。从左到右依次是：带关闭按钮的 tab 胶囊、“+”，最右侧是“收起侧边栏”和“全屏”两个按钮。tab 多到放不下时，tab 条横向滚动，不显示滚动条，两端渐隐。只有胶囊让出空间，后面的按钮不收缩、不被裁切。单个标题过长时单行截断，截断后用 Tooltip 显示全文（Q20）。tab 标题跟随当前界面语言。tab 条的高度、胶囊的几何与对齐按 DeepSeek Harness 的实际尺寸，必要时取代 HEAD-01 中右栏头部为 48px 的约定。tab 条遵守窗口拖拽区约定：空白处可以拖动窗口，交互控件退出拖拽区（Q12）。 |
| RP-07 | 关闭页面的方式有：tab 的关闭按钮、中键，以及右键菜单的“关闭”“关闭其他标签页”“关闭右侧标签页”。批量关闭只作用于本格内的 tab。没有撤销关闭。引导页是唯一的 tab 时：没有关闭按钮，中键无效，右键不弹出菜单。其他页面作为唯一的 tab 被关闭时，右栏整栏收起，下次展开时显示引导页（Q11）。 |
| RP-08 | 可以在 tab 条内拖拽 tab 调整顺序。焦点在 tab 上时，也可以用键盘把它左移或右移（Q19）。具体按键在 design 阶段确定，不与“方向键在 tab 之间移动焦点”冲突。 |
| RP-09 | 右栏展开时，用 tab 条末端的“收起侧边栏”收起，取代原来头部的 X，Tooltip 与可访问名称沿用 HEAD-06。右栏收起时，标题栏的“打开侧边栏”是展开的入口（Q12）。 |
| RP-10 | tab 条末端的按钮在“全屏”和“退出全屏”之间切换。全屏面板覆盖整个窗口，底层的列宽保持不变。普通形态与全屏形态共用同一棵内容树，切换时页面不重新挂载。宽度拖拽区只在普通形态显示。全屏面板遵守窗口安全区与拖拽区约定（Q12）。 |

### 宽度、窄窗口与全屏

| 编号 | 已确认行为 |
| --- | --- |
| RP-11 | 右栏左缘有分隔条：可以拖动，也可以聚焦后用方向键、Home、End 调整，键盘步长与左侧栏分隔条相同。首次打开时宽度为帧宽的 45%，下限 300px，上限为帧宽的 70%，中栏至少保留 400px。宽度偏好整个窗口共用一份，只记在内存里，不保存；重新加载应用后回到 45%（Q12、Q13）。 |
| RP-12 | 空间不够时，左侧栏不为右栏让位：右栏先缩到 300px，仍然不够就整栏收起，不再覆盖中栏。原来覆盖中栏的形态删除。整栏收起会写入该 Session 的展开状态，窗口变宽后不会自动重新打开（Q12）。 |
| RP-13 | 帧宽小于 768px 时，打开右栏会自动全屏，不占普通列宽。在这种窄窗口下退出全屏，右栏随之收起；窗口变宽后不会自动重新打开已经关闭的右栏（Q12）。窗口最小宽度为 520px，所以这条规则在实际窗口中会出现。 |

### 保存、快捷键与入口

| 编号 | 已确认行为 |
| --- | --- |
| RP-14 | 按 Session 把 tab 列表、顺序、选中项、展开状态和全屏状态存入 localStorage。重启或重新加载后，在渲染页面内容之前恢复。读回时校验字段类型与成员关系，不合格时只清除对应 Session 的记录；存储失败时，当前布局仍可在内存中使用。恢复时移除当前不可用的页面类型，例如开关关闭后的诊断页。页面内部的选择照旧不保存，例如子代理页里选中的子代理（Q13）。 |
| RP-15 | Mod+Alt+B 展开或收起右栏，没有选中 Session 时无效。焦点在右栏内时：Mod+Alt+Enter 切换全屏；Mod+W 关闭当前页面。关闭唯一的引导页时，右栏收起，引导页保留。关闭后焦点移到同一 Session 中仍然可见的右栏页面，连续按 Mod+W 仍作用于右栏。焦点不在右栏页面时，Mod+W 保持关闭窗口的原有行为。前台有弹窗、菜单或对话框时，由它们先处理关闭，它们拒绝时右栏和窗口都不关闭。输入法组合输入期间不响应这些快捷键。按钮标出有效的键位。不做“刷新页面”和“分栏”的快捷键（Q13）。 |
| RP-16 | 以下入口都改为“打开或聚焦对应页面，必要时展开右栏”：会话标题栏的后台任务、子代理、定时任务、团队四个按钮；工具卡和子代理卡的“查看”；计划卡与计划审阅卡的“在侧边栏查看”；Job chip 与后台任务通知行；子代理通知行；设置中定时任务的“打开会话”。计划审阅的新请求仍然按 requestId 自动打开一次计划页（Q11）。 |
| RP-17 | tab 条按 WAI-ARIA tabs 的手动激活模式工作。用快捷键打开页面或展开右栏后，焦点移到右栏的活动页面。用快捷键关闭页面后，焦点按 RP-15 移动。右栏收起后，焦点回到标题栏的“打开侧边栏”。分隔条有 separator 语义和可访问名称，按钮有可访问名称和 `aria-keyshortcuts`。 |
| RP-18 | 右栏新增的文案照搬 DeepSeek Harness 的中文原文并配英文，包括：新标签页、开始、打开侧边栏、收起侧边栏、全屏、退出全屏、关闭其他标签页、关闭右侧标签页、展开／收起右侧栏、请先选择会话。界面上已有的、指右侧面板的“右栏”文案改为“侧边栏”，例如“在右栏查看”改为“在侧边栏查看”。不引入分栏、浮窗相关的文案（Q8）。 |

### 开发者开关

| 编号 | 已确认行为 |
| --- | --- |
| DEV-01 | 设置 → 通用里新增一张“开发者”卡片，只有一个开关“会话数据诊断”。说明文字为“在侧边栏启用当前会话的原始数据和对话分组数据分析功能”。开关默认关闭；全局生效，不区分项目；发布构建也可以打开。开关经 Sidecar 设置库保存，重启后保持（Q2、Q7）。 |
| DEV-02 | 打开开关后，各 Session 的引导页末尾出现“会话数据诊断”卡片，但不自动打开诊断页。关闭开关后，所有 Session 中已经打开的诊断页一起关闭：诊断页是唯一的 tab 时，按 RP-07 收起右栏；引导页不再列出它；恢复已保存的布局时也移除诊断页（Q7）。 |

### 会话数据诊断：通用部分

| 编号 | 已确认行为 |
| --- | --- |
| INS-01 | 页面标题为“会话数据诊断”。只检查主区当前的 Session，不含子代理的子 Session。没有输入框，只读，不改变 Session 数据。在归档 Session 和 worktree 已移除的只读 Session 中同样可用（Q3、Q15）。 |
| INS-02 | 工具栏左上角是“展示形式”下拉框（“原始数据”或“对话分组”），旁边是瞄准按钮。另一侧是当前行数，筛选时显示“匹配数 / 总数”，以及“跟踪最新”。不提供“加载更早”：Coko 打开 Session 时已经补发全部历史（Q15）。切换展示形式时，重置选中、筛选、折叠与滚动。没有记录时显示“暂无记录”。 |
| INS-03 | 表格的列依次为：序号、类型（表头带筛选图标）、Run、时间（UTC，只在原始数据中显示）、数据。Run 列是该行所属 Run 在 Session 内的序号，从 1 开始，不属于任何 Run 时为空。数据列是横向摘要：省略已有独立列展示的字段；只剩一个字段时只显示值；最多 240 个字符。行高固定，表格虚拟化。序号列较窄，悬停或聚焦时用 Tooltip 显示完整值。时间显示到毫秒（`HH:mm:ss.SSS`），即 Sidecar 提交条目的时间。实时增量行没有时间戳，时间列留空。 |
| INS-04 | 有子行的行可以展开或收起。父级行按嵌套层次依次吸顶在表头下方，使用不透底的主题底色。手动展开或收起时，被点击的组头保持在原来的屏幕位置，并暂停跟随。 |
| INS-05 | 表格在离底部 40px 以内时跟随新行。向上滚动或手动折叠后暂停跟随。新行先填进尾部留白，填满后恢复正常跟随。“跟踪最新”清除留白并恢复跟随。 |
| INS-06 | 点击类型列表头的筛选图标，打开编辑浮层：浮层跟随表头按钮定位，定位后聚焦输入框。候选从所有已加载的行中异步更新。按 Enter 或“确认筛选”时确认输入的片段；点击候选，或用方向键选中候选后按 Enter，则确认该类型。匹配不区分大小写，默认为包含匹配，首尾的 `*` 写不写都一样。只编辑不会改变表格；按 Esc、点击取消或点击外部放弃草稿；清空后确认则恢复全部类型。筛选后保留匹配行和它们的父级上下文：上下文行显示为淡色，强制展开，不计入匹配数。新增的行沿用已确认的筛选。确认后重置选中、手动折叠与尾部留白，并回到顶部。沿引用导航或瞄准选取时，如果目标行被筛选排除，先清除筛选再定位。 |
| INS-07 | 在对话分组中，新增和更新的行用约 700ms 的背景淡出高亮。原始数据的行只在被定位时闪烁。系统要求减少动态效果时不播放这些动画。 |
| INS-08 | 选中行后，在表格下方打开详情面板。面板默认占 40% 高度，可以拖动上边缘的分隔条，或用方向键、Home、End 在 15%～80% 之间调整；切换记录时保留高度。记录无法序列化时，只在面板内显示“无法序列化这条记录，可以选择其他记录继续查看。”，不影响表格。记录已经移除时，提示“该记录已移除或结算，请选择当前记录。”。 |
| INS-09 | 选中一行时，定位到主区时间线：展开目标所在的折叠层，平滑滚动到目标后闪烁一次。高亮画在覆盖层上，不往时间线里添加元素。目标本来可见时只闪烁。系统要求减少动态效果时，立即滚动，不闪烁。找不到精确目标时，依次尝试同一 Run 中附近的内容、其他已加载 Run 中的内容；都没有可呈现的候选时，高亮当前可见的时间线列，不移动它。定位不切换页面，也不切换 Session（Q16）。 |
| INS-10 | 瞄准按钮在主区时间线上覆盖一层透明蒙层，拦截点击。悬停时预览，点击后选中当前展示形式中对应的记录，展开它的表格祖先并打开详情；底下的时间线控件不会被激活。滚轮操作转给时间线的滚动区域。没有匹配的记录时，提示“当前表格没有匹配记录，请选择其他元素或按 Esc 取消。”，并继续等待选取。以下情况取消选取：按 Esc、再次点击瞄准按钮、切换展示形式或 Session、隐藏或关闭诊断页、窗口失焦。同一时刻只有一个选取器有效。匹配只依据时间线元素上的身份属性，不比较文本相似度（Q16）。 |

### 会话数据诊断：原始数据

| 编号 | 已确认行为 |
| --- | --- |
| INS-11 | 每行是一条已加载的 Session Entry：序号为 seq；类型为 kind，message 条目附上角色，例如 `message/assistant`；时间为 createdAt；数据为 payload 的摘要。详情是完整的 JSON：默认全部展开，可以逐层收起；保留 `[Circular]` 标记，大整数显示为可读的字符串。读回时被跳过的条目（seq 有空缺）不显示，也不补造（Q15）。 |
| INS-12 | 同一 Run 的条目组成一组：`run_start` 作为吸顶组头，组内其余条目按 seq 排列，组在表格中的位置以组头的 seq 为准。组结束后仍保持展开，可以手动收起。缺少 `run_start` 的条目不伪造组头，作为根行显示。不属于任何 Run 的条目也是根行，按 seq 排在各组之间。Coko 没有 step 级的起止记录，所以只有一层分组（Q15）。 |
| INS-13 | 诊断页打开期间，收到的、属于 Run 的进度作为子行，挂在该 Run 组末尾的“实时进度”行下，按到达顺序排列。`assistant_delta` 按内容块分组；`tool_start`、`tool_update`、`tool_end` 按 toolCallId 分组。生成中的组展开。收起的思考块显示拼接后的思考文本，收起的工具参数块显示拼接后的参数片段，长度沿用摘要上限。对应的条目提交后，已经匹配的增量转到该条目下，并收起；没有匹配上的增量留在“实时进度”行下。增量子行只保存在诊断页的内存中：在同一 Session 内切换 tab 时保留；切换 Session、关闭诊断页或重新加载后清空。诊断页打开前收到的增量，以及历史 Run 的增量都不显示，因为 Coko 不保存增量。不属于 Run 的进度不在这里显示，包括后台任务、子代理、定时任务、团队和代码智能的更新（Q15）。 |

### 会话数据诊断：对话分组

| 编号 | 已确认行为 |
| --- | --- |
| INS-14 | 行对应主时间线的展示投影：同一个 Run 中相邻的工具调用与非空的思考组成过程分组，作为组行，成员放在它下面；其他时间线行作为根行，按时间线顺序排列。时间线上不单独成行的项（排队中的追加指令、后台任务的起止）不出现。序号是投影身份；类型是过程分组或时间线行的种类；Run 是所属 Run 的序号；不显示时间列（Q16）。 |
| INS-15 | 选中行后，详情用对象树显示该行在当前投影中的值，按需展开，不转换为 JSON。集合分批展开，getter 只显示标记、不执行，循环引用显示祖先路径。Run、过程分组、时间线行和来源 Session Entry 都提供引用按钮。点击引用，打开它当前的值并增加一级面包屑；点击前面的面包屑，返回到该级。第一级始终保留最初选中的行。引用有对应的表格行时，展开它的父级组，滚动定位并闪烁该行，同时按 INS-09 定位到时间线。选择表格行或从时间线选取元素，都会开始一条新路径。展开过的字段一直保留到投影下一次发布（Q16）。 |

## User Stories

1. 作为 Coko 用户，我希望每个 Session 的右栏有自己的一组 tab，以便切换 Session 时看到这个 Session 之前打开的页面。
2. 作为 Coko 用户，我希望第一次打开右栏时看到引导页“开始”，以便知道右栏里有哪些页面。
3. 作为 Coko 用户，我希望在引导页点击卡片后，引导页原位换成这个页面，以便不留下多余的 tab。
4. 作为 Coko 用户，我希望用 tab 条上的“+”重新打开引导页，以便打开当前没有显示的页面。
5. 作为 Coko 用户，我希望同一种页面只开一个 tab，再次打开时聚焦已有的那个，以便右栏不出现重复的页面。
6. 作为 Coko 用户，我希望已经显示在屏幕上的页面被再次打开时发光提示，以便知道打开的是哪一个。
7. 作为 Coko 用户，我希望用关闭按钮、中键或右键菜单关闭页面，以便右栏只留下需要的内容。
8. 作为 Coko 用户，我希望右键菜单提供“关闭其他标签页”和“关闭右侧标签页”，以便一次清理多个页面。
9. 作为 Coko 用户，我希望关闭最后一个页面时右栏直接收起，下次展开时回到引导页，以便展开后看到的不是空白。
10. 作为 Coko 用户，我希望拖拽 tab 调整顺序，以便常用的页面排在前面。
11. 作为键盘用户，我希望用键盘把 tab 左移或右移，以便不用鼠标也能排序。

15. 作为键盘用户，我希望聚焦分隔条后用方向键、Home、End 调整右栏宽度，以便不用拖拽也能调整。
16. 作为 Coko 用户，我希望窗口变窄时右栏先缩到最小宽度，再不够就收起，而不是盖住对话，以便对话区始终能读。

## Implementation Decisions

标注“工程决定”的条目是 Agent 在授权范围内做出的实现选择，不是用户确认的产品决定；其余条目来自 Q1—Q21 的确认。

### 右栏容器

- **按 Session 的布局 store。** 新的右栏布局 store 按 Session 保存 tab 列表、顺序、选中项、展开状态和形态（普通或全屏），本身不依赖 React，只在 app 层订阅。所有改动都经过同一组动作：打开或聚焦、关闭、批量关闭、移动、选择、展开或收起、切换形态。单例去重、引导页规则和“唯一 tab”规则都集中在这组动作里，页面和入口不直接改写布局。不提供撤销，也不记录历史，因为没有对应的产品控件。
- **页面类型登记表。** 沿用现有的静态登记表。每种页面声明 id、标题的字典键、图标、正文组件和可用条件；诊断页的可用条件是开关已打开。页面正文仍然只接收当前 Session 的 id，现有六个页面组件不改。新增页面只在登记表里加一行，不引入插件式的运行时注册。
- **统一入口。** 去掉现有的、整个窗口共用的“选中 tab”store，改由右栏布局 store 提供“按 Session 打开或聚焦某个页面”的动作，RP-16 列出的所有入口都调用它。各 store 现有的“请求打开”计数可以保留，作为调用这个动作的触发来源。
- **（工程决定）tab 标题跟随语言。** tab 标题在每次渲染时从字典读取，不在打开时固定。DeepSeek Harness 在打开时固定标题，是因为它的标题来自资源地址；Coko 的标题都来自字典。
- **布局保存。** 每个 Session 在 localStorage 中占一个键，内容是 tab 的种类与顺序、选中项、展开状态和形态。读回时用 typebox 校验。在渲染页面正文之前完成恢复；校验失败只清除该 Session 的键；写入失败只记录日志，不影响内存中的布局。这些是界面的显示状态，不是用户数据，所以沿用列表 store 已有的 localStorage 做法，不放进 Sidecar 设置库。
- **（工程决定）删除 Session 时清理。** Session 被永久删除后，同时清除它的布局键，避免 localStorage 无限增长。
- **三栏几何。** 右栏宽度按 DeepSeek Harness 的列宽算法计算：左侧栏不为右栏让位；右栏在 300px 与帧宽的 70% 之间取偏好值，并保证中栏不少于 400px；放不下 300px 时取消右栏，并整栏收起。删除现有的“右栏覆盖中栏”形态和“侧栏为右栏收起”的让位步骤。帧宽小于 768px 时自动全屏：全屏面板覆盖整个窗口，底层列宽保持不变。
- **AppFrame 的右栏分隔条与全屏。** 新增右栏分隔条，拖动与键盘交互与左侧栏分隔条相同，只在普通展开形态显示。右栏宽度偏好由 App 保存在内存中，传给布局计算。全屏面板与普通面板共用同一棵内容树，切换时不重新挂载。
- **快捷键。** Mod+Alt+B 和 Mod+Alt+Enter 放进 renderer 现有的全局快捷键处理，遵守输入法组合输入与前台弹层的现有约束。Mod+W 需要 main 配合：Coko 现在没有自定义应用菜单，Electron 默认菜单里的“关闭窗口”会先截获 Mod+W。改为由 renderer 根据焦点决定关闭当前页面还是关闭窗口，其余默认菜单项（编辑、视图等）保持原样。用自定义菜单还是拦截输入事件，在 design 阶段决定。
- **共享组件。** tab 条（胶囊、关闭按钮、溢出滚动与渐隐、右键菜单、键盘排序）和引导页的卡片作为 `packages/ui` 的共享组件，只接收已经本地化的文案；业务组装放在 desktop renderer。样式使用 Tailwind 与语义 token，几何参照 DeepSeek Harness 的实际尺寸，不新增全局 token；确实需要新的几何 token 时，在 design 中单独说明。

### 开发者开关

- **新的设置键。** 新增全局设置键 `developer`，值为 `{ sessionDiagnostics: boolean }`，缺省为 false。读写方式与 theme、locale 相同：renderer 经现有的设置接口读写，Sidecar 不读取它，不改协议消息，也不改服务端。schema 与缺省值放在协议包中，与 notifications 设置相同；renderer 读到不符合 schema 的值时按缺省处理。

### 会话数据诊断

- **独立的功能模块。** 诊断页是 desktop renderer 中一个独立的功能模块，包括：表格模型（深度优先的扁平行数组，每行有 key、parent、depth 和展开状态）、吸顶与跟随布局、类型筛选、摘要格式、详情面板、对象树与 JSON 树，以及两种展示形式各自的数据模型。界面使用 Coko 的组件、浮层与字典。
- **原始数据的来源。** 读取 chat-store 中当前 Session 已经加载的条目，不新增请求。实时增量复用 chat-store 现有的 progress 订阅：它在 store 处理完每一帧之后转发已打开会话的全部进度。诊断页按 Session 过滤，并排除不属于 Run 的进度。chat-store 不需要改动。诊断的数据模型自己维护增量子行，它的生命周期跟随“该 Session 的诊断页处于打开状态”，而不跟随正文组件的挂载，因此在同一 Session 内切换 tab 时不丢失。
- **增量与条目的匹配。** `assistant_delta` 按 contentIndex 归入同一 Run 中下一条提交的 assistant message；`tool_start`、`tool_update`、`tool_end` 按 toolCallId 归入对应的工具结果；压缩相关的进度归入对应的 compaction 条目；其余进度和没有匹配上的增量，留在该 Run 的“实时进度”行下。提交与匹配的判定时机，在 design 阶段按 chat-store 处理条目与进度的顺序确定。
- **共享的展示投影。** 过程分组的 id 依赖上一次的计算结果，显示身份也由视图持有，所以诊断页不能自己另算一份，否则身份会和时间线对不上。主时间线每次提交后，把它算出的投影（时间线行、显示身份、过程分组、Run）发布到按 Session 区分的发布点，诊断页订阅这个发布点；主时间线的计算方式不变。只有该 Session 的主时间线已经挂载时，诊断页才收得到数据，这与 INS-01“只检查主区当前的 Session”一致。
- **主时间线的定位接口。** 时间线的行、过程分组和工具卡上暴露诊断用的身份属性：时间线行身份、过程分组 id、Run id、条目 seq 和工具调用 id。时间线另外提供“展开到某个身份”的入口，诊断页用它展开过程分组、详情等折叠层。高亮和瞄准蒙层画在 body 层的覆盖层上，不往时间线中加内容。属性名在 design 阶段确定。
- **虚拟列表。** 按[技术栈](../../docs/TECH_STACK.md)选定的版本安装 `@tanstack/react-virtual`。行高固定，自定义渲染范围，把吸顶行包含进去。DeepSeek Harness 用到的滚动锚定选项在选定版本中是否可用，在 design 阶段核实；不可用时改用等价的滚动锚定方式。

## Testing Decisions

### 原则与接缝

只断言外部事实，包括：渲染出的文字与可访问名称、实际几何、焦点位置、从 localStorage 和设置中读回的值、窗口是否关闭，以及时间线上被定位的元素。不用 class 名、内部函数的调用次数或 Agent 声称完成来代替。只有模型服务、外部网络和时钟使用可控替身；store、展示投影、诊断数据模型和布局计算都用真实实现。

测试接缝为 Q21 确认的四类入口：

1. **真实 App 的 Browser Mode 测试（主接缝）。** 装配方式照 [App 浏览器测试](../../apps/desktop/src/renderer/app/app.browser.test.tsx)与[对话联合浏览器测试](../../apps/desktop/src/renderer/features/conversation/integrated-detail.browser.test.tsx)：使用真实 store，用 fixture 回放条目和进度。覆盖 RP-01—RP-18 中除 Mod+W 以外的行为，DEV-01—02，INS-01—INS-16，SEC-01，以及 390 CSS px、明暗主题与 zh/en。几何与让位的既有用例见 [AppFrame 浏览器测试](../../packages/ui/src/app-frame/app-frame.browser.test.tsx)，拖拽排序见[侧栏列表浏览器测试](../../apps/desktop/src/renderer/features/sidebar/sidebar-lists.browser.test.tsx)，现有页面见[追踪 tab 浏览器测试](../../apps/desktop/src/renderer/features/right-panel/trace-tab.browser.test.tsx)。
2. **真实 Electron E2E（faux 模型）。** 只验证浏览器测不到的部分：
   - 焦点在右栏时，Mod+W 关闭页面，不关闭窗口；焦点不在右栏时，Mod+W 关闭窗口。
   - 重启应用后恢复 tab；设置中的开发者开关在重启后仍然生效。
   - 用真实 Sidecar 运行一个 faux Run：生成过程中出现增量子行，Run 分组正确，能定位到时间线。
   
   写法照 [Trace E2E](../../apps/desktop/e2e/trace.e2e.test.ts)，以及带重启步骤的 [对话 E2E](../../apps/desktop/e2e/chat.e2e.test.ts) 与[删除项目 E2E](../../apps/desktop/e2e/project-delete.e2e.test.ts)。
3. **agent-browser 静默检查。** 检查 tab 条的实际几何、全屏时与红绿灯和拖拽区的关系、真实悬停，以及明暗主题。按项目约定在 Electron 中静默调试，交付时说明哪些交互在这里验证过，哪些只有浏览器测试覆盖。
4. **纯函数单测（补充）。** 移植 DeepSeek Harness 的表格模型、布局、筛选与摘要单测；另外测试 Coko 自己的规则：Run 分组、增量转交给条目、localStorage 读回校验和列宽算法。单测不能代替前三类入口测试。

### 旧测试与执行范围

- 断言旧行为的测试随行为一起修改，并在交付记录中说明原因。涉及的旧行为有：右栏覆盖中栏、侧栏为右栏收起、整个窗口共用的选中 tab、右栏头部的标题与 X、新对话页显示右栏。
- 至少 9 个测试文件直接依赖现有右栏的 DOM：6 个 E2E（jobs、schedules、subagents、teams、terminal-details、trace），以及协作、追踪 tab、定时任务通知 3 个浏览器测试。它们都改用新的入口。
- 按[测试约定](../../docs/tech-stack/testing.md#测试执行与结果报告)运行最小相关测试集和类型检查。AppFrame 的布局是共享接口，因此扩大到使用它的浏览器测试。无理由不运行全仓测试。E2E 与 agent-browser 的结果分开报告。

## Further Notes

### 调查基线与参考差异

本次调查的 Coko 基线为 `25d4228e3cbc177d6199d4c99f8cd777be7c2931`（已包含提交的标题栏规格），DeepSeek Harness 基线为 `8bd073392eef6f54e921a093b95076248eb08cbb`。版本变化后，下文的参考事实需要重新核对。与参考实现的差异如下：

- 引导页列出全部页面（见 RP-05）。DeepSeek Harness 的引导页不列计划、计划任务和子智能体对话这类页面。
- tab 标题跟随界面语言，属于工程决定。
- 补充了 tab 的键盘排序和标题截断（Q19、Q20），以满足 Coko 界面约定中的“键盘和指针均能完成操作”和“标签页优先单行截断”。键盘排序在 DeepSeek Harness 中被记为已知缺口。
- 原始数据只按 Run 分一层组，没有 Turn 和 Step 两层。增量不保存，所以历史 Run 没有分片。
- 没有照搬“原始数据不脱敏”。
- 用 Run 列取代 T/S 列。对话分组的引用类别由 Node / Group / Turn / Step 改为 Run / 过程分组 / 时间线行 / 来源 Session Entry。描述中的“聊天分组”改为“对话分组”，与展示形式的名称一致。
- 列宽算法照搬 DeepSeek Harness：左侧栏不为右栏让位。这与 Coko 现有的算法不同。

### 已知后果

- 右栏不再覆盖中栏，侧栏也不再为右栏收起。窗口宽度接近 1024px 时，如果左侧栏被拉宽，右栏可能没有空间打开，需要收窄左侧栏或调宽窗口。
- 新对话页不再显示右栏，选中项从整个窗口共用改为按 Session 区分。本规格取代标题栏规格中的两项约定：HEAD-01 的“右栏头部为 48px”，以及 HEAD-06 的“右栏自带 X”。
- 焦点在右栏页面时，Mod+W 不再关闭窗口。
- 诊断页的筛选和表格布局会扫描所有已加载的行，Session 很大时有扫描成本。DeepSeek Harness 也记录了同样的限制。本规格不另设性能指标。
- 这是 Coko 第一次复制第三方源码，安装包会新增一份第三方声明。

### 交付方式

本规格涉及按 Session 保存布局、跨 main 与 renderer 的 Mod+W、主时间线投影的共享与定位接口，并且第一次引入第三方源码。因此按[开发流程](../../docs/DEVELOPMENT_WORKFLOW.md#架构设计如何产生文档)，先在同一目录写 design.md，再用 `to-tickets` 拆成实施票。实施票按依赖顺序排列：先做右栏，再做开发者开关和会话数据诊断。整体在“对话状态栏与标题栏”规格的 9 张票交付之后开始（Q6、Q14）。
