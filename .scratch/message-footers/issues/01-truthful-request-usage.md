# 01: 正常请求的真实用量

**What to build:** 正常模型请求返回的真实用量能够经持久化到达现有界面，不再因为合法额外字段而显示假零；用户能区分真实零、未知和部分报告，重新打开对话后结果保持一致。本票交付可运行的计量链路，不等待新底栏完成。

**Spec:** [消息底栏与本轮用量规格](../spec.md)

**Spec scenarios:** AC-11、AC-13、AC-14、AC-18（正常请求与重载）、AC-19、AC-20（保留既有计量消费者）

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

**Closed:** false

## Acceptance criteria

- [ ] 实施前补充本功能的计量设计，明确实际请求尝试身份、Run/Session 归属、唯一计数来源、usage 完整性来源、持久化与旧记录兼容；为重试和压缩预留同一契约，不建立互相重复的计量系统。必要的兼容性预重构先做，并保持现有入口可运行。
- [ ] 经真实适配入口输入 Chat Completions、Responses、Anthropic 的代表性流式响应，包括当前依赖产生的 reasoning、cacheWrite1h 等合法扩展字段；有效用量不会被整体丢弃。通过现有可见用量入口展示服务已返回的准确计数，不能只修复人工裁剪后的测试对象。
- [ ] 未缓存输入、缓存读取、缓存写入、输出正确归一化；服务商输入总量中的缓存不重复累计，reasoning 作为输出子集保留、不再加到总量。无效数据仍受到校验，不将任意未知对象视为合法 usage。
- [ ] 明确报告的全零与没有取得报告可区分；必要字段未知或只取得部分计数时保留完整性状态和已知值。只有协议明确省略即零时才填零，不通过初始化零值推断已报告，不用本地估算冒充服务计量。
- [ ] 正常请求的计量事实经真实 Sidecar 提交、读回和重启后保持一致；同一请求的助手消息与追踪等多个载体不重复计数，相同事件重放不翻倍。
- [ ] 旧记录中的合法扩展字段可兼容读取；无法证明的历史完整性不伪造，旧数据不因本票被破坏或改写为猜测值。
- [ ] 标题、子代理及分支复制历史的用量归属仍遵循规格；现有会话累计费用、预算和审计消费者不因修正统计而失效。
- [ ] 通过真实 Sidecar 协议集成及真实 App 浏览器入口验证这条完整路径，修复前可捕获额外字段假零回归；同步所属当前行为文档，记录精确检查结果和限制。

## 范围与衔接

本票负责正常请求计量、完整性表达和兼容性基础；02 在同一契约上纳入重试与压缩的全部实际尝试，04 消费这些事实构建新底栏。具体请求字段或存储布局由设计说明，不以本票硬编码尚未确定的 API。展示和持久化必须有实际结果，不能只交付类型或抽象接口。

## 验证与回执

采用规格已确认的 Sidecar 协议集成与实际 App Browser Mode 测试边界，只在模型服务、网络或时钟边界替换不确定输入。按实际改动运行最小相关测试、类型及文档检查；记录实际数量、退出码、对象版本、文档影响和未验证项。完成后在 Comments 追加交付证据，再判断是否关闭，不把本票通过等同于整份规格交付。
