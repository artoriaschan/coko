# 04: 移除标题栏的交接入口

**What to build:** 交接只能用 `/handoff <下一步目标>` 发起，目标为当前目录。交接完成后，照常自动切到目标 Session 并写入摘要草稿。目标没能创建时，弹出应用级 Toast，“重试”按失败记录中的下一步目标，对当前目录重新发起交接。交接对话框和标题栏按钮删除；只在窄窗口出现的“更多操作”收起菜单一并删除。

**规格场景:** [spec](../spec.md) 的 AC-09；对应 HEAD-05。

**设计依据:** 规格本身，包括其中关于“重试”的工程决定。

**文档影响:** handoff 当前行为说明中的入口、对话框与失败反馈；Subagent 与团队文档中“没有‘更多操作’菜单项”的说法。

**Blocked by:** 03 — 标题栏改为标题行与“对话”tab 行（两票修改同一份标题栏操作列表与相关测试）

**Status:** ready-for-agent

- [ ] 标题栏和窄窗口菜单中都没有交接入口；交接对话框与标题栏按钮已删除；时间线中的交接行不变。
- [ ] `/handoff` 成功后，如果用户仍在源 Session，就切到目标 Session 并写入摘要草稿，与现有行为一致。只有订阅完成之后到达的条目才触发切换，补发的历史不触发。
- [ ] 目标没能创建时，每次失败弹出一次应用级 Toast；点“重试”后，按失败条目中的下一步目标对当前目录重新发起交接。旧对话框的“复制摘要”入口随之消失，这是 spec 中已记录的后果。
- [ ] 交接完成与失败的处理常驻挂载在对话区，不依赖标题栏是否渲染，也不依赖窗口宽度。
- [ ] 窄主区的收起机制（菜单项与菜单关闭后执行的回调）随交接一起移除；四个状态按钮在任何宽度下都不变。
- [ ] 与交接对话框有关的测试随之删除，交接的效果另有测试覆盖；交接 E2E 改走 `/handoff`。原因记入 Comments。
- [ ] 同步修改 handoff、Subagent 与团队的当前行为说明。实际执行的检查和文档影响记入 Comments。
