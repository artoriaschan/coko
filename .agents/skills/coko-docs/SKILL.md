按以下顺序维护 Coko 文档。规则正文在 [文档体系](../../../docs/DOCUMENTATION_SYSTEM.md) 和 [文档生命周期](../../../docs/DOCUMENT_LIFECYCLE.md)；本 skill 只规定执行顺序和完成条件，规则冲突时以这两页为准。

1. **定归属。** 按文档体系的层级、类型和归属边界，为每项要写的事实确定唯一所属文件，判断原地更新、增加章节还是新建。完成条件：每项事实都有所属文件；需要新增类别或目录时，已先在文档体系登记。
2. **起草。** 新文档复制 [模板](../../../docs/templates/README.md)，修订时保持原有确认状态、候选标记和适用范围。完成条件：frontmatter 的 kind、description、lifecycle 及类型要求的 status 已填写，模板注释和"填写"占位已替换或删除。
3. **找消费者。** 搜索旧路径、文件名、标题、锚点和被改变的结论，范围包含 `.agents/`、`.scratch/` 等隐藏目录。完成条件：列出全部命中位置及各自的处理动作；无命中时写明搜索词。
4. **同步。** 按生命周期的"一次更新的完整步骤"修正正文、最近的目录索引、上层导航、AGENTS 触发入口和活动任务；弃用或归档按其表格处理。完成条件：第 3 步的每个命中都已修改，或有保留理由。
5. **机械检查。** 运行 `pnpm run check:docs`。完成条件：退出码 0。失败时修正文档；认为规则本身有误时报告给用户，不为通过而修改 `scripts/check-docs.ts`。
6. **读回。** 不依赖本次上下文，从 AGENTS → `docs/README.md` → 正文重新读取，逐行核对生命周期"完成检查与回执"表中脚本不覆盖的项：语义同步、归属与权威、替代链、历史保留。完成条件：每行都有"通过"或具体缺口。
7. **回执。** 报告改动文件、第 5 步的命令与结果、第 6 步的缺口与未验证项，以及实际保存状态（仅本地、已提交或已推送）。
